## 1. What may write inside a question file after it is placed?
**Decision:** who may change an open question file, and what the orchestrator sees when you save · **Recommended:** (a) · **Why:** nothing can be lost, and your answer always confirms exactly the text you read

---

**What happened.** On 12 October the orchestrator changed two question files after placing them, while you had them open. Q83 (when a value of one number type goes where another number type is needed) got two added paragraphs. Q106 (the rule words for converting numbers) got a corrected sentence. A solution agent (an agent like me that works out a fix with you) had asked for both changes. When you saved your answers, your editor wrote back the copy it had opened before the changes, so both changes were gone. Nothing noticed. The watch (the script command that wakes the orchestrator when you save a question file) only says that a file changed, so the orchestrator relayed your answers as usual. This is problem P169 in the problem graph.

**Why it happened.** The rule "never edit a placed question" is one sentence in the orchestrator's skill. The same skill tells the orchestrator to write into open files in other cases: an answer you type in chat is written into the file, and the script rewrites links inside open files when another question file moves. So no check can tell a forbidden write from an allowed one. The script also keeps only a fingerprint of each file, not its text, so it cannot show what a save took away.

- (a) **Only your editor writes inside a placed file, and every save is shown as a change.** Once a question is placed, nobody else writes inside it: not the orchestrator, not an agent, not the script. A correction comes to you as a new file that says what changed, and your answer confirms only the text of the file you answered. The script keeps each file's text, and the watch shows the orchestrator, under the file's name, the lines you added and any lines your save took away. A save that took lines away is checked with you before it is relayed. This also builds the part you approved in Q94 on 9 October that was never built: the watch shows what you wrote, and closing a file is refused if you saved again after the orchestrator last looked. One cost: when an open file links to another question and that question is closed, the link opens nothing until the open file is closed too. Today 4 of the 29 open files have such a link. About two hours of work.
- (b) **Edits stay allowed, and the script puts lost lines back.** After your save, the script merges your copy with the orchestrator's changes and writes the result. Your answer may then confirm text you never saw, since the change shows up only after you saved. The script must also guess which copy your editor opened, and a clash between the two copies needs your hand. About half a day of work.
- (c) **Words only.** The rule is written for every agent, with its reason, and nothing checks it. In this form it failed twice on 12 October. Minutes of work.

Recommended: (a), because it is the only option where nothing can be lost and where your answer always confirms exactly what you read.

## 2. (orchestrator) The words that (a) writes into the skill
**Decision:** the rule's wording in the orchestrate skill and the agents' prompt · **Recommended:** the words below · **Why:** they only restate (a)

---

In SKILL.md ›Questions to Thobias‹, in place of "Never edit a question once it is placed. His editor holds it open, and saving his answers writes the editor's old copy back over yours. A new point goes in a new question.":

> - **Once placed, a question file is his alone.** Nothing writes inside it but his editor: not you, not an asker, not the script. His editor holds the file open and writes its copy back when he saves, over anything written since he opened it, so a change made meanwhile is lost and his answer would confirm text he never saw. A change to a placed question, a correction or an addition, goes in a follow-up file that says what changed; his answer in the open file confirms only the text that file showed. The script keeps the text of each open file as the watch last showed it to you; the watch prints, under the path, the lines his save added and the lines it took away, and `question-seen` and `question-close` refuse a file that changed since. A save that took away lines of the question as placed is relayed only once he has said he meant it.

The chat line becomes: "An answer he types in chat counts the same: relay it, and close the file with `question-close ID --chat FILE`, which writes his words into the closed copy, never into the open file." The watch bullet says that the watch prints the lines added and taken away. every-prompt.md (the part every agent's prompt shares) gets: "A placed question is never changed, by you or by the orchestrator (the orchestrate skill, ›Questions to Thobias‹): when something it shows changes while he answers, send the change at once as a new question that says what changed." The template's comment gets: "Nobody else writes in this file once it is placed; a correction comes as a new file." S63 (the reply-file solution you chose in Q94) is then complete, since its script half lands with this one.
