You chose (b) in the last question. Here is the same rule, said simply.

**What a slot is.** A slot is the place inside a node where one field is kept. In `x pr`, the parse of `pr` writes `tape[0].lhs = tape[-1]`, and from then on the `lhs` slot of the new node holds the node `x` itself, not the number `x` has.

## 1. The rule, to be written into DESIGN.md
**Decision:** whether these words are recorded · **Recommended:** ok · **Why:** it is option (b), said without the jargon

---

> While a parse runs, `tape[0].lhs` gives the node that the field `lhs` holds, for example the name `x`, and does not run it. So `tape[0].rhs = tape[0].lhs` makes `rhs` hold the same node, and both run later, when the finished node runs. A field declared `?` has no type yet, so the parse may use it as a number only inside a check such as `if tape[0].n.type ⊆ u64 ( … )`, the same check it already uses on tape cells (`⊆` asks "fits inside", and `u64` is a whole number from 0 up); `tape[0].n.type` itself needs no check. While the parse runs, only a written number such as `3` has a value, so using a name such as `x` as a number there is an error.

**How this looks once `^` mints, as `array` does.** You are right that `^` in power.logos is written the old way: it makes every node of type `^` itself and writes `output_type` into each node. DESIGN already says it should mint, and that work is waiting. Written like `array`, `^` would look like this:

```logos
^ := type (
    share mints := hashmap type -> type,
    share get_mint := fn (t := type ?) -> type (
        mut mint := mints[t],
        if mint != ? return mint,
        mint = type ( lhs := t ?, rhs := t ?, share output_type := t, share run = ( … ) ),
        mints[t] = mint,
        mint
    ),
    share parse = (
        tape[0].type = get_mint(tape[-1].type),
        tape[0].lhs = tape[-1],
        tape[0].rhs = tape[1],
        tape.is_constructed[0] = true, tape.remove(1), tape.remove(-1)
    )
)
```

Here the check is not needed. The parse reads the operands' types from the tape cells, picks the mint, and writes the operands into fields that the mint has already typed. It never uses a field that has no type. The check matters only for a parse that uses a `?` field of its own node as a number, like the `q` example from the last question. Minting is the better way to write such a type, and the rule only says what happens when someone does not.
