## The root cause, in plain words

The seed has **two ways to read a node**, and they disagree:
- `place_layout` reads a value in a named place, by the value's **type**;
- `read_kind` reads every other node by the **kind byte**, a small number at the start of every type's record, from a fixed list in Rust.

So three plain programs fail (dev 3d0655b, interpreted):

```
[1, 2]          run error: this node was built with no operation to run
s := «a», 0     run error: a record, text or hole is not read as one value; read a field or take its address
r := 1/2, 0     run error: a literal here has no exact value in the type it lands in
```

`read_kind` exists because a type's record leaves out four things a read needs, and Rust fills each in by the kind byte:
1. **Which fields a type has.** `identities/type.logos` names five; `scope`, `fields`, `size_bytes` and `extent` exist only as byte positions in Rust. `type.size_bytes` is refused today.
2. **Where an operation is.** `+`, `scope`, `if` and `return` keep their operation in each node, not on the type. `[1, 2]`'s is empty, hence the first error.
3. **How a text or a `[…]` sits in a place.** DESIGN says it only for types a Logos `parse` builds.
4. **What a plain number is.** The seed reads it as an `i32`, a stand-in, and `1/2` is no `i32`.

**The fix in one sentence:** a node is read through its type's record and nothing else, so `read_kind` and the kind byte go.

## 1. Do you take the whole fix?
**Decision:** how far the fix goes · **Recommended:** (a) · **Why:** it removes the second way of reading, and each step fixes a program you can run

---

- (a) **The whole fix, one step at a time:** `type.logos` declares every field (`parse_rank`, `associativity`, `parse`, `run`, `free`, `print`, `scope`, `fields`, `size_bytes`, `extent`); operations mint (#242, your Q-61); a core type's `run` may be Rust (question 3); a text and a `[…]` are an address (question 4); the `i32` stand-in goes; the kind byte goes last (#101). Then all three programs work. About 70 places in Rust change.
- (b) **The rule only, for now.** `type.logos` is completed and nothing else; the three programs keep failing.

## 3. May a core type's `run` be written in Rust, as its `parse` already may?
**Decision:** where `scope`, `if` and `return` keep their operation · **Recommended:** (a) · **Why:** the operation then sits on the type, where DESIGN reads it, and a Logos `run` can replace it later

---

- (a) **Yes.** Every `( … )` runs the type `scope`'s operation. `square_brackets` has no `run`, so `[1, 2]` is data, not an error.
- (b) **No, every `run` is Logos.** `scope`, `if` and `return` cannot be written in Logos yet, so they keep their operation in each node until then.
