## 2. Parsing while the program runs, where a type is known only then
**Decision:** whether your point becomes a rule · **Recommended:** "record it", if you meant it as a rule · **Why:** today DESIGN.md says the opposite for one case

---

You wrote: "when checks needs to be done in runtime on types that means the runtime also needs to do parsing DURING runtime, because the parse is different between types". DESIGN.md does not record this point yet. Three rules touch it:

- ›A `type (…)` inside a body is built each time it runs‹: a type written inside a function is kept as lexed text and built by the parser each time it runs. That is parsing while the program runs, for this one case.
- ›Inside a body, a `-> type` call may take an argument known only at run‹: "Only a use that needs the type during the parse (`pick(n) ?`, `pick(n) 5`, a read of its fields) is the checked error". So in `f := fn (n := i32 ?) -> i32 ( x := pick(n) 5, … )` the `pick(n) 5` is refused today, not parsed when it runs. Your point would change this rule.
- ›A type is a comptime value, resolved in the pass‹: "The line falls at `compile`". Compiled code has made its decisions in advance, so parsing while it runs would need the parser inside the compiled program.

Answer "record it", and the orchestrator asks you the exact words in a question of their own. Answer "ok" to leave the rules as they are.
