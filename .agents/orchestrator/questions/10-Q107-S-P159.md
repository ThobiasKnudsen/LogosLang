## What goes wrong

A name for the text type crashes the seed (problem P159):

```
t := «a».type, t
thread '<unnamed>' panicked at src/identities/string.rs:106:31: start byte index 2 is out of bounds for string of length 1
```

It should give the text type, as `t := i32, t` gives `i32`. And the text type has no name (problem P164): `string` gives ``error: unknown name `string` ``, though DESIGN.md calls the text type `string`.

**Why.** `:=` gives a new name the same identity, so `pow := ^` parses exactly as `^` does. The seed makes `«` and the text type one identity: the text type's only spelling is `«`. So `t := «a».type` makes `t` a second `«`, and using `t` makes the `«` reader take the text after `t` as a quote and run off the end. `#`, `(` and `[` are words of their own, apart from the comment, `scope` and `square_brackets` types they build; only `«` is not. DESIGN.md does not say which is right (root cause W322).

## 1. Is `«` the text type itself, or a word of its own?
**Decision:** what `«` is · **Recommended:** (a) · **Why:** it is how `#`, `(` and `[` already work, and every name of a type then means that type

---

- (a) **A word of its own** (solution S97). `«` reads the quote and builds a value of the type `string`, as `#` builds a comment and `(` a `scope`. Then `t := «a».type, t` gives the text type, `string` is a name, and `«a».type == string` is `true`. The agent tried it in the seed: every quote, comment, `print`, `lex` and `regex` works as before, and all 566 tests pass. The new rule, beside ›Strings nest by depth; only five escapes; `«…»` is the only spelling‹:

  > ### `«` is an identity of its own; the text type is `string`
  > `«` is an identity apart from the type of what it builds, as `#` is apart from the comment type and `(` from `scope`: its `parse` reads the quote after it and builds a value of the text type, `string`. `string` is a type like any other and stands as itself, so a name bound to it is the type and opens no text: `t := «a».type, t` gives the text type.
  > - **Why:** <your words>

- (b) **The text type itself** (solution S98). `«` stays the text type's spelling, and its reader first checks that the word it met is `«`, as a number's reader checks for a digit. It fixes the crash, but a check on the character `«` then decides which names open a text, so no other spelling can ever open one.

Recommended: (a), because it is how `#`, `(` and `[` already work, and it needs no check on the spelling.

The patterns stay as you chose in Q88: a word nobody declared, and a number like `5`, are names of their type (`unknown_word`, `rational_number`).
