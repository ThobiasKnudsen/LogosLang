## 1. Should `^` take an integer and a float that cannot hold all of it, such as `i64` with `f64`?
**Recommended:** (b) · **Why:** then `^` and `+` follow one rule, and a number never loses part of itself where `lossy` is not written

---

In Q117 I decided this myself, as "refused". Then I found that two of your rules answer it differently, so it is your choice, and Q117's point 1 waits for this answer.

- Your rule on `^` (26 September): "if lhs or rhs is float then output_type has to be float as well". Read alone, every integer with a float works.
- Your rule on conversions (Q-63, 2 October; Q83): a number converts where it is not written only when nothing is lost. That is why `i64 3 + f64 2.0` is refused: an `f64` cannot hold every `i64`.

```
x := i64 3, y := f64 2.0, x ^ y      # (a) 9.0    (b) refused
x := i32 3, y := f32 0.5, x ^ y      # (a) 1.7320508    (b) refused
x := i32 3, y := f64 0.5, x ^ y      # 1.7320508 in both: every i32 fits in an f64
```

- (a) **`^` takes every mix.** The integer converts to the float, losing digits past what the float holds. `^` then differs from `+`.
- (b) **`^` takes a mix only when the float holds every value of the integer**, as `+` does. Otherwise you write the loss: `f64 lossy (x) ^ y`. The `^` rule then only names the result type of a pair that is taken.
