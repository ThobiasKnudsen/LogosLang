## What this is about

**The words.** When Logos parses a line, it first cuts the line into pieces and puts them on the **tape**, a list of **cells**, one per piece. A type can have a `parse` slot, its **constructor**: a small Logos function that runs when the type's name appears on a line, and that reads and edits the tape (`tape[k]` is the cell k steps to the right, `tape[0]` its own cell). Each cell has a **flag**, `tape.is_constructed[k]`, which says "this cell is built". A word nobody has declared yet, like `zz`, is a **fresh spelling**: its cell holds the text `zz` and no node (no value) at all. **DESIGN.md** is the repo's rule book; a heading in it is written like ›this‹.

COMMMENT: cells is not a word that should be used. node or dyad should be used instead based on wherther or not the node is a dyad or not. btw its nolonger called DESIGN.md its called KNOWLEDGE.md 

**The problem (P31).** This program crashes with a segmentation fault instead of giving an error:

```logos
h := type (share parse_rank = *.parse_rank + 1, share parse = ( tape.is_constructed[1] = true, tape.remove(0) )), h zz, 5
```

Output: nothing, exit 139 (segmentation fault). It should be a checked error with a message, exit 1. Here `h`'s constructor marks the next cell, the fresh spelling `zz`, as built, then removes itself. The parser trusts the flag, takes the empty cell as a value, and reads through a null pointer.

The solution agent found four ways to the same crash on today's `dev` (commit 5dbf3b2, release build), all inside `h`'s `parse`:

```logos
tape.is_constructed[1] = true, tape.remove(0)          # flag the next cell          -> exit 139
tape.remove(0), tape.is_constructed[0] = true          # remove itself, flag index 0 -> exit 139
tape[0] = tape[1], tape.is_constructed[0] = true, tape.remove(1)   # copy the empty cell -> exit 139
print «{tape[1].type == void}», tape.is_constructed[0] = true      # just read its type  -> exit 139
```

**The root causes.** The why agents traced P31 to four:

- **W123:** DESIGN.md says a built cell holds a node (›The tape is Logic Graph with a string extension‹: "A constructed cell is already a graph dyad."), but no rule says what happens when a write breaks that.
- **W150:** the flag and the cell's pointer are two separate writes (›`is_constructed` is the tape's own list‹: "The flag lives on the tape, as a linked list parallel to the cells, never as a field of the dyad"), so no single write sees both.
- **W157:** no rule says what `tape[k]` gives for a fresh spelling's cell. Today it hands out a null pointer, which is the fourth crash above. This is the question below.
- **W126:** the seed lets a constructor flag any cell it can reach, though your rule allows only its own (decided below).

Two more causes sit under W123: **W127** (the rule "a built cell holds a node" lives in no one place in the code; each reader checks it or trusts it on its own) and **W135** (each reader decides on its own what an empty built cell means, so whichever reader touches it first crashes).

## 1. What a constructor gets when it reads a fresh spelling's cell
**Decision:** what `tape[k]` gives for a cell that holds a spelling and no node · **Recommended:** (a) · **Why:** it follows two rules you already have, and changes no ruling

---

In `h zz`, `h`'s constructor can read `tape[1]`, the cell of `zz`. That cell holds the text `zz` and no node. You ruled this on 29 September 2026 in ›An unknown spelling stays text on the tape; `:=` makes the binding, and the node comes with the value‹: "The cell holds the spelling and no node." No rule says what the read `tape[1]` gives then. Today it gives a null pointer, so `tape[1].type` crashes (the fourth crash above), and `tape[0] = tape[1]` copies the emptiness into another cell.

Two existing rules point one way:
- ›What still holds of the old lifecycle‹: "`undefined` is a null slot, and reading it is a checked error, never undefined behavior."
- ›A `tape[k]` read past the lexed frontier lexes on demand for every constructor‹: "A read that needs more than a cell has (`tape[k].dyads`, `tape[k]:name`) is the error it is on any cell without one."

- (a) **S39, the read is the checked error.** `tape[k]` on a cell that holds a spelling and no node is the same checked error as reading any empty slot. A constructor can still look at such a cell without an error through `tape.spelling[k]` (gives the text `zz`) and `tape.is_constructed[k]` (gives `false`). No constructor in the seed reads a fresh spelling's cell with `tape[k]` today.
- (b) **S40, the cell gives the pattern that lexed it.** `tape[k]` gives the identity that recognised the word (the "word" pattern, or the "symbol run" pattern for something like `+-+`), so a cell is never empty. This undoes your 29 September ruling that the cell holds no node, and a flagged pattern cell would then pass as a value nobody declared, so the check decided below would still be needed.

Wording for (a), a new sentence in ›What `lex` returns: a `parsing_tape` fragment‹ after "constructing it later is the ordinary unknown-name error.":
> Reading `tape[k]` on such a cell is the checked error of reading an empty slot (›What still holds of the old lifecycle‹); `tape.spelling[k]` and `tape.is_constructed[k]` read it without error.

Wording for (b): in ›An unknown spelling stays text on the tape‹, "The cell holds the spelling and no node." becomes "The cell points at the pattern identity that lexed it and holds the spelling.", and ›Unknown spellings are two pattern identities‹ changes the same way, with History lines saying the 29 September form is superseded.

Recommended: (a), because it follows two rules you already ruled, keeps the 29 September ruling, and is one check in one place.

## Decided
These are my own decisions. Answer "ok" to accept them, or write what you want instead. Each becomes a Ruled line in DESIGN.md with your "ok".
- **A built cell that holds nothing is refused at the tape write that makes it (S37), not at the end of the line (S38).** A tape write that would leave a flagged cell holding no node is the checked error at that write: `tape.is_constructed[k] = true` on a fresh spelling, or `tape[k] = …` putting no node into a flagged cell. The seed checks this pair in one place, the tape's two writes, so every reader can trust the flag. This rests on ›The tape is Logic Graph with a string extension‹ ("A constructed cell is already a graph dyad."), on ›What still holds of the old lifecycle‹ ("reading it is a checked error, never undefined behavior") and on your rule to fix at the root, so that one rule decides in one place. S38 would leave every reader that meets the cell before the line ends to guard on its own, which is W127 and W135 multiplied. New sentence after "A constructed cell is already a graph dyad.": "A constructed cell always holds a node: a tape write that would leave a flagged cell holding no node (`tape.is_constructed[k] = true` on a fresh spelling, or `tape[k] = …` of no node into a flagged cell) is the checked error at that write."
- **A constructor flags only its own cell (S41).** `tape.is_constructed[k] = …` at any k other than 0, or after the constructor removed its own cell with `tape.remove(0)`, is the checked error; reading `tape.is_constructed[k]` stays allowed at any k. This is your ruling of 19 September 2026, in two places: ›Two levels: the binding is the lex level, the dyad is the value level‹ ("none is ever assigned (one exception, ruled 19 September 2026: a constructor writes its own cell's flag, `tape.is_constructed[0] = true`, when it has constructed something …)") and ›`is_constructed` is the tape's own list‹ ("The cell's own constructor writes it `true` when it has built something."). The seed instead lets a constructor flag any cell: `x := 3, h := type (share parse_rank = *.parse_rank + 1, share parse = ( tape.is_constructed[1] = true, tape.remove(0) )), h x, 5` prints `5`, exit 0, though `x`'s own constructor never ran on its cell. The only line that names a flag write at another index is the **Open** line of ›A `tape[k]` read past the lexed frontier lexes on demand for every constructor‹, marked "Claude's, open to Thobias", which is not a ruling. Its words "(`tape[k] = …`, `tape.is_constructed[k] = …`)" become "(`tape[k] = …`)", so it agrees with your ruling.
