## 1. Is this what `unknown_name` is?
**Decision:** what the tape holds for a word nobody has declared, and how `unknown_name` behaves · **Recommended:** (a) · **Why:** it treats an unknown word exactly like every other word, which is what your answer asks for

---

**Your sentence.** You asked: "why not just set the type to what the name already says the type should be?" The solution agent reads it like this. The lexer (the step that cuts a line into words and looks each word up) should give `zz` whatever its name in the lookup table says, as it does for every other word, with no special step for unknown words. Today the lookup table already knows the two patterns that match an unknown word: a word like `zz`, `[A-Za-z_][A-Za-z0-9_]*`, and a run of symbols like `+-+`. The seed declares both as names (in `src/identities/fresh.rs`). But after the lookup finds one of them, the lexer throws the result away and stores nothing, a null pointer (`src/parse/lex.rs`, line 63). That null is what every crash reads. If you meant something else, please say what, with an example.

**(a) That reading, worked out.** Both patterns are names of the one type `unknown_name`. So `zz` on the tape is `unknown_name` itself, not yet built, and its text `zz` is kept in `tape.spelling[1]`. This is exactly how `5` works today: the tape holds the number pattern, not yet built, and keeps the text `5` beside it; the number's own `parse` builds the value from that text. Then:

- `unknown_name`'s `parse_rank` is the lowest of all. So every constructor that takes a name gets it first: `:=`, a parameter list like `fn (a)`, a conjecture's hole.
- `unknown_name`'s `parse` runs only if nothing took the word. It is the error "unknown name `zz`", the same message as today. This replaces the special "leftover" check the parser runs today at the end of a line: it is now the type's own `parse`, so an unknown word is no exception.
- `regex «…»` gives a built node of type `unknown_name`, holding a regex (`regex «[0-9]+»`) or a plain spelling (`regex «..»`). That is the "plain spellings but also regex" of your answer. Today `regex «…»` gives a separate type of its own; that type goes.
- Left of `:=` stands an `unknown_name`, either one from a bare word (its text read from the tape) or one from `regex «…»` (its value read), or an already declared name, which the new name shadows, as today.
- A constructor can ask whether the next word is undeclared without any error: `tape[1] == unknown_name` is `true`, and `tape.spelling[1]` is its text.

In Logos:

```
zz := 5                            # `:=` takes zz, reads its text, and declares zz
x := 3, x + zz                     # error: unknown name `zz` (zz's own parse; nothing took it)
regex «[0-9]+[kK]» := type ( … )   # regex gives an unknown_name holding a regex
regex «..» := type ( … )           # … or holding a plain spelling
```

All four ways to crash from the last round become harmless. Marking `zz` as built makes it stand as `unknown_name`, the way a bare `i32` stands as itself. `tape[1].type` gives `type`. `tape[0] = tape[1]` copies `unknown_name`. The parser's many separate "is this pointer null?" checks can then be deleted.

**(b) A new node for every unknown word.** Each time the lexer meets `zz`, it makes a new node of type `unknown_name` whose value is the text `zz`, and `tape[1]` gives that node. This also removes the null. But it makes one node per unknown word in the graph, which lives on after the tape is thrown away. It keeps the text twice, in the node and in `tape.spelling[1]`. It builds a value before any constructor runs, which no other word does (`5` is built by its own `parse`). And the "unknown name" error then needs a new special check wherever such a value is used.

**The wording (a) would write in DESIGN.md**, for your yes:

1. In ›An unknown spelling stays text on the tape; …‹, the first sentence, "The cell holds the spelling and no node.", becomes:
   > A spelling nobody has declared lexes as every spelling does: the lookup finds one of the two fresh-spelling patterns, whose type is `unknown_name`, so the tape holds `unknown_name` itself, not yet built, and keeps the text in `tape.spelling[k]`, as it holds the number pattern for `5`.

   Its last sentence, "A fresh spelling nobody declares is the leftover-cell error at the segment boundary.", becomes:
   > A fresh spelling nothing takes meets `unknown_name`'s own `parse` at its turn, which is the error `unknown name` with its text.
2. In ›Unknown spellings are two pattern identities‹, "Each leaves the cell holding its spelling and no node (…)" becomes:
   > Both are names of the one type `unknown_name` (›`unknown_name` is the type of a name nobody has declared yet‹).
3. In ›A pattern identity is declared `regex «…» := type (…)`‹, "gives a recognizer, which `:=` enters into the trie" becomes "gives an `unknown_name` holding the pattern, which `:=` enters into the trie" (the trie is the lookup table).
4. A new rule:
   > ### `unknown_name` is the type of a name nobody has declared yet
   > Its value is a name: a plain spelling or a regex. The two fresh-spelling patterns are its names, so a word nobody declared is `unknown_name` on the tape until something takes it; `regex «…»` gives a built node of it, holding a plain spelling (`regex «..»`) or a pattern (`regex «[0-9]+»`). It has the fields every type has. Its `parse_rank` is the lowest of all, so every constructor that takes a name (`:=`, a parameter list, a conjecture's hole) reads it first; its `parse` is the error `unknown name` with the text. Left of `:=` stands an `unknown_name`, its text read from the tape or its value read, or a declared name, which the new name shadows.

## Decided
This is my own decision. Answer "ok" to accept it, or write what you want instead. You did not read it last round, so here it is again, shorter.

- **A constructor may mark only its own node as built.** Writing `tape.is_constructed[k] = …` at any position other than 0 (the constructor's own node), or after the constructor removed its own node, becomes an error. Reading `tape.is_constructed[k]` stays allowed at any position.

  Why: your rule of 19 September, in ›Two levels: the binding is the lex level, the dyad is the value level‹, already says a constructor writes only its own flag: "a constructor writes its own cell's flag, `tape.is_constructed[0] = true`, when it has constructed something". An earlier agent's proposal, never ruled (the Open line of ›A `tape[k]` read past the lexed frontier lexes on demand for every constructor‹), allows a flag write at any position, and the seed follows that proposal. With question 1's fix alone, the crash program no longer crashes, but `h` marks `zz` as built, so `zz`'s own `parse` never runs and "unknown name `zz`" is never reported: the line just runs. The same happens today with a declared name, whose constructor is skipped:

  ```
  x := 3, h := type (share parse_rank = *.parse_rank + 1, share parse = ( tape.is_constructed[1] = true, tape.remove(0) )), h x, 5
  ```

  Output today: `5`, exit 0. After this change: an error, because `h` wrote a flag that is not its own. Every constructor in the seed and its tests already writes only position 0, except the test of this crash.

  The wording: in ›Two levels‹, after "… `tape.is_constructed[0] = true`, when it has constructed something;" add "a flag write at any other position, or after the constructor removed its own node, is the checked error;". In the Open line, "(`tape[k] = …`, `tape.is_constructed[k] = …`)" becomes "(`tape[k] = …`)".
