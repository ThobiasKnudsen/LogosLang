## 1. Should `^` keep taking every mix of number types, converting inside itself with `lossy`?
**Recommended:** (a) · **Why:** a `^` with a fractional exponent is approximate anyway (it goes through `exp` and `ln`), and every `^` that works today keeps working

---

`^` is written in Logos, in `identities/power.logos`. Issue #198 (one conversion step for numbers) makes every conversion checked: a number converts without `lossy` only when nothing is lost. Inside `^`, a plain number you wrote, such as the `0.1` in `x ^ 0.1`, is a fraction, and no float holds 1/10 exactly. So `^` must either write `lossy` inside itself, or refuse such calls.

```
x := f64 2.0, x ^ 0.5                 # (a) works, as today   (b) works: 0.5 is exact
x := f64 2.0, x ^ 0.1                 # (a) works, as today   (b) refused
2 ^ (1/3)                             # (a) works, as today   (b) refused
x := i64 3, y := f64 2.0, x ^ y       # (a) 9.0, as today     (b) refused
```

- (a) **`^` takes every mix, as today.** `power.logos` writes `lossy` on its three conversions. Your 26 September `^` rule reads this way: "if lhs or rhs is float then output_type has to be float as well".
- (b) **`^` refuses what `+` refuses.** A mix that loses digits is refused, as `x + 0.1` and `i64 3 + f64 2.0` are (your Q106 and Q-63 rules). You would write `x ^ (f64 lossy 0.1)`.
