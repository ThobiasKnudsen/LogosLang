## The root cause, in plain words

`type.logos` is where `type` says what every type holds. Today it says five things:

```
type := type (
    parse_rank := f64 ?
    associativity := ?
    parse := parse ?
    run := run ?
    free := free ?
    …
)
```

But a type's record in the seed holds more: `scope`, `fields`, `size_bytes`, the cached `@T`, an `extent` reader, and a kind byte. Those live only in Rust, in `meta.rs`, as byte offsets chosen per kind tag. DESIGN asks for the opposite (›Still to be written in type.logos; reflection of fields is open‹: "Every field under the `type` scope must be expressed there"), and also leaves open what a type shows about its fields.

So no Logos-level shape exists that a record could be read through, and every reader uses Rust's offsets. You can see it on `type` itself:

```
type.size_bytes          error: this read does not fit the node's type
type.scope               error: this read does not fit the node's type
type.parse_rank          92.0      (read from a Rust offset)
```

**One problem it causes.** `bool` has no kind tag in Rust's list, so it borrows `i32`'s. A comparison then becomes an `i32`:

```
x := i32 1, a := x == 1, a          prints 1     should print true
x := i32 1, (x == 1) + 1            prints 2     should be refused, like true + 1
x := i32 1, mut a := i32 0, a = x == 1, a     prints 1     should be refused, like a = true
```

**What else it explains.** 3 problems (P21, P26, P27) through a chain of 9 causes: no declared shape (W54), so Rust picks every record shape per tag (W52), so a built-in type has no `size_bytes` member (W48, W43, W42), so the kind byte is the only thing that says what a type is (W40), so `bool` borrows `i32`'s tag (W35), so a comparison is laid out as an `i32` (W32, W30, W37, W34).

**Related roots.** W2 (a node does not carry the type it gives back; its fix S1 is chosen as #82, and it fixes the same three problems sooner). W49 (lowering is one Rust table, not keyed by backend; shares `src/identities/mod.rs`).

## 1. Which fix do you take?

- (a) **S23, the whole fix.** `type.logos` declares every field a type's record holds, and the record holds nothing else. Concretely:
  - declared there: `parse_rank`, `associativity`, `parse`, `run`, `free`, `print` (already ruled, #174), `scope`, `fields`, `size_bytes`, `extent`;
  - what one kind of type needs beyond these becomes a `share` member of that type's own body: a pointer type's `pointee`, an operator's `arity` and `roles`;
  - the cached `@T` leaves the record: `@` keeps its mints, as `array` keeps one type per element type;
  - the kind byte goes (#101); a type is told apart by what it is, `t == bool`;
  - Rust keeps `type`'s layout alone, which DESIGN allows ("whose layout is the seed's only built-in knowledge"), and a test checks it against `type.logos` field by field.

  Then `i32.size_bytes` is `u64 4` because `i32` fills it, and `bool` is `bool` everywhere. Big: the `meta.rs` offsets, about 70 readers of the kind byte and record layout, and `pointer.rs`. It must run alone in `src/identities`. Slices: (1) the rule and `type.logos`, (2) every type fills `size_bytes`, `scope`, `fields` and readers go through them, (3) the per-kind extras become `share` members and `@T` moves to `@`'s mints, (4) the kind byte goes (#101).
- (b) **S24, the rule only for now.** Write the rule and complete `type.logos`, and leave the seed on its Rust offsets until later. Cheap and touches no code, but the seed keeps a second, unchecked copy of the shape, and none of the 9 causes goes away. This is the same as slice 1 of (a). (Its recorded assessment says "S20" by my slip; it means S23.)

Recommended: (a), started with its slice 1, so the rule lands now and the seed slices follow in order after S1 (#82), which fixes the three problems sooner.

## 2. What does `t.fields` give? (DESIGN has this open)

Your website loop wants to walk a type's fields. For example:

```
pt := type ( a := i32 ?, b := i64 ? )
pt.fields.length                 u64 2
for f in pt.fields ( print «{f:name} {f.type}» )
                                 a i32
                                 b i64
```

- (a) **The list of the type's per-value fields, as their bindings, in the order written; `share` members are not in it.** `f:name` is a field's name, `f.type` its type. This fits ›Field names live in the shared name index, not on the type‹: the list points at the bindings, it does not copy names. It is also exactly what `size_bytes` sums (›`.size_bytes` is a `u64`‹).
- (b) **Leave it open.** `type.logos` declares `fields` so the record has a place for it, but reading it from Logos waits.

Recommended: (a), because `size_bytes` already needs this list to exist, and the walk is your stated intent.
