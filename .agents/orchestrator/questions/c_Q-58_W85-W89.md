## 1. A line that fails part way: how does it know which names it already freed?

**The two problems (dev 6b3a673, interpreted):**

```logos
bag := type ( mut n := i32 ?, share free = ( print «freed {n}» ) ),
g := fn () -> i32 ( error «stop» ),

a := bag(1), x := immediate ( free a, g() ), 1
# P39: prints "freed 1" twice, then "run error: stop". Should be once.

a := bag(1), x := g() + ( free a, i32 1 ), 1
# P44: prints only "run error: stop". g() failed before `free a`, so a should be freed.
```

P44 is the example your Q-43 ruling was made for, and the same happens inside a function.

**The two roots the why run found:**
- **W89:** the parse records where a name ends as a whole line, never as a spot inside the line. So when a line fails half way, it cannot tell whether its own `free a` already ran.
- **W85:** DESIGN answers that with NULL (Q-43): `free` writes NULL, and a failing line frees every place that is not NULL. A pointer has a NULL, 0. A record kept in its own bytes has none: every byte pattern of `bag` is a real `bag` (`bag(0)` is all zeros). DESIGN leaves this Open (#240).

So today a `return` in the middle of a line uses the line's order (Q-45), and a fault in the middle of a line reads NULL (Q-43): two rules for one thing, leaving a line early.

**Your own reading, Q-45.5:** "a name has onlyone :end but it could have multiple in many cases, and if im right being able to express all places it could end like in rust would likely solve this". You asked whether Rust does it this way. It does, nearly: Rust's compiler knows, at every call that can fail, which variables still hold a value, and that call's cleanup frees only those. It needs a hidden flag only when a value is moved in one branch and not in the other. Logos never needs that flag, since an `if`'s close already frees the name in the arms that did not end it.

**The options:**

- (a) **S31: a name ends at a spot inside its line (the Rust way).** Both agents found it on their own (the W85 agent recorded it as S34). The parse keeps the spot of each `free` and `move` in its line's order. A line left early, by a `return` or a fault, frees each name whose end comes after the spot where it stopped:
  ```logos
  x := g() + ( free a, i32 1 )    # g() fails before `free a`: a is freed
  x := immediate ( free a, g() )  # g() fails after `free a`: a is not freed again
  ```
  - `free` and `move` write no NULL and nothing reads one, so no value needs a NULL form: #240's Open point goes away, and a `bag` stays in its bytes.
  - Fixes P39 and P44 for every type, in both tiers, the REPL and `immediate`. `return` and fault become one rule.
  - Cost: it reverses the choice your Q-43 ruling made ("Chosen over no check at all, each spot where a line can fail knowing from the line's order which names are still alive"), and a run error must carry the spot where it left its line, which it does not today. About 150 lines change; the NULL write and the code that reads it are deleted.
- (b) **S35: a value whose type fills `free` lives behind a pointer.** This is (b) of your Q-45.3, which you answered "b" before your `:end` idea. `a := bag(1)` puts the bag in a node of its own and `a` holds the address, so `free a` writes 0 into `a` like any pointer.
  - Fixes P39 and P44, and keeps Q-43 as ruled.
  - Cost: one node per such value and one more hop per field read, and a `bag` inside another record becomes a pointer. W89 stays: `return` and fault still leave a line by two rules.
  - Note: an unwritten `mut a := bag ?` would then hold 0 and free nothing, which answers Q-56 one way.
- (c) **S33: only the narrow fix.** An `immediate` that frees a name tells its scope at once. Fixes P39's double free only; P44's leak stays, and #240 stays open.

Also considered and advised against: S32, the line's order for a record and NULL for a pointer, which gives leaving a line three mechanisms chosen by the value's kind.

Recommended: (a). It is your own direction and the way Rust does it, it makes `return` and fault one rule, it deletes the NULL write and read instead of adding a NULL form, and it fixes both programs. Its price is reopening Q-43, ruled today. If you want Q-43 to stand, (b) is the sound choice. Either way, the next round shows you the exact DESIGN wording before anything is written.
