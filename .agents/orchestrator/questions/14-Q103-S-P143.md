## What this is about

Three gaps in DESIGN.md about who owns a value, that is, whose end runs its `free`. Words used below:
- **made**: just created or moved: `alloc 1 of i32 5`, `bag(3)`, `move a`, a call whose result says `-> own`.
- **borrowed**: read from a name that keeps owning it: in `b := a`, `b` borrows.
- **hands on**: the caller owns the result. Since your Q89 (9 October) a function hands on a made value only when its result says so: `mk := fn () -> own @i32 ( alloc 1 of i32 5 )`.
- `<bag>` is the test type `bag := type ( mut n := i32 ?, share free = ( print «freed {n}» ) )`.

On `dev` today, both say `-> own` and both hand on a value an early `return` made:

```
mk := fn (c := i32 ?) -> own @i32 ( if (c == 1) (return alloc 1 of i32 3), alloc 1 of i32 4 ), x := mk(1), print «{x@}»
  error: a `return` cannot hand ownership out yet; make it the function's last value, which moves out to the caller

<bag>, mk := fn (c := i32 ?) -> own bag ( if (c == 1) (return bag(3)), bag(4) ), x := mk(1), print «got»
  got
  freed 3
```

The pointer is refused, the record works. One rule should decide both.

## 1. May a `return` hand on a value it made?
**Decision:** whether a `return` under `-> own` hands on a made value as the last value does · **Recommended:** (a) · **Why:** your Q89 rule then decides every way out of a function

---

DESIGN.md does not say. Rule 3 of ›Three fail-closed ownership rules, and `-> own @T`‹ opens its door to "the function's last value" only, for a reason that no longer holds since Q89: "a return type that cannot yet say it transfers ownership". `-> own` now says it.

- (a) **Every `return` is a result too.** Under `-> own @i32`, `return alloc 1 of i32 3` hands the value on, so the first program prints `3`. Without `own`, a `return` of a made value gets the error a made last value gets: "write `-> own @i32`". A type's `run`, which has no `->`, reads its mark from its last value and every `return` together, so a `run` that makes in a `return` and borrows on its last line is refused, as your Q72 refuses an `if` whose arms make and borrow. Small.
- (b) **Only the last value hands on.** A `return` of a made value is refused in every function, so the record program gets the pointer's error, and it must be written as `( if (c == 1) (alloc 1 of i32 3) else (alloc 1 of i32 4) )`.

Recommended: (a). Rust works the same: `fn mk(c: bool) -> Box<i32> { if c { return Box::new(3); } Box::new(4) }`.

## 2. Who frees a value made inside a call's brackets?
**Decision:** for a parameter without `own`, whether the value made for it is freed when the call returns or at the end of the caller's line · **Recommended:** (b) · **Why:** a parameter then owns only when it says `own`, as a result owns only when it says `-> own`

---

Two rules disagree about `f := fn (p := @i32 ?) -> i32 ( p@ )` called as `f(alloc 1 of i32 5)`:
- ›Holding is decided at the binding site, parameters included‹: the argument "is bound to the parameter in the callee's frame, which holds it; no `own` gate is needed".
- ›Gate spelling: words left of `:=`; ownership in the reference type‹: "a parameter `a := own @T ?` consumes …, `a := @T ?` borrows".

Today the pointer call is refused, and `f(box (1, 2))` with a record runs and never frees the box. The same body serves `f(a)`, where `p` borrows, so it cannot also own in `f(alloc …)` without a hidden per-call flag, which you turned down in Q-43.

- (a) **Freed when the call returns.** `p` borrows in every call, and the made value is freed as the call returns. One new place where a life ends. Medium.
- (b) **Freed at the end of the caller's line.** `p` borrows, and the made value is one no name takes, so your Q-25 rule frees it at its line's end. A function takes a value over only when its parameter says `own`. This replaces the "parameters included" sentence. Nothing new: issue 224 (free a value nobody takes at its line's end) does the freeing; until it lands, the refusal stays and covers records too. Small.

They differ only inside one line: in `x := f(box (1, 2)) + g()`, (a) frees the box before `g()` runs, (b) after. Rust does (b): `f(&Box::new(5))` drops the box at the statement's end.

## 3. Where is "this owns its value" written down?
**Decision:** in the value's type or on the place that holds it, for every type · **Recommended:** (c) · **Why:** you asked on 9 October that these safety facts be thought through carefully before the borrow checker; questions 1 and 2 do not need this answer

---

DESIGN.md says it two ways. ›Gate spelling…‹: "`own @T` says the reference owns (a fact about the value, like its type)". ›A field may be `own t ?`…‹: "`own` is a gate on the field's binding, as on an owning name's" (marked open to you). The seed does the first for a pointer (`a := alloc 1 of i32 5` gives `a` a special "owning `@i32`" type) and the second for a record (`a := bag(3)` keeps `bag` and marks the name). Every ownership check is then written once per kind, which is how the problem above came about.

- (a) **In the type, for every type.** `own bag` becomes a type, as "owning `@i32`" is. An array whose cells own their bags must say so. Large.
- (b) **On the place, for every type.** `own` is a mark like `mut`; the special owning pointer type goes. A pointer in an array cell has no name to mark, so an array must say whether its cells own. Large.
- (c) **Not now.** Decide it in the ownership talk you asked for under Q92. Until then both ways stay, and the fixes for 1 and 2 read ownership through one function that answers for both.
