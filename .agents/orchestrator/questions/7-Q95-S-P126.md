*Rewritten on 12 October, before you answered: a test showed the old (a) cannot be built (see below).*

Today I hear a save only through the watch, which runs inside one of my own tool calls. It stops after 30 minutes, and a computer restart ends it. Until I get a turn and remember to start it again, your saves wait. That happened with Q79, Q89 and Q90 (problem P126), after the 9 October restart (problem P135), and again now: a network drop stopped it for three days.

Claude Code can run small scripts by itself, called **hooks**: when a session opens or is resumed, when a turn ends, after each tool call. One kind can **wake me even when I am idle**. Only hooks in a settings file come back after a restart; hooks in the skill's own file are gone until the skill runs again (tested 9 October). And Claude Code refuses to let any session write a settings file (it refused mine on 9 October), so that one step has to be yours.

- (a) **One command you run once, on this computer:** `! bash ~/.claude/skills/orchestrate/orchestrate.sh hooks-install` in my session, or the same without `!` in any terminal. It adds a short block to your `~/.claude/settings.json` that hands four moments to one script in the skill's folder. From then on the watch starts by itself when my session opens or is resumed, and your save wakes me at once. A second hook keeps my turn from ending while a file holds a save I have not taken in; a third blocks the question dialog. In every other session the script stops at once. Later fixes change only the script, never your settings again, and `status` tells me when the block is missing. It covers every repo on this computer. About three hours of work.
- (b) **Hooks in the skill's own file.** Nothing for you to do, but after a restart they are gone until I run the skill again, so your saves wait for my first turn, as in P135.
- (c) **The same block in each repo's settings file.** It travels with the repo to another computer, but you add it by hand in every repo.

Recommended: (a), because one command once is the least that survives a restart, and nothing has to be remembered after it.

Opening my session again after a computer restart stays yours.
