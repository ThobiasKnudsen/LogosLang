## 1. Which rule decides `y := x`?
**Decision:** whether a declaration from another name copies the value or gives it a second name · **Recommended:** (a) · **Why:** both rules then hold, and `y = 7` never changes `x`

---

Two rules read differently:

> ›`:=` decides nothing about copy or reference; the type's reading rule does‹ (5 September): "A **data** type reads its value as bytes, stored in a fresh place: `y := x` is a **copy**. Own address, own binding, `y = 7` leaves x at 5, `&x != &y`." And ›A function reads as a copy‹: "`g := f` is an independent function record".

> ›An unknown spelling stays text on the tape; `:=` makes the binding, and the node comes with the value‹ (29 September): "Nothing is copied from one node into another; the name denotes the node the value built."

The seed does both (dev, interpreted; problem P168):

```
mut x := i32 1, y := x, x = 9, print «{y}»                                                       1      (a copy)
pt := type ( mut a := i32 ?, b := i32 ? ), mut p := pt(1, 2), q := p, p.a = 9, print «{q.a}»     9      (shared)
pt := type ( a := i32 ?, b := i32 ? ), p := pt(1, 2), q := p, print «{&p == &q}»                 true   (shared)
```

**The reading that makes both true.** The second sentence replaced an older mechanism, "`:=` fills that dyad" (DESIGN_HISTORY.md): a declaration made an empty node for the name, then copied the value into it. "Nothing is copied" says that empty node is gone; it never spoke about `y := x`.

- (a) **Both hold, read this way.** `y := x` copies a number, a record and a function into `y`'s own place; a type gives the type itself; an array copies its address. The record lines print `1` and `false`. The second sentence is reworded so it cannot be read the other way (point 3).
- (b) **The second decides, for every type.** `y := x` is a second name for `x`'s value, so the number line prints `9`; the first rule and ›A function reads as a copy‹ are replaced, and a copy needs a word of its own.

## 2. Does a type's name get a place?
**Decision:** whether `t := i32` lays out a place like every other declaration · **Recommended:** (a) · **Why:** one rule for every declaration, no special case for types

---

›A scope lays out its declarations; a use reaches the offset through its binding‹: "Every declaration of a scope, shared or not, has an offset". The seed gives `t := i32` none (`t := i32, print «{t:frame}»` prints `0`): a branch of its own makes `t` another spelling of `i32`.

- (a) **Yes.** `t` gets eight bytes holding the address of `i32`; reading `t` gives `i32` itself, so `t 5` is still an `i32`. Every declaration is laid out by its type alone, and the branch for types goes.
- (b) **No.** The rule gains an exception for types; `mut t := i32` would still need a place.
