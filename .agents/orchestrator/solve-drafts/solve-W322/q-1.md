## What goes wrong

A name for the text type crashes the seed (problem P159):

```
t := «a».type, t
```

Output: `thread '<unnamed>' panicked at src/identities/string.rs:106:31: start byte index 2 is out of bounds for string of length 1`. It should give the text type, as `t := i32, t` gives `i32`. (The seed prints the text type as `type`: `«a».type` prints `type`.)

And the text type has no name (problem P164). This program:

```
string
```

gives ``error: unknown name `string` ``, though DESIGN.md calls the text type `string`.

**Why.** An identity is what a word means; `:=` gives a new name the same identity, so `pow := ^` makes `pow` parse exactly as `^` does. The seed makes `«` and the text type one identity: the text type's only spelling is `«`. So `t := «a».type` makes `t` a second `«`. When `t` is used, the `«` reader takes the text after `t` as a quote and runs off the end. `#`, `(` and `[` are words of their own in the seed, apart from the comment, `scope` and `square_brackets` types they build. Only `«` is not. DESIGN.md does not say which is right (root cause W322).

A second gap sits under the first (root cause W323): DESIGN.md does not say whether how far a word reads past itself (how far `«` reads its text, or `#` its comment) goes with the word's meaning when `:=` makes a new name, or stays with the one spelling.

Nothing has been proposed for these two before. Related: solution S23 (to complete `type.logos` with every field a type holds) already lists this reach as a field of the type, which agrees with point 2 (a) below.

## 1. Is `«` the text type itself, or a word of its own?
**Decision:** what `«` is · **Recommended:** (a) · **Why:** it is how `#`, `(` and `[` already work, and every name of a type then means that type

---

- (a) **A word of its own** (solution S97). `«` reads the quote and builds a value of the type `string`, as `#` builds a comment and `(` builds a `scope`. `string` is a type like any other. Then `t := «a».type, t` gives `type`, `string` gives `type`, and `«a».type == string` gives `true`. I tried this in the seed: every quote, comment, `print`, `lex` and `regex` works as before, and all 566 tests pass. The rule it would write, as a new rule beside ›Strings nest by depth; only five escapes; `«…»` is the only spelling‹:

  > ### `«` is an identity of its own; the text type is `string`
  > `«` is an identity apart from the type of what it builds, as `#` is apart from the comment type and `(` from `scope`: its `parse` reads the quote after it and builds a value of the text type, `string`. `string` is a type like any other and stands as itself, so a name bound to it is the type and opens no text: `t := «a».type, t` gives `type`.
  > - **Why:** `:=` gives a new name the identity's `parse` (›`lex_rank` belongs to the binding, not the type‹), so if `«` were the text type itself, every name of the text type would open a text.
  > - **Ruled:** <date>, Thobias (<this question>).

- (b) **The text type itself** (solution S98). `«` stays the text type's spelling, and the type's reader checks whether the word it met is `«` before it reads a quote. This is how a number works today: `5` and `rational_number` are one identity, and its reader checks for a digit. It fixes the crash too, but a check for the character `«` then decides which names open a text, so no other spelling can ever open one.

Recommended: (a), because it is how `#`, `(` and `[` already work, and it needs no check on the spelling.

The patterns stay as you chose in your Q88 answer: a word nobody declared, and a number like `5`, are names of their type (`unknown_word`, `rational_number`). Unlike `«`, a pattern's match is the whole value, and it never reads past itself.

## 2. (orchestrator) Does how far a word reads past itself go with its meaning?
**Decision:** whether the reach goes with `:=` · **Recommended:** (a) · **Why:** the reach is part of the word's `parse`, and `parse` already goes with `:=`

---

This only matters for a second name of an opener, so it matters only under 1 (a). For example, a language could give `«` a spelling of its own, `“`, with `lex «“» := logos (lex «\«»)`.

- (a) **It goes with the meaning** (part of S97). `“abc»` then reads as the text `abc`, as `«abc»` does. The spelling's own length stays the name's. The sentence it would add to ›Two levels: the binding is the lex level, the dyad is the value level‹, after "That is why these three cross `:=` with no special rule, and `lex_rank` does not":

  > How far a token reads past its own spelling, as `«` reads its quote and `#` its comment, is part of its `parse` and crosses `:=` with it; the spelling's own length is the name's.

- (b) **It stays with the spelling** (solution S99). `“` would get the `«` reader's meaning but not its reach, so the reader would look for a quote that was never cut out of the line with it. Every name would also carry one more field.

Recommended: (a), because ›Every identity has a `parse_rank`, and `(` works in two steps‹ already makes reading raw text part of what `«` and `#` do when they are built.
