## What this is about

**The words.** When Logos parses a line, it first cuts the line into pieces and puts them on the **tape**, a list of **cells**, one per piece. A type can have a `parse` slot, its **constructor**: a small Logos function that runs when the type's name appears on a line, and that reads and edits the tape (`tape[k]` is the cell k steps to the right, `tape[0]` its own cell). Each cell has a **flag**, `tape.is_constructed[k]`, which says "this cell is built". A word nobody has declared yet, like `zz`, is a **fresh spelling**: its cell holds the text `zz` and no node (no value) at all. **DESIGN.md** is the repo's rule book; a heading in it is written like ›this‹.

**The problem (P31).** This program crashes with a segmentation fault instead of giving an error:

```
h := type (share parse_rank = *.parse_rank + 1, share parse = ( tape.is_constructed[1] = true, tape.remove(0) )), h zz, 5
```

Output: nothing, exit 139 (segmentation fault). It should be a checked error with a message, exit 1. Here `h`'s constructor marks the next cell, the fresh spelling `zz`, as built, then removes itself. The parser trusts the flag, takes the empty cell as a value, and reads through a null pointer.

I found four ways to the same crash on today's `dev` (commit 5dbf3b2, release build), all inside `h`'s `parse`:

```
tape.is_constructed[1] = true, tape.remove(0)          # flag the next cell        -> exit 139
tape.remove(0), tape.is_constructed[0] = true          # remove itself, flag index 0 -> exit 139
tape[0] = tape[1], tape.is_constructed[0] = true, tape.remove(1)   # copy the empty cell -> exit 139
print «{tape[1].type == void}», tape.is_constructed[0] = true      # just read its type  -> exit 139
```

**The root causes (four, one fix family).** The why agents traced P31 to these, which the orchestrator gave me together:

- **W123:** DESIGN.md says a built cell holds a node (›The tape is Logic Graph with a string extension‹: "A constructed cell is already a graph dyad."), but no rule says what happens when a write breaks that. ›The constructor sets `tape.is_constructed[0] = true` itself‹ puts no condition on the flag.
- **W150:** the flag and the cell's pointer are two separate writes (›`is_constructed` is the tape's own list‹: "The flag lives on the tape, as a linked list parallel to the cells, never as a field of the dyad"), so no single write sees both.
- **W157:** no rule says what `tape[k]` gives for a fresh spelling's cell. Today it hands out a null pointer, which is the fourth crash above.
- **W126:** DESIGN.md says two different things about which cells a constructor may flag (question 3 below).

Under W123 sit two more why-steps the agents accepted: **W127** (the rule "a built cell holds a node" lives in no one place in the code; each reader checks it or trusts it on its own) and **W135** (each reader decides on its own what an empty built cell means, so whichever reader touches it first crashes).

**Related root causes, not part of this fix:** **W26** (a first write `x = 5` to a name declared `x := ?` does not lay the name out) rests on the same rule about fresh spellings, but is about `=`, not the tape; it has its own solution, **S16** (issue #227).

**Solutions already proposed for these roots:** none.

The three questions are independent: each can be answered without the others. Questions 2 and 3 are yours; question 1 is marked for the orchestrator, because the recorded rules (fix at the root, one place for a rule) decide it.

## 1. Where a built-but-empty cell is refused (orchestrator)
**Decision:** at the tape write that makes it, or at the end of the line · **Recommended:** (a) · **Why:** only (a) stops every crash; (b) still crashes in any reader that meets the cell before the line ends

---

Something must refuse a cell that is flagged built and holds no node. There are two places it can happen.

- (a) **S37, at the write.** A built cell always holds a node. A tape write that would leave a flagged cell holding no node is the checked error at that write: `tape.is_constructed[k] = true` on a fresh spelling, or `tape[k] = …` putting no node into a flagged cell. In the seed (the Rust implementation), the tape's two writes check this pair in one place, so every reader can trust the flag. The error points at the constructor's own line. The first three crashes above become errors; the fourth needs question 2.
- (b) **S38, at the end of the line.** The writes stay unchecked. When the line (the "segment") is built, the existing check for leftover unbuilt cells also catches a flagged empty cell and reports `unknown name zz`. This is a smaller change to DESIGN.md, but any reader that meets the cell before the line ends still crashes, so each of them would need its own guard.

Wording for (a), a new sentence in ›The tape is Logic Graph with a string extension‹ after "A constructed cell is already a graph dyad.":
> A constructed cell always holds a node: a tape write that would leave a flagged cell holding no node (`tape.is_constructed[k] = true` on a fresh spelling, or `tape[k] = …` of no node into a flagged cell) is the checked error at that write.
> - **Ruled:** <date of the answer>, the orchestrator under the recorded rules (S37 for W123). **Why:** the flag and the pointer are two writes (›`is_constructed` is the tape's own list‹), so the pair is checked where the second one lands, and a reader that trusts the flag never meets an empty cell.

Wording for (b), in ›A constructor's outcome is read off its own cell‹, the sentence "After a segment is built, a leftover unconstructed cell is the checked error" becomes:
> After a segment is built, a leftover unconstructed cell, or a constructed cell that holds no node, is the checked error.

A third way, making one write set both the pointer and the flag, is ruled out by ›The constructor sets `tape.is_constructed[0] = true` itself; a tape write never sets it‹ (you ruled 19 September 2026 that a write cannot mean "done", because the `array` chooser places a value whose own `parse` still has to run), so I did not record it.

Recommended: (a), because it is the only option where no reader ever sees an empty built cell, so the per-reader checks (W127, W135) can be deleted instead of multiplied.

## 2. What a constructor gets when it reads a fresh spelling's cell
**Decision:** what `tape[k]` gives for a cell that holds a spelling and no node · **Recommended:** (a) · **Why:** it follows two rules you already have, and changes no ruling

---

In `h zz`, `h`'s constructor can read `tape[1]`, the cell of `zz`. That cell holds the text `zz` and no node (you ruled this 29 September 2026 in ›An unknown spelling stays text on the tape; `:=` makes the binding, and the node comes with the value‹: "The cell holds the spelling and no node."). No rule says what the read `tape[1]` gives then. Today it gives a null pointer, so `tape[1].type` crashes (the fourth crash above), and `tape[0] = tape[1]` copies the emptiness into another cell.

Two existing rules point one way. ›What still holds of the old lifecycle‹: "`undefined` is a null slot, and reading it is a checked error, never undefined behavior." And ›A `tape[k]` read past the lexed frontier lexes on demand for every constructor‹: "A read that needs more than a cell has (`tape[k].dyads`, `tape[k]:name`) is the error it is on any cell without one."

- (a) **S39, the read is the checked error.** `tape[k]` on a cell that holds a spelling and no node is the same checked error as reading any empty slot. A constructor can still look at such a cell without an error through `tape.spelling[k]` (gives the text `zz`) and `tape.is_constructed[k]` (gives `false`). No constructor in `identities/` reads a fresh spelling's cell today.
- (b) **S40, the cell gives the pattern that lexed it.** `tape[k]` gives the identity that recognised the word (the "word" pattern, or the "symbol run" pattern for something like `+-+`), so a cell is never empty. This undoes your 29 September ruling that the cell holds no node, and a flagged pattern cell would then pass as a value nobody declared, so question 1 would still be needed.

Wording for (a), a new sentence in ›What `lex` returns: a `parsing_tape` fragment‹ after "constructing it later is the ordinary unknown-name error.":
> Reading `tape[k]` on such a cell is the checked error of reading an empty slot (›What still holds of the old lifecycle‹); `tape.spelling[k]` and `tape.is_constructed[k]` read it without error.
> - **Ruled:** <date of the answer>, Thobias (S39 for W157). **Why:** the cell has no node to give, and every other read of an empty slot is already the checked error.

Wording for (b): in ›An unknown spelling stays text on the tape‹, "The cell holds the spelling and no node." becomes "The cell points at the pattern identity that lexed it and holds the spelling.", and ›Unknown spellings are two pattern identities‹ changes the same way, with History lines saying the 29 September form is superseded.

Recommended: (a), because it follows two rules you already ruled, keeps the 29 September ruling, and is one check in one place.

## 3. Which cells a constructor may mark as built
**Decision:** only its own cell, or any cell it can reach · **Recommended:** (a) · **Why:** it is your 19 September ruling, and the other side is an open line I wrote

---

DESIGN.md says two things here, so I may not pick:

- ›Two levels: the binding is the lex level, the dyad is the value level‹ (your ruling, 19 September 2026): "none is ever assigned (one exception, ruled 19 September 2026: a constructor writes its own cell's flag, `tape.is_constructed[0] = true`, when it has constructed something …)". ›`is_constructed` is the tape's own list‹ agrees: "The cell's own constructor writes it `true` when it has built something."
- ›A `tape[k]` read past the lexed frontier lexes on demand for every constructor‹, its **Open** line (marked "Claude's, open to Thobias"): "a write past the reach (`tape[k] = …`, `tape.is_constructed[k] = …`) stays the checked error, no cell to write". This treats a flag write at any index k as allowed, an error only past the end.

The seed follows the second. So today this program runs and prints `5`, although `x`'s own constructor never ran on its cell:

```
x := 3, h := type (share parse_rank = *.parse_rank + 1, share parse = ( tape.is_constructed[1] = true, tape.remove(0) )), h x, 5
```

Output: `5`, exit 0. The parser checks a constructor's result only on the constructor's own cell, so a flag on another cell is never judged by anyone.

- (a) **S41, its own cell only.** A constructor writes only the flag of the cell it was run for. `tape.is_constructed[k] = …` at any k other than 0, or after the constructor removed its own cell with `tape.remove(0)`, is the checked error. Reading `tape.is_constructed[k]` stays allowed at any k. Every flag write in `identities/` and the test programs already writes index 0; only the P31 test does not.
- (b) **S42, any cell it can reach.** Keep what the seed does, and widen ›Two levels‹ to allow `tape.is_constructed[k] = …` at any k. A constructor could then mark `x` in `h x` built without `x`'s constructor running. This is safe from the crash only together with question 1 (a).

Wording for (a): in ›Two levels‹, after "… `tape.is_constructed[0] = true`, when it has constructed something;" add "a flag write at any other index, or after the constructor removed its own cell, is the checked error;". In the Open line of ›A `tape[k]` read past the lexed frontier …‹, "(`tape[k] = …`, `tape.is_constructed[k] = …`)" becomes "(`tape[k] = …`)". A Ruled line: "<date of the answer>, Thobias (S41 for W126). **Why:** the driver judges a constructor's result on its own cell only, so a flag anywhere else is a judgment nobody checks."

Wording for (b): in ›Two levels‹ the exception becomes "a constructor writes the flag of any cell in its reach, `tape.is_constructed[k] = …`"; in ›`is_constructed` is the tape's own list‹, "The cell's own constructor writes it `true`" becomes "A constructor writes it, on any cell in its reach"; History lines say the 19 September form is superseded.

Recommended: (a), because it is the rule you ruled, nothing in the repo needs more, and it keeps the driver's one judgment of each constructor meaningful.
