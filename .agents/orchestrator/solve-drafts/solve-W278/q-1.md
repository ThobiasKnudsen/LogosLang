## 1. One way to end a piece of work (orchestrator)
**Decision:** how orchestrate.sh ends a piece of work and finds its worktree · **Recommended:** (a) · **Why:** one function with one order, and git's own list of worktrees, replace four copies and a list typed into the script

---

**What this is about.** The orchestrator runs each piece of work (an issue, a why agent's search for a cause, a solution agent, a helper) as background Claude sessions in a worktree of its own: a folder with its own checkout of the repo, made by `git worktree add`. Each session is a row in `claude agents`, the list of background sessions. When the work ends, the script `~/.claude/skills/orchestrate/orchestrate.sh` must stop the work's sessions and remove their rows, remove the worktree and its branch, and move the work's notes (its folder under `.agents/orchestrator/state/`) to `state/done/`.

**The four causes.** The graph of problems and causes (`PWS.json`) holds four root causes, all found while tracing one problem:
- W278: no one function ends a piece of work. Four commands each write their own steps for it: `merge` (twice, once for each way of merging), `why-done`, `solve-done`, and the helper cleanup that `status` runs. Each puts the steps in its own order.
- W281: SKILL.md, the skill's rule file, has no rule for that order either. It lists each command's steps on their own, and the list for `merge` stops the sessions last, after the worktree is gone.
- W283: SKILL.md says "A session belongs to the worktree it runs in; the script finds sessions by that". Most commands do so, but the helper cleanup finds a helper by a session id written to a file when the helper starts. A session resumed after a restart gets a new id that is written nowhere, so the file goes stale.
- W287: nothing records where a worktree was made. The script works the place out from the work's name each time, and for older places it keeps a list of two folders typed into the script (`.claude/worktrees` and `.agents/worktrees`). A place set in the repo's `orchestrate.conf` (the `WORKTREE_ROOT` key) and changed later is not on that list.

**One problem they cause (P144).** On 9 October, `orchestrate.sh merge 82` merged issue 82 (the output-type work). Its worktree stood in the older place, `.claude/worktrees/issue-82`. The merge removed the worktree first and looked for its sessions after. With the folder gone, the script looked in the new place, `.agents/worktrees/issue-82`, found no session, and left the reviewer running:

```
$ orchestrate.sh merge 82
merged logoslang#82 into dev at 27ed63c; branch and worktree gone; issue closed
$ orchestrate.sh status
  logoslang-issue-82-review-7	5cf32136	idle	done
```

It should have stopped and removed every session of the merged work, wherever its worktree stood.

**What else they explain.**
- P151: a helper resumed after a restart can have its worktree removed while it still runs, since the cleanup looks for its old id. On 12 October the orchestrator wrote help-8's new id into the file by hand as a stand-in.
- P152: a worktree made in a place set in `orchestrate.conf` is lost to the script once the conf names another place, even while its folder stands; `status`, `merge`, `spawn-reviewer` and `kill` then miss it. No repo is in that state today.
- New, found today: on 9 October the helper cleanup removed help-5's worktree but left its row, because the helper's job had ended and the cleanup reads only the list of running sessions. The row `logoslang-help-5` (8a60fcfc) is still in `claude agents --all`. I report it to the orchestrator as a new problem; question 2 asks about the row.

**Related causes.** No other cause touches these functions. The solutions for the question watch (the script that wakes the orchestrator when you save a question file, held by solve-W243) also change `status`, so the two changes meet in one function. A helper's draft of a shorter SKILL.md (help-5's) would need the same edits as below.

**The options.** No solution was proposed before. I see three, recorded as S87, S88 and S89.

- (a) **S87: one way to end the work, the worktree found through git.** One function in orchestrate.sh ends every piece of work in one order: first every check that can refuse, so a refusal changes nothing; then every session row in the worktree is stopped and removed, ended rows too; then what is kept is moved out (a why agent's probes, a solution agent's drafts); then the worktree, the branch and the notes go. `merge`, `why-done`, `solve-done` and the helper cleanup all call it. The script finds a worktree in git's own list (`git worktree list`), which holds every worktree, since SKILL.md lets them be made only by `git worktree add`; so the list of two older places goes. The folder stays the one way to find a work's sessions: the helper cleanup finds a helper by its folder too, and the five files that keep session ids, which nothing else reads, go. SKILL.md states the order once. This removes P144, P151, P152 and the help-5 case. About three hours, all in the skill's files.
- (b) **S88: as (a), but the place written down.** Each command that makes a worktree writes its path into the work's notes, and the script reads it there. It fixes the same problems, but it is a second copy of what git already keeps: every move of a worktree must update it, and the worktrees open now need a one-time pass. Not recommended.
- (c) **S89: the smallest patch.** `merge` stops the sessions before it removes the worktree, `resume` writes a resumed helper's new id into its file, and the cleanup also removes an ended helper's row. That removes P144, P151 and the help-5 case, but the steps stay written four times, each in its own order, and P152 stays. Under thirty minutes. Not recommended.

Recommended: (a), because it deletes the four copies, the typed-in list and the second way of finding sessions, so one rule decides each thing and no other command can bring the problems back.

**The words (a) would add to SKILL.md**, at the end of the bullet "Names carry the project" under ›One repo, one orchestrator, several bases‹, after "A session belongs to the worktree it runs in; the script finds sessions by that, whatever they are named.":

> The script finds a task's worktree in git's own list of worktrees (`git worktree list`), wherever it was made. Work ends one way, whichever command ends it (`merge`, `why-done`, `solve-done`, a helper's reap): first every check that can refuse, so a refusal leaves the sessions and the worktree as they are; then every session row in the worktree is stopped and removed, ended rows too; then what is kept is moved out (a why agent's probes, a solution agent's drafts); then the worktree is removed, then its branch, then its state moves to `state/done/`.

›Merging‹ would replace "the worktree and the merged branch removed with the safe delete" and "the last session stopped" with "the work ended as ›One repo, one orchestrator, several bases‹ says"; ›A Linear repo and the PR flow‹ would replace "stops and removes every session row in the worktree, and removes the worktree and the branch" the same way. Reason, for SKILL_HISTORY.md: each closing command had its own order, and on 9 October 2026 `merge 82` removed the issue's worktree before it looked for its sessions, so its reviewer kept running.

## 2. The row help-5 left behind
**Decision:** whether the orchestrator removes help-5's leftover row · **Recommended:** (a) · **Why:** the helper is finished, no command can reach the row, and its transcript stays

---

help-5 was a helper: a background session the orchestrator started to look one thing up and write the answer to a file. It wrote its answer, and on 9 October the script's cleanup removed its worktree and its notes. Because of the bug in question 1, its row stayed in `claude agents --all` as `logoslang-help-5` (session 8a60fcfc, its job ended). S87 would not reach it either, since git no longer knows its folder. `claude rm 8a60fcfc` removes only the row; the conversation's transcript stays on disk. SKILL.md lets the orchestrator remove a leftover row only on your word for that row (›Staying responsive‹, `drop-row`).

- (a) **Remove it**: the orchestrator runs `claude rm 8a60fcfc` once, and the transcript stays.
- (b) **Leave it**: the row stays in `claude agents --all`.

Recommended: (a), because the helper's work is done and the row only adds noise to the session list.
