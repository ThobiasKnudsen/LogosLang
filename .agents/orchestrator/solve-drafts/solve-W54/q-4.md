## 1. Which rule decides `y := x`?
**Decision:** whether a declaration from another name copies the value or gives it a second name · **Recommended:** (a) · **Why:** both rules then hold, and it is what the seed already does for numbers

---

**Two rules that read differently.** The first is from 5 September:

> ›`:=` decides nothing about copy or reference; the type's reading rule does‹: "A **data** type reads its value as bytes, stored in a fresh place: `y := x` is a **copy**. Own address, own binding, `y = 7` leaves x at 5, `&x != &y`." And ›A function reads as a copy‹: "`g := f` is an independent function record".

The second is from 29 September:

> ›An unknown spelling stays text on the tape; `:=` makes the binding, and the node comes with the value‹: "Nothing is copied from one node into another; the name denotes the node the value built."

**The seed does both** (dev, interpreted). A number is copied, a record and a function are shared:

```
mut x := i32 1, y := x, x = 9, print «{y}»                                      1      (a copy)
pt := type ( mut a := i32 ?, b := i32 ? ), mut p := pt(1, 2), q := p, p.a = 9, print «{q.a}»     9      (shared)
pt := type ( a := i32 ?, b := i32 ? ), p := pt(1, 2), q := p, print «{&p == &q}»                true   (shared)
f := fn () -> i32 ( 1 ), g := f, print «{f:offset} {g:offset}»                   0 0    (g names f's node)
```

This is problem P168. The seed's code even quotes the second rule ("The name denotes the node the value built, never a copy of it") in the place where it makes `q` share `p`.

**The reading that makes both true.** The second rule's sentence replaced an older mechanism, recorded in DESIGN_HISTORY.md: "`:=` fills that dyad". Back then a declaration first made an empty node for the name and then copied the value into it. "Nothing is copied from one node into another" says that this empty node is gone. It never spoke about `y := x`. So the first rule still decides `y := x`: what is copied is decided by the value's type.

- (a) **Both rules hold, read this way.** `y := x` copies a number, a record and a function into `y`'s own place. A type gives the type itself (`t := i32` makes `t` another spelling of `i32`). A value that travels as a pointer, such as an array, copies the address. The second rule's sentence is reworded so it cannot be read the other way. With this, the record above prints `1` and `false`, and `g := f` is its own function.
- (b) **The second rule decides, for every type.** `y := x` makes `y` a second name for `x`'s value. Then `mut x := i32 1, y := x, x = 9, print «{y}»` prints `9`, the first rule and ›A function reads as a copy‹ are replaced, and a copy needs a word of its own that DESIGN does not have yet.

Recommended: (a), because it keeps `y = 7` from changing `x`, which the first rule calls the safest default, and it matches the history of the second rule.

## 2. Does a type's name get a place?
**Decision:** whether `t := i32` lays out a place like every other declaration · **Recommended:** (a) · **Why:** one rule for every declaration, with no special case for types

---

›A scope lays out its declarations; a use reaches the offset through its binding‹ says: "Every declaration of a scope, shared or not, has an offset". But the seed gives `t := i32` no place: `t := i32, print «{t:frame}»` prints `0`, because the seed has a separate branch for a declaration whose right side is a type, and it only makes `t` another spelling of `i32`.

- (a) **Yes, like every declaration.** `t` gets a place of eight bytes holding the address of `i32`. Reading `t` gives `i32` itself, so `t 5` is still an `i32` (the parse knows this from the declaration, as it does today). Every declaration is then laid out by its type's layout alone, and the separate branch for types goes. It costs eight bytes per type name.
- (b) **No, a type's name stays another spelling with no place.** The rule above gains one exception for types, and the seed keeps its separate branch. A changeable type name (`mut t := i32`) would still need a place.

Recommended: (a), because it removes a branch on what kind of thing the right side is, and the rule "every declaration has an offset" stays without exceptions.
