## The root cause, W85, in plain words

When a line fails, its cleanup frees every value the line has not freed yet. Today it tells "already freed" from "not yet" by looking for NULL in the name's place (your Q-0043 ruling). A pointer has a NULL: 0. A record kept directly in its bytes has none: every byte pattern of

```logos
bag := type ( mut n := i32 ?, share free = ( print «freed {n}» ) ),
```

is a real `bag` (`bag(0)` is all zeros). So the cleanup cannot know whether `free a` already ran. DESIGN leaves exactly this Open (#240). Code: `end_held` and `holds_by_address` in `src/identities/drop_model.rs`, `is_plain` in `src/identities/this.rs`.

## What it causes (dev 6b3a673, interpreted)

P39, a double free:

```logos
bag := type ( mut n := i32 ?, share free = ( print «freed {n}» ) ),
g := fn () -> i32 ( error «stop» ),
a := bag(1), x := immediate ( free a, g() ), 1
```
```
freed 1
freed 1
<command line>: run error: stop
```

It should print `freed 1` once. And a sibling not filed yet, the opposite mistake, a leak, when the line fails before its `free`:

```logos
f := fn () -> i32 ( a := bag(1), x := g() + ( free a, i32 1 ), x ),
f()
```
```
<command line>: run error: stop
```

It should print `freed 1` first (›A checked error is a fault‹: the fault ends each scope "as at its normal end", the values' `free` included). The same at the top level.

## 1. Which way do we close the gap?

Your own reading in Q-0045.5 was: "a name has only one :end but it could have multiple in many cases, and if im right being able to express all places it could end like in rust would likely solve this". You asked whether Rust does it this way. It does, nearly: Rust's compiler marks, for every point in a function, which variables still hold a value. Every call that can fail gets its own cleanup path, and that path drops only the variables that still hold one at that point. Nothing is written into a moved-out variable. Rust needs a hidden flag only when a value is moved in one branch and not the other; Logos never has that case, because an `if`'s close already frees the name in the arms that did not end it. So in Logos this needs no flag at all.

- (a) **S31 (also recorded as S34): the parse knows every end inside a line (the Rust way).** This is the solution logoslang-solve-W89 asks you about in its own question for W89; one answer there or here decides both. Each `free` and `move` gets its spot in its line's order, and the spot where a line fails tells which ends came before it. In `x := g() + ( free a, i32 1 )` a fault in `g()` comes before `free a`, so `a` is freed; in `( free a, g() )` it comes after, so it is not. No NULL is read, so no value needs a NULL form, and a `bag` stays in its bytes.
  - Fixes P39 and the leak for every type, both tiers, the REPL and `immediate`; also fixes W89.
  - Costs: it reverses the choice in your Q-0043 ruling ("Chosen over no check at all, each spot where a line can fail knowing from the line's order which names are still alive"), and deletes "every value with a `free` slot needs a NULL form". S31 goes one step further: `free` and `move` of a name stop writing NULL too, since nothing reads it. Medium-large: the parse gives each end its spot, and a run error must carry the spot it left its line through (it carries none today); deletes `holds_by_address`, `ended_at_run`, the NULL write for names and the pass's `reached` list.
- (b) **S35: keep a value whose type fills `free` behind a pointer.** `a := bag(1)` puts the bag in a node of its own and `a` holds the address, so `free a` writes 0 into `a` like any pointer. This is option (b) of Q-0045.3, which you answered "b" before pointing at the `:end` idea.
  - Fixes P39 and the leak; keeps Q-0043 as ruled. `b := a` borrows the address, as ›A filled `share free` is the value's teardown; one name owns each value‹ already says.
  - Costs: one node per such value, one more hop per field read, a `bag` inside another record becomes a pointer; ›`:=` decides nothing about copy or reference; the type's reading rule does‹ gets a line that such a type reads by address. Does not fix W89. `mut a := bag ?` would hold 0 and free nothing (Q-0056 still open).

Recommended: (a), because it is your own direction and the way Rust does it, it removes the need for a NULL form instead of adding one, and it costs nothing at run time. The price is reopening Q-0043, which you ruled today; if you want to keep Q-0043 as it stands, (b) is the sound choice.
