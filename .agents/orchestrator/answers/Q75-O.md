## Your two questions from Q74
These are answers to you, so there is nothing to answer here.

**How are the same nodes found and merged today, when the wording differs?** In three steps. The last step is always a reading, never a word count.
1. **Before a problem is added,** `pws.py similar` looks for one like it. The same program counts as the same problem at once. Otherwise it counts the words the two texts share, ignoring short and common words such as "the", and shows each problem that shares at least a fifth of its words. I read those and decide.
2. **Before a why agent adds a cause,** it runs the same search with its "anchors". An anchor is a name in the code that the cause points at, such as the function `run_lines` or the file `scope.rs`. An anchor stays the same however the sentence is worded, so two causes that name the same function are found even when their words differ. If an accepted why already states the same fact, the agent answers `existing W12` instead of adding a new one. "The same fact" has a test: neither one makes the other happen, and one fix removes both.
3. **When both agents have answered,** `pws.py compare` puts their drafts side by side. It groups two drafts when they share an anchor or a third of their words, and it marks a draft that looks like a why already accepted. I read each group and decide. When two are the same, `accept W --same-as W2` keeps one node and stores the other wording on it, so a later search finds it by either wording.

For example, one agent writes "A scope's lines are read by five readers, each with its own end rule", and the other writes "Five functions each decide where a line of a scope ends". Few words match, but both name `run_lines`, so `compare` groups them, and I merge them if they pass the test.

**Should the search stop when the agents find only causes that already exist?** Yes, and it already works that way, branch by branch. A cause that was explored in an earlier run is never asked about again. So a run whose every branch ends at known causes stops after its first round. That is what makes later runs cheaper as the graph grows.
