## 3. Is this the rule for a solved cause that is found again?
**Decision:** record this rule, and have the tool flag such a case · **Recommended:** (a) · **Why:** it is your idea from Q75, and today nothing notices such a case.

---

First the facts you asked for. Solved problems stay in `PWS.json`: a problem is marked `fixed` with the commit that fixed it (or `withdrawn`), and a chosen solution is marked `done` at the commit that built it. So every node is already marked solved or not. But nothing notices today when a later why run reaches a cause whose solution is already done.

> **A solved cause found again is a problem.** When a why run reaches a cause whose solution is done, or the program of a fixed problem fails again, the orchestrator records a new problem that says so, for example "W12, solved by S5 at commit abc123, is reached again by P90's why run". Its own why run then finds out which it is: the why agent was wrong, the fix was incomplete, or something else. `pws.py` flags the case when it happens, so it is never missed.

**Is there an algorithm that ranks how similar two texts are, with no model?** Yes, several. These are the ones that fit:
- **TF-IDF with cosine similarity.** Each text becomes a list of its words, each weighted by how rare the word is in the whole graph. So a rare word such as `run_lines` counts much more than a common one such as "scope". Two texts then score from 0 to 1.
- **BM25.** A refinement of TF-IDF and the default ranking in the search engines Lucene and Elasticsearch. It is built to rank documents against a query, so for comparing two texts with each other, TF-IDF cosine is simpler.
- **Stemming or character n-grams.** These make "freed" match "free" and "readers" match "reader". Today's count treats them as different words.
- **MinHash.** This only pays off with millions of texts, so it does not fit here.

None of these needs a database. With a few hundred nodes, each search can be computed fresh from `PWS.json` in a fraction of a second. A RAG would need a model to turn texts into vectors, and somewhere to store them.

Sources: [TF-IDF document similarity](https://metricgate.com/docs/tf-idf-document-similarity/), [text similarity measures](https://metricgate.com/docs/text-similarity-analysis/), [BM25 in MATLAB](https://ch.mathworks.com/help/textanalytics/ref/bm25similarity.html), [BM25, TF-IDF and Postgres compared](https://emschwartz.me/comparing-full-text-search-algorithms-bm25-tf-idf-and-postgres/), [MinHash and near-duplicate detection](https://mbrenndoerfer.com/writing/minhash-algorithm-jaccard-similarity-lsh-deduplication).
