## The core vision

Logos's foundational commitment is **radical unification**: every piece of logic the system contains — programs, types, proofs, compilation rules, optimization passes, the compiler itself, documentation, tooling, and the language's own parsing rules — lives in a single data structure, the **Logic Graph**. There is no separation between "the language" and "what is written in it." Everything reachable in the system is queryable and manipulable through the same meta-reflection.

The bet is that the usual boundaries — language vs. compiler, code vs. specification, program vs. proof, source vs. tooling — are accidents of how systems were historically built, not necessities. Collapsing them yields a system that is simpler at its core, more expressive in what it can state, and more honest about what it is.

Logos is also a serious systems language: static memory safety via a borrow checker (lexical lifetimes, no GC, explicit ownership and moves), zero-cost abstraction, capability tracking for effects, and a layered architecture compiling to multiple backends. The unification does not cost much performance. Logic Graph code is interpreted by default; an immutable (frozen) region can be explicitly JIT compiled with Cranelift, which is faster in most cases, whereas mutable code stays interpreted — compiling it would only be invalidated the moment its structure changed. Reflection needs an LG form to exist, not a compiled one — it cannot be done on anything lower than the LG — so JITed code stays fully reflectable through the LG it was compiled from, and interpreted code simply *is* its LG. The seed is the one running thing that is neither interpreted nor JITed: it is compiled Rust that behaves like frozen, JITed Logos, never mutated at runtime (it is all compiled, and one would not want to borrow every seed identity). Its reflectability is a target reached incrementally, not a property of any version before self-hosting: the seed ships its primitives as `native` — callable-only machine code, opaque to reflection — and each becomes reflectable as LG only once it is ported to Logos source, so the seed's logic reflects in full only at the self-hosted end state (see *The architecture*).

## Why now: a substrate for machine-written code

The unification thesis is old; what makes it urgent now is who writes the code. A fully reflective, rewritable structure that carries its own types and proofs was, for most of computing history, a luxury: humans wrote the code, and humans mostly did not need the machine to reason about the code's own structure. That is part of why the closest ancestors stayed niche. When models write most of the code, that same property flips from luxury to requirement.

The reason is the feedback loop. A model that edits *text* pushes a guess through a fragile toolchain and hopes it holds. A model that edits a Logic Graph rewrites a structure that already carries its scopes, types, borrow states, and (above the seed) proofs, and gets machine-checked feedback that the change is correct and safe before it runs. The same reader-writer rule that governs memory also governs self-modifying code (see *Representation, elaboration, and lifetimes*), so a program can improve its own code iteratively without being permitted to break it. Machine-checked correctness is the direction this is built toward, because that is what a non-human author most needs and least reliably supplies on its own.

This is precisely the gap in the two systems Logos learns from, each of which holds one half and not the other:

- **Smalltalk** is the malleable half: a live, fully reflective image that can inspect and rewrite itself at runtime. What it lacks is any correctness floor. It is dynamically typed, with no borrow checker, no static guarantees, and no way to prove a self-modification is right. Its reflection is runtime-only and carries no types, lifetimes, or proofs, and it is image-based and garbage-collected rather than a bare-metal systems substrate. Malleable, but unsafe.
- **Lean** is the proven half: machine-checked proofs down to a small trusted kernel, self-hosted, with real metaprogramming. What it lacks is being a general systems substrate. It is garbage-collected and functional, not built for systems, GPU, or native-speed performance; it keeps surface syntax, elaboration, and kernel term language as separate layers rather than one uniform structure the running program rewrites; and its verification is aimed at mathematicians proving theorems, not at a graded floor that scales from a borrow check to a full proof over the same code. Proven, but not a substrate a program rewrites and runs fast.

Neither has both halves. Logos aims for the union on a systems base: rewrite it as freely as Smalltalk, check it as strictly as Lean, run it as fast as Rust, all in one structure. The other sections describe how (the single reader-writer rule, the graded verification strata, interpret-by-default with opt-in compilation); this section is why that particular combination is worth the size, and why now.

The bet is staged and testable. The near claim is the coding feedback loop, to be measured by an agent evaluation — a model given the graph and its machine-checked feedback against the same model on an established text language — as soon as v0.1.0, the first public preview, exists. The far claim, agents reasoning over hosted human language with provenance, sits behind the proof layer and hosting, and never carries near-term weight. *(Ruled in discussion, 31 August 2026.)*

## The architecture

**The Logic Graph is the primary representation.** Not an AST (syntax-only) and not a conventional IR (post-elaboration codegen form), it is the unified structure holding the program with all semantic information attached (resolved scopes, inferred types, borrow states, propagated capabilities), the rules that governed its parsing and elaboration, the standard library, the compiler's own logic, and eventually proofs about all of it. Navigation is uniform: the same operations users employ on their own code traverse any subgraph, including the compiler's.

**A small Rust bootstrap seed starts the system.** The seed is the minimum: a parser producing Logic Graph nodes, an evaluator for those nodes, enough type machinery to check the kernel, and a path to Cranelift. Everything beyond — the full type strata, borrow checker, rewriting engine, optimization passes, standard library — is written in Logos and processed by the seed, until the system compiles itself. The seed's small size is what makes Logos formally tractable: auditable by hand, eventually verifiable, a fixed reference point. Once built it is compiled and immutable: its own logic is reflectable as Logic Graph — tooling can read it — but frozen, never rewritten at runtime, and it is the single trusted core every other part is processed by and traced back to. The discipline is restraint — knowing what belongs in the seed and what does not. The core the seed realizes is not bootstrapped sequentially: its identities — the dyad cell, `type`, `Scope`, the primitives — are mutually dependent and come into existence together, one hand-built cyclic graph. Sketches of the core are therefore *specifications* of that graph, not programs (their textual order is not evaluation order), and checking the seed's graph against them is a planned verification step.

**The reflection boundary is callable-versus-data, and it bottoms out in `native`.** What reflects and what does not divides along *callables versus data*, not seed versus user. Every Logic Graph structure — types, values, scopes, and a function's own source body — is reflectable, since reading it is exactly what the interpreter and the lowering do; what is opaque is the *callable*, a machine-code body (`@exec`) one invokes but cannot read into. This is forced, not chosen: interpretation consults each node's evaluator, so were every evaluator itself Logic Graph to interpret, the recursion would never bottom out — some functions must be machine code or nothing runs, and compilation exists precisely to produce them. A function is thus two things at once — a reflectable source body and, once compiled or native, an opaque callable — the same duality as interpreted code being its own Logic Graph while JITed code stays reflectable through the source it compiled from. A **`native`** function is the limiting case: callable-only, a machine-code body with no Logos source, the opaque leaf the tower rests on. The seed ships every primitive as `native`, which is what makes the bootstrap tractable — no spec-Logic-Graph is owed for the primitives, so the seed-against-spec verification above is deferred, not cancelled, returning per identity as that identity is ported. Self-hosting then replaces `native` primitives with Logos source one at a time, each gaining a reflectable body while keeping its callable, so the boundary never moves and the `native` set only shrinks toward an irreducible floor — `invoke`, allocation, raw memory, syscalls — that can never have a Logos source.

**The Logos IR is the codegen-oriented intermediate layer.** Between the Logic Graph and any backend sits a target-agnostic IR with explicit basic blocks, control flow, memory operations, and types. Target-agnostic optimizations (constant folding, CSE, inlining, monomorphization) operate here. The Logos IR is itself representable in the Logic Graph — another stratum of the same structure. The Logos IR should be designed to fit many different backends, like Cranelift, LLVM, WASM, and potentially unique hardware. All of these parts are not the same set so there must be a way to describe what is possible and not for each backend. And the Logos IR should be extensible for the future. But the v1.0.0 Logos IR should at least be solid for most/all things Cranelift is solid at.

**The backend interface defines what a backend must provide.** Anything that consumes Logos IR and emits code — Cranelift, LLVM, a custom embedded compiler, WebAssembly, a GPU backend — satisfies one interface. Cranelift is the default (fast compilation, good code, ideal for meta-circular execution); LLVM is selectable for production and hot loops; backends mix within a program at function or module granularity via scope modifiers like `backend cranelift (...)` or `optimize_with llvm (...)`.

## The rewriting engine

Logos collapses three things other languages keep apart — compiler optimization, computer algebra, and user-defined transformation — into one operation: take a Logic Graph or Logos IR fragment, apply rewrite rules, extract the form minimizing a cost function.

The engine uses **equality saturation**: rather than rewriting destructively in priority order, it builds an e-graph of forms equivalent to the input under the rule set, then extracts the lowest-cost form. Extraction is optimal over the forms the e-graph actually holds; reaching a true fixpoint is not guaranteed — size-increasing rules can grow the e-graph without bound — so the engine runs under an explicit iteration/size/time budget and extracts the best form found within it. (Optimal extraction under a sharing-aware cost function is itself NP-hard, so the default extractor is heuristic, with an exact mode available.) The e-graph approach is production-validated — Cranelift's mid-end uses one — though production systems bound the search rather than fully saturating, as here.

- **Rule sets are first-class Logos values.** A rule is a pair of Logic Graph patterns (match, rewrite). The standard library ships canonical sets for arithmetic, algebra, trigonometry, and compiler optimizations; users compose, extend, or override them.
- **Cost functions are first-class Logos values.** A cost function maps Logic Graph nodes to costs. The standard library ships FLOP count, numerical stability, code size, register pressure, and target-specific metrics; users supply their own.
- **Multiple targets, one engine.** Minimum-cost (default `simplify`), canonical (equality testing), factored (root extraction), expanded (pattern matching), numerically-stable (Horner, log-sum-exp), and target-specific forms are each just a choice of cost function and/or rule subset.
- **Compile-time evaluation is first-class.** Because `eval` over Logic Graph fragments is built in, the engine can run at compile time on symbolic expressions and bake only the optimal form into the binary. Differentiating an expression, simplifying the derivative, and emitting native code is one `eval`-bracketed pass with no runtime symbolic machinery. The same applies to optimization: `eval (optimize_for(target, kernel))` performs target-specific rewriting on user code at compile time.

The same engine serves the compiler's `x + 0 → x` and the mathematician's `sin²(θ) + cos²(θ) → 1`. The compiler's optimization passes are Logos libraries over this engine, not hand-written compiler code; adding a pass is library work.

## The type strata and verification

The strata compose, and users pay only for what they use.

- **Base type stratum** — primitives, record types, enums, arrays, function types, references with lexical lifetimes, ownership and moves, capability annotations (`pure`, `total`, `async`, `thread_pinned`, GPU-subset, allocator-bound). The borrow checker operates here: for whole values and fixed places (fields, elements) it is decidable, fast, and points errors at nodes the user wrote; borrowing a *predicate-defined* set of indices is the advanced case, which discharges its disjointness obligation through the SMT layer and is therefore bounded by the solver, not constant-time. One rule covers every case: among references that are simultaneously live and overlap, many readers XOR one writer — read∩write and write∩write empty, read∩read free. The checker is therefore one generic function asking one question — *can these two extents overlap; does this access fall inside this extent?* — answered yes, no, or unknown; the tiers are not separate rules but answerers of rising strength for the same question (identity and field-offset comparison; constant then symbolic index arithmetic via SMT; predicate disjointness where decidable; kernel-checked proof beyond), and what varies between borrow-checking "cases" is never the rule but the difficulty of computing its inputs: which references coexist (lifetimes, control flow, threads) and which references exist at all (summaries at function boundaries, since references escape through data structures).
- **Refinement types** — predicates on primitives (`i32 where >= 0`, `i32 where 0 <= self < array_len`), with an SMT solver discharging obligations at assignments and call sites. Rules out out-of-bounds, division-by-zero, and overflow at compile time wherever the solver can discharge the obligation; where it cannot, the obligation surfaces as an error to resolve — a strengthened precondition, an explicit check, or a handled case — never a silent pass. Code using no refinements is unaffected.
- **Pre- and post-conditions** — refinement predicates on function inputs and outputs; preconditions proven at call sites, postconditions in bodies. They compose: a call yields its postcondition as a new fact.
- **Termination annotations** — opt-in decreasing measures for functions that want to participate in proof contexts. Functions without them stay usable but cannot appear where totality is required.
- **Full dependent types and proof terms** — types depending on values, propositions as types, proofs as programs, checked by a small trusted kernel. Arbitrary mathematical theorems about programs become statable and provable. *(Superseded in discussion, August 2026 — proofs are rewrite rules and `proof` is its own type; see* The proof layer*. Statable-and-provable stands; the propositions-as-types shape does not.)*

**Verification composes with rewriting.** Each rewrite rule can carry a proof that it preserves the relevant property (equality, refinement satisfaction, numerical equivalence within tolerance); the engine then guarantees simplification preserves it. A verified CAS — every simplification provably equality-preserving — emerges as a library. *(Sharpened in discussion, August 2026: the rule does not carry a proof — the rule* is *the proof, its derivation the body the trusted core checks; see* The proof layer*.)*

A systems programmer gets the base type stratum and borrow checker; someone wanting guarantees beyond memory safety opts into refinements and pre/post; scientific, cryptographic, or verified-systems work opts into dependent types. The strata interoperate; parts of a program can be verified while the rest stays lower.

## The proof layer

**Proofs are rewrite rules, and `proof` is its own type.** *(Ruled in discussion, August 2026; supersedes the propositions-as-types architecture in the rest of this section, whose paragraphs stand below as the superseded record.)* A proof is an fn-shaped rewrite rule. A **value rule** — `p1 := proof (a := generic_number ?, a + a) -> (2 * a) ( … )` — licenses rewriting its pattern into its replacement; a **truth rule** — `proof (a := generic_number ?, a + a == 2 * a) -> true ( … )` — states any proposition whatsoever. The truth rule is the primitive: a value rule is accepted exactly when its truth counterpart holds. Premises are extra inputs that must rewrite to true at the application site (`proof (a := generic_number ?, a != 0, a / a) -> 1`) — implication; the typed holes are quantification; and `==` and its kin remain ordinary boolean operators carrying no proof machinery. Recorded as rejected, to stay rejected: usage verbs on the proposition types (a `forward`/`backward` living on `==`), and the proposition-as-output-type spelling (`fn (a) -> (a + a == 2 * a)`). `proof` merges with `fn` behaviorally, never structurally *(ruled the same discussion)*: both bind typed identities, carry bodies, and share the `->` spelling — each type's own constructor decides what may follow its arrow, fn a type, proof a shape — but a proof stores what fn has no place for: `pattern`, `replacement`, `premises`, its `derivation`, and its **world**, the axiom set it rests on. Being an ordinary type is also what makes a proof an ordinary *value*, so proof-carrying data — a sorted array holding, beside its bytes, the proof of its ordering — is a field, not a mechanism. A derivation is a chain from pattern to declared replacement in which every step cites an already-accepted proof or axiom — fn's trailing-expression rule, licensed stepwise — and checking that chain is the whole job of the small trusted core, which alone may accept a body as evidence and which demands totality, a non-terminating body proving anything. An **axiom is a bodiless proof** — asserted, never derived, the "empty value slot" of the ecumenical section verbatim — and **induction is such an axiom**, higher-order (one premise is itself a rule), mintable per datatype by the type's own constructor: the constructor-authors-its-own-teardown shape again. Application is the rewriting engine unchanged: matching binds the holes — calling in reverse, a non-linear pattern like `a + a` demanding that both slots hold the same `a` — *known equal*: same content, or proven equal by the rules applied so far (the engine's equality class), which with no engine running collapses to the same dyad by address — fail-closed, the binding checked against the hole's declared type *(wording amended in discussion, 30 August 2026; "by address" is the case with nothing yet proven)* — and the engine applies non-destructively under equality saturation, extracting by cost under budget, so registered directions never ping-pong and a goal not reached within budget is simply not proven. Rule *sets* being first-class values (see *The rewriting engine*) is what carries the **ecumenical system** over unchanged: a scope — a section, a sub-language, an import — registers the rule set it accepts, an axiom's acceptance is its presence in that set, a proof's `world` is the union of the worlds of the steps its derivation cites, and two results combine only where their worlds' union stays consistent — exactly the branch discipline of the next section, with the coherentist layer ranking the still-unproven as before.

**Proofs are a layer over the Logic Graph, not a property of the substrate.** The base node model classifies a value by following its `type` pointer — a recursion that terminates in the self-referential `type : type`. That self-loop is sound as *operational* machinery (it is never read as a logic) but inconsistent as one (Girard's paradox), so the proof system does not build on it. Instead, propositions, proofs, and their classifying universes are ordinary Logic Graph values that **carry their logical universe as stored data, read by `universe_of` rather than `type_of`**. The same nodes thus bear two classifications — `type_of` for execution (self-looping, irrelevant to the logic) and `universe_of` for checking (stratified, stored) — so the proof system's soundness is decoupled from `type : type` entirely. This is the standard kernel treatment of universes (levels as checked data, as in Lean/Coq) recast in the node model.

A proof is an ordinary, distinguishable, reflectable value; erasure is an optimization. Stratification re-enters only if rules quantifying over rules — induction as a higher-order axiom — is shown to admit a paradox, not before. The paragraphs stand as the superseded record.)*

A proposition is a value in `Prop`, a proof is a value inhabiting it, and the connectives (`False`, `And`, `Or`, implication, `Forall`, `Exists`, equality) are ordinary inductive and function types — no proposition primitives. Curry–Howard holds at the *representation* level (a proof is a real, reflectable node carrying its type) while logical classification is the separate `universe_of` relation, giving the isolation of a deep embedding without demoting proofs to inert data.

Two walls follow: nothing eliminates from the `type : type` substrate into `Prop`, and conversion reduces only tagged, terminating objects.

**Theorems, axioms, and reach.** A theorem is a named proof — a definition whose type is a proposition and whose value is a kernel-checked term. An axiom is a proposition declared with an empty value slot: asserted, not proved, enlarging the trusted base, with every dependent proof traced back to it. The sound layer can prove properties of *any* Logic Graph node — the self-referential substrate and the proof system itself included — by reasoning over representations and an operational model, treating substrate types as syntax and never lifting substrate classification into logical truth (the CompCert/MetaCoq discipline). It verifies everything above it; by Gödel's second theorem it cannot prove its own consistency, which stays the irreducible part — trusted by hand-audit, not proved.

**The layer is deferrable.** None of this is needed for the substrate to run, so the proof system ships after the base language, in the standard library — **inside v1.0.0** *(ruled 5 September 2026)*: the release is the completeness promise (*Completeness, not cleanliness*), and a release that left verification out would leave exactly the hole downstream fills differently, so refinements, the rewrite-rule proof layer, its trusted core, and the ecumenical system all belong to v1.0.0's standard library, the 'not needed for an initial release' of *Feasibility* superseded. Its smallest checking core — the proof kernel — is an ordinary importable library, not part of the seed: it is trusted only by code that opts into it, so it never enlarges the seed's mandatory trusted base, which stays the single core everything is processed by. Everything stated and proved on top — the connectives, theorems, and tactics — is *checked* by that kernel, not trusted.

## The ecumenical proof system

*(Design direction reached June 2026; like the rest of the proof layer it ships after Core and is deferrable.)*

**Proofs do not live in one global theory; they live in a graph of theories.** A single consistent axiom set is one *branch*; the Logic Graph holds many, including mutually contradictory ones — `P` in one branch, `¬P` in another — each internally consistent, coexisting without poisoning each other. A contradiction arises only from combining incompatible assumptions in *one* proof, and the system never does: every proof carries the **set of axioms it depends on** (its branch), and two results combine only when the union of their axiom-sets is consistent. This is the **ecumenical proof system** — named after the proof-theoretic *ecumenical systems* in which classical and intuitionistic logic coexist in one framework — and structurally a *theory graph* (cf. MMT, Hets, the IMPS "little theories" method) that carries its own dependency provenance.

**The branch is the axiom-closure, not the whole dependency-closure.** Definitions are branch-neutral and shared; only *axioms* — propositions asserted with an empty value slot — commit a proof to a branch. So when the kernel checks a proof it emits the set of axioms that proof transitively rests on (as Lean's `#print axioms` does), and that set is the proof's world. Adding a branch *soundly* means forking on an **independent** statement — one the base can neither prove nor refute, like the parallel postulate over Euclid's other axioms, or CH over ZFC: you *assume* `P` or *assume* `¬P`, never prove both from one base (which would mean the base itself is inconsistent).

**Consistency is checked, never guaranteed.** Keeping `P` and `¬P` apart is trivial — one is the other's negation. But two axioms that look independent yet are jointly inconsistent derive `False` only through some chain, and finding that chain is undecidable (a system cannot prove its own consistency — Gödel's second theorem). So a combination is admitted as compatible **until a `False` is derived from it**, whereupon the cluster is marked poisoned and its results withdrawn — non-monotonic, in the manner of assumption-based truth maintenance and belief revision. "Consistent" means "no contradiction found within budget," never "proven impossible."

**A coherentist layer ranks plausibility, and it is read-only.** Backward search reduces a goal to the sub-statements that would establish it, recursively, and *where it bottoms out sets the status*: at axioms or proven theorems the goal is **proven** (certain); at a web of unproven-but-densely-interconnected statements it is **plausible** (a ranking, not a proof). The more consistent structure that depends on a candidate axiom, and the more it interconnects, the higher its plausibility — coherentism computed over the proof graph's own edges. These scores feed *what to try proving*; they **never** count as proofs — the same one-directional wall as the rest of the layer (kernel → ranking, never ranking → kernel). This is the system's humility: it self-corrects the instant a proof or a contradiction arrives, while keeping every still-consistent branch alive.

**It composes with the universe kernel rather than replacing it.** The two are orthogonal layers over the one graph: *universes* stop self-referential paradox **within** a theory (the stratified `universe_of` tower above); *branches* manage incompatible assumptions **across** theories. They meet at one productive point — large-cardinal axioms, which assert that taller universes exist, so there "which branch am I in?" and "how tall is the universe tower?" are the same choice, settled (as in real mathematics) by fruitfulness, i.e. by the coherentist layer.

## Memory and concurrency

- **Stack by default** — locals are scope-bound; their memory is reclaimed with the frame, an effect-free bulk operation. No GC. Reclamation and destruction are distinct: returning memory that needs no teardown stays implicit, while running teardown never is — teardown is always visible defer structure (next bullet).
- **Explicit heap, and no implicit destruction** — `alloc T v` returns an owning `@T`, and what frees it is never an invisible scope-end rule: **the constructor authors the teardown and inserts it as reflectable `defer` structure**. Only the construction site knows how a value was built — which allocator, whether ownership was taken, what invariants hold — and an `@T`'s type cannot carry the whole story, since ownership does not always follow the name holder (sometimes the pointee must survive the name). So `alloc` inserts `defer free a` — the *specific allocator* captured in the inserted call, which is what lets many allocators coexist safely (see *User-replaceable allocators*) — into the scope where the result's ownership lands; and `alloc` is only the first instance of the general rule: *any* constructor may insert its paired teardown (a file-opening constructor inserts its `defer close`), and a record type's auto-derived constructor composes the teardowns its field definitions declare, because deconstruction has too many shapes for any single mechanism to know them all — each constructor knows its own. `defer` runs LIFO at scope exit, so teardown order reverses construction order. `drop x` applies to an identity and runs its destructor. `drop` and `own` both exercise the `own` access kind (below: consume, emptying the source to `undefined`): a pending deferred teardown over an emptied place is a *sanctioned no-op* — the phase bits are the drop flag — which is what cancels the inserted defer on an early `drop`, on ownership transfer out of the scope (`own` transfers ownership and removes the source identity), and on a conditionally-moved value, all with no graph edit; the compiled tier elides the flag check wherever the checker proves no conditional move, as Rust elides drop flags. Because teardown is ordinary graph structure rather than hidden drop glue, "every alloc reaches a paired free on every path" is a provable proposition over the graph, discharged by the same proof layer as everything else — RAII as checkable structure, not a trusted builtin. `&T` / `&mut T` are statically checked (many shared OR one exclusive), with lexical lifetimes keeping the model predictable. Recorded as rejected, to stay rejected: implicit scope-end destruction in any form, and `:=` inserting `defer drop` on every declaration — declaration stays neutral; teardown authorship belongs to constructors alone. *(Ruled in discussion, July 2026.)* Both points once left to spec are ruled *(30 August 2026)*: a constructor result passed directly as an argument — `f(alloc i32 5)` — is bound to the parameter name in the callee's frame and its teardown attaches there, the binding-site rule applied to parameters (no `own` gate is needed, since there is no caller place to empty; a value that reaches no name at all stays the checked error); and the order of a record's field-declared teardowns is **authored per type** — a type whose fields carry teardowns must write its own destructor, and defining one without it is a checked error at the type definition, pointing at the fields; there is no derived LIFO fallback (its lines are the per-field teardown items a partial move lets the scope-exit teardown skip, *5 September 2026*, below). The seed realizes this now (July 2026): `alloc`/`own`/`drop`/`free`/`defer` exist, the inserted teardown runs LIFO at scope exit by the scope's own machinery as ordinary body structure, and the owning heap pointer is the first identity whose `destructor` slot is non-null (a `&x` borrow mints the same `@T` with a null destructor, so owning-ness rides the node `alloc` built, not `@T` in general). Two v0.1.0 approximations stand in for machinery not yet built: the *emptied-to-undefined* flag is a **null pointer** written into the place (the seed has no phase bits, so a deferred teardown over a null place is exactly the sanctioned no-op), and the teardown attaches at the **binding site** — `a := alloc …` and `b := own a` insert `defer free <place>` into that place's scope, so only *named* owning bindings are covered. A bare owning temporary passed directly as an argument is rejected by the seed today, a bug against the ruling above; field-declared teardown composition awaits the destructor-authoring check. Three fail-closed rules hold the line meanwhile, each a place where ownership would otherwise escape the machinery that frees it: an owning value must be bound to a name (an unbound one has nothing to attach its teardown to); a scope's *value* may not be a place that scope owns, since the inserted teardown would free it on the way out and hand back freed memory (`own` is how ownership leaves a scope, so it is required); and ownership may not cross a *function return* at all, because a block hands ownership to its binder in full view of the parse while a call hides its body behind a return type that cannot yet say it transfers ownership — the caller would not know it owes a `free`. That last one lifts with the ownership gate on the return type *(ruled 30 August 2026)*: `-> own @T` hands ownership to the caller, whose binding site attaches the teardown, while a bare `-> @T` returning an owned place stays the checked error (`own`/`drop` as gates on a reference, the same primitive as `pub`/`mut`). Shared ownership is a recorded direction, not yet built: a `share` operator co-owns *without* emptying the source, its owning type's destructor decrementing a reference count and freeing only at zero — the same destructor-slot-plus-inserted-`defer` machinery this section already builds, so single-owner `own` (move) and `share` (co-own) coexist the way a move and an `Rc`/`Arc` clone do; and `share` comes in flavors *(ruled in discussion, August 2026)* — the non-atomic count is the cheap one whose gate denies the reference crossing a thread boundary, the atomic count crosses freely, and the user picks per case, so neither cost is ever forced. *(Seed realization, the null-pointer drop-flag stand-in, binding-site attachment, and the `share` direction all ruled in discussion, July 2026.)* **`own` and `drop` are static** *(ruled 3 September 2026)*: the parser marks the source name dead at the line that empties it, under three rules that need nothing the parse has not already seen. *Same level*: `own x` or `drop x` written as a sibling of `x`'s declaration makes `x` dead from that line on. *Nested block*: `own x` inside an `if` body or an inner scope, `x` belonging to the outer scope, makes `x` dead in the outer scope once the block closes; maybe-moved is treated as moved for the *name*, while the phase bit (the null pointer today) still decides at run time whether the teardown fires, so no branch analysis is needed and a later `x := …` is safe because it gets a fresh place. *Bodies that run again or later*: `own x` or `drop x` on an outer name inside a loop body or a `fn` body is a checked error, since the loop would read a dead name on its next pass and a function may own only what it was handed through its parameters *(`drop` added to the rule's wording the same day: it empties the place just as `own` does)*. A dead name takes nothing, read, write, or pass, until `:=` redeclares it (see *Name resolution is scope-filtered*); refilling a moved-from `mut` place with `=` is recorded as declined, to stay declined (Rust re-initializes such a binding, Logos redeclares). `drop x` applies to **any** identity, running its destructor where one is set and emptying the place either way, so one verb releases a name whatever its type *(the seed realized both the same day)*. Conditional transfer follows the same line: an `own` argument is consumed at the call, and a callee that fails to take it hands the value back inside its error value (the LogosMath paragraph below). **`own` and `drop` take a field path too** *(ruled 5 September 2026, superseding the bare-names ruling of 3 September, which stands below as the superseded record)*: `own p.f` ends the lifetime of the path `p.f` at that line exactly as `own x` ends x's — a **sub-range under p's entry** in the name index (*Name resolution is scope-filtered*), created only when a partial move happens, so it costs nothing where none does — and `drop p.f` runs f's destructor and ends the path the same way. Sibling paths stay live, `p.g` reads on, while **p is dead as a whole**: `g(p)`, `own p`, and reading p whole are parse errors until scope end, because a callee holds no record saying f is gone. p's teardown at scope exit **skips f from the records**: the authored destructor's lines are the per-field teardown items, in the order the type wrote them, and an item whose field's lifetime ended in the scope is skipped where the parse knows it and guarded by the field's phase bit where it does not (a move inside an `if`; the null the seed writes into a pointer field today), the same two timings the bare-name rules use — so the destructor consults nothing and needs no empty value authored per type. The three body rules apply to a path as to a name: same level, nested block, and no `own` of an outer path inside a loop or `fn` body. Reasons: with lifetimes and gates on the identity's record, a field's end is one more entry of the kind the record already holds, so the 3 September cost — a per-field record of what moved, a flag inside the bytes — is a sub-range made on deviation and the phase bit bare names already rely on; and pulling one resource out of a value so it outlives the value is what the swap door existed for, which this makes ordinary. Superseded with it: that door. Recorded open: how a non-pointer field carries its phase bit for the conditional case (the layout question *Phase is stored as tag bits* leaves to fields; the seed's null covers pointer fields only). The seed accepts `own p.f` and writes the null today, and lacks the sub-range and the dead-as-whole mark — pending work, no longer a bug. *(Superseded record, 3 September 2026:)* `own` and `drop` take a bare name, never a field path: a value is owned whole or not at all, so `own p.x` and `drop p.x` are parse errors and nothing inside a value is ever emptied on its own. That deletes the alternative's whole cost — no per-field record of what has moved, no moved-flag inside a value's bytes (a field is bytes at an offset, not a dyad, so it has no phase bits to carry one), and no special case for the destructor. What stands from it: a destructor receives its value by **mutable reference**, never by `own` (an `own` parameter is a binding site, and the binding-site rule would attach to it the very teardown the destructor is), and tears the fields down in place: the raw teardown words, `free` and `close`, on each resource, and a nested field's own destructor called as the ordinary function it is. Parameters are untouched, since inside a body `own x` on a parameter is a bare name of the frame's scope.
- **Place-granular borrows** — borrows are tracked per *place* (a field, an element, a predicate-defined set of indices), not per whole object, so the borrow rule (many shared, one exclusive) applies only where two places provably overlap — a disjointness obligation the checker discharges through the refinement/SMT layer, being itself a Logos program free to query the solver. Exclusive and shared borrows of disjoint regions of one object therefore coexist — odd indices writable while even indices stay shared-readable, say — capturing safely the split-borrow patterns conventional checkers reach only through `unsafe`. These borrows are *local*: resolved at the borrow site, within the scope that can see the place, and they do not outlive it carrying their extent — the escaping case, where the extent rides on the reference identity itself, is *Reference-granular permissions* below.
- **Reference-granular permissions (after v1.0.0; v1.0.0 must not block them).** The fine-grained extent of a borrow is carried by the *reference identity itself* — a borrow is already its own node — as a total, pure predicate over places. The obligations it generates (disjointness between coexisting references, containment of each access) discharge statically through the tiered ladder above, and predicates and proofs erase before codegen like everything in `Prop`, so a fully discharged reference compiles to a bare address; a runtime check is only ever an explicit opt-in fallback, never silently inserted. What v1.0.0 owes this future: references exist as graph identities at check time and erase to raw addresses in codegen; the extent descriptor is deviation storage (the default whole-place reference stores nothing); the checker is factored around the one overlap/containment query so later tiers plug into its *unknown* bucket; places are graph values a predicate can mention; the optimizer keys aliasing and immutability on a reference's extent, never implicitly on whole objects; and extent predicates are admitted under the same obligations as recognizers — total, pure, terminating.
- **Read and write are one mechanism across the system.** Visibility (`pub`), mutability and borrowing (`&` / `&mut`), and graph access (reflection and `graph_mut`) are not separate features but one primitive — a read or write *capability over a place, for a lifetime, granted to a scope*. Visibility is the `'static`-lifetime read of a name; a borrow is the region-lifetime read or write of a value or sub-place; reflection and graph mutation are the read and write of a graph node. The borrow rule — many shared XOR one exclusive — is the reader–writer rule, and it governs all of them uniformly, including across threads. The scope tree supplies the default grants (a declaration is reachable in its own scope and descendants), so the common case needs no annotation and `pub`/`mut` remain sugar over the primitive. One model, two enforcement timings: static checking for *accessing* fixed structure, incremental re-validation for *mutating* it — because writing the graph changes the structure the checker reads. The checker holds a privileged read over the whole graph — it must see every node to identify and check what is built on it — so user-facing visibility restricts *peer* access, never the checker's reflection (a private field is hidden from other code, not from the checker). Beyond the coarse per-branch grants the scope tree gives, access may also be set by *functions* — total, pure predicates over places or scopes — for the fine-grained cases (these indices writable, that field readable only by its type's methods). These access-setting predicates are **`gate`s**, ordinary identities like any other — `pub` and `mut` are themselves gates. A gate is a **fail-closed predicate** returning `true | false | ?` (the universal unknown): access is permitted only on `true`; `false` and `?` both deny, with `?` retained as a standing obligation — the synthesis goal a later prover discharges, moving an access from `?` to `true` by proving it safe (composition is Kleene three-valued, so an unresolved `?` stays visible, and only the enforcement boundary collapses `?`→deny). The check is **lexical and static** — decided from the viewer's scope chain at elaboration time and never consulted by compiled code *("erased before codegen" amended 5 September 2026: the record stays resident for reflection and re-validation, running code simply never resolves a name)* — so there is **no ambient authority**: being *called by* a holder grants nothing, an indirect call cannot launder access, and the only way to give a callee access is to hand it the reference explicitly. A gate's requirement propagates *backward* through the call graph as a static obligation, discharged at the scope that legitimately grants it, and it stays analyzable starting from any code section. The access kinds themselves are an **open set**, not a substrate enum: `read` and `write` (observe, mutate in place) are joined by `call` (invoke an authority without inspecting it) and `own` (consume/move, emptying the source to `undefined`), with more — borrow, alias, drop, observe-for-proof — admitted the same way. A gate computes the kind in force by analyzing the live evaluation stack; what keeps that sound is that each operator declares an **effect signature** classifying its operand slots, and the trusted evaluator stamps the access mode from that signature — evaluator code cannot forge a read into a write. Gates run on the *same* stack they analyze (a separate meta-stack was rejected as a regress), bounded by one rule: everything above the first gate-evaluation marker on the stack runs ungated, so gate evaluation terminates. *(Mechanism from design discussion, June 2026; not yet validated. Clarified 30 August 2026: the stack a gate reads is the pass's own — the static scope chain and call structure as elaboration sees them — never a runtime call stack; and since structure is built and rebuilt in the one pass, that chain can change at run time, a gate being decided when the access is elaborated and re-validated on structural change.)* The seed builds the chokepoint, the lexical tier, and the classified `?` seam only — **no prover**; the stronger answerers (the borrow checker, the proof layer) bolt onto `?` exactly as the tiered checker above describes. *(Surface ruled in discussion, August 2026.)* A gate's spelling belongs to its constructor, like every identity on the tape — there is no global gate-syntax rule — and the first gates are prefix constructors on the value: `x := pub 5`, `x := pub mut 5` *(respelled 5 September 2026 from `pub x := 5` and `pub mut x := 5`, since the left of `:=` is a name alone — *Declarations are immutable by default*)*, and ownership as a gate word in a reference's type, where `a := own @T ?` consumes (the callee owns, the source empties), bare `a := @T ?` borrows, and `a := share @T ?` co-owns *(respelled with the one declaration operator, 2 September 2026)*; the same word on a return type, `-> own @T`, hands ownership out to the caller. Unmarked is fail-closed: private, immutable, borrow-only. `own` is one word for the right and the act — a use-site `own a` is legal exactly where the reference's gate grants `own` *(ruled 30 August 2026: `take` as a separate gate word is deleted and recorded as rejected)*.
- **Sections, the arche, and effect identities.** *(Ruled in discussion, August 2026.)* Access has two granularities, and both are the one gate primitive. The coarsest gate is the name index itself: a name the trie does not offer to a scope cannot even be spelled there — visibility as the `'static`-lifetime read above. The fine grain is the gate proper, an ordinary identity that may read the static call stack and the caller's surrounding scope; reading the caller is for *tightening* only — a gate may deny by where it is called from, but permitting on caller identity alone is the confused deputy readmitted, and stays barred by the standing rule that being called by a holder grants nothing. A **section** is a region of code defined by which names reach it; the **arche** is the root section — the scope a run begins in, command line or REPL, holding every primordial name by construction. Kernel access is a *position* in the import and call tree, never a runtime mode: nothing asks "which mode am I in", there is only what a scope can name. (Recorded as declined: mode bits, and the name "user modes" — sections partition code, and extending them to users later is configuring which names a user's root starts with.) The **effect identities** — `extern`, the native I/O identities as FFI builds them (file, network, clock, environment), and the durable store — are fail-closed: no section holds them unless a reference was deliberately handed down, so what a dependency can do is read off what it was given. Pure computation, `alloc` included, stays ambient — computing cannot touch the world outside the process, and gating it buys noise, not safety. `extern` is the strictest case because it is the door out of the graph: code behind it escapes every in-language gate, so it is granted, never ambient. The **dyad view** joins the fail-closed set *(ruled in discussion, August 2026)*: reflection is reachability of the view like any other authority, so an imported section cannot read foreign structure — private fields included — unless the view was handed down; the arche holds it by construction. (Reflection cannot touch the world, but it reads what visibility hides: privacy-sensitive the way effects are world-sensitive.) *(Seed status, August 2026: the view registers ambient like every identity for now — the fail-closed default stands as the target and awaits the grant path, a capability passed by argument, which needs `type`-typed parameters.)* An effect reference passed into a `pub` function grants **`call` only** by default — usable, never storable or copyable; a holder that must keep its capability (a logger keeping its file) is spelled by the caller explicitly opening more than `call` — silence-means-no extended to delegation *(ruled in discussion, August 2026)*. And resource exhaustion — a section that loops or allocates without bound is harm without authority — is recorded as real and deferred: budgets enter as later gates when needed, and `alloc` stays ambient meanwhile. **A language is a section with an authored start** *(ruled 3–4 September 2026)*: `language (…)` parses its body in a section holding **five names** — `:=`, `,`, `«`, `»`, `logos` *(six on the morning of 4 September 2026, `lex` among them; `lex` left the set that evening, fetched as `lex := logos (lex)`, since `lex` with nothing to consume stands as its own value, while the five that remain are exactly the names without which the door and a declaration cannot be written: `logos («)` would open a string, `logos (:=)` and `logos (,)` have no operand and no value to stand as)* — plus unknown spellings, which may stand only on the left of `:=`; every other name enters by declaration, `if := logos (if)`, and for what cannot stand alone `lex «)» := logos (lex «)»)`, — `?` included *(ruled 4 September 2026: a word with no meaning yet is `leave := logos (?)`, or `? := logos (?)` once and `leave := ?` after; the start set holds only what is needed to write the door and the declarations, and nothing the door can fetch)* — `logos (…)` being the Logos language's scope continued (*Substrate vocabulary*) and read with Logos's own bracket, which is why brackets need not be among the six, and a comment needs `# := logos (#)`. A language made this way opens closed too: inside `my_language (…)` only its own names exist, and **the door back is `logos (…)`, opt-in per language** *(ruled 4 September 2026, the same evening, rolling back that morning's `{ }` extension)*: a language admits the door by declaring the name in its definition, `logos := logos (logos)`, in the very shape of `if := logos (if)`, and a language that does not is sealed, fail-closed like every other section — inside its blocks `logos` is an unknown spelling. `logos (…)` continues **the Logos scope the block lexically stands in**, so `english ( she leave at logos (t). )` written in a function body reads that function's `t`, and at Logos top level `logos (…)` is literally the plain group. Superseded with it: `{ }` as "the hole to the surroundings" of every closed scope — `{ }` is the `«` and `#` constructors' own interpolation spelling and nothing more, unassigned elsewhere as before, because a language block is code with names, not text, and already had a door, while making `{` a bracket every language constructor must honor would have reserved a spelling in a design where every spelling belongs to the constructor that declares it and would have handed a closed section a door its author never declared. `type (…)` stays the **open** block: its body sees its surroundings, which is what makes `y := 1, g := type (y := 3)` the ruled error; an instance's block follows the language its type was defined in. Two consequences: a language may give a Logos spelling its own meaning — an English `not` — because the Logos one is not in its section, so nothing collides; and every `my_language (…)` block continues the one scope, the REPL's session model (*The scope's constructor is the driver*).
- **Reflectability is a droppable capability, so the resident graph is a dial.** An interpreted region *is* its LG and a JITed region stays reflectable *through* its LG (see *The architecture*), so keeping a region reflectable means keeping that LG resident — which is the only thing the source-to-graph size expansion actually charges for. But reflection is a read over graph nodes, governed by the one reader–writer rule like every other access, so it is *revocable*: drop the last read capability into a compiled region and its LG has no reader, is reclaimed by the same reachability that frees a scope's runtime graph (*Two graphs, one source of truth*), and the region collapses to its bare callable — a `native`-like leaf, an `@exec` body with no readable source. This adds no collector; sealing a region is the reader–writer rule applied to the graph's own memory. Resident cost is therefore a spectrum the program sets per section: fully reflectable — the whole image, seed and stdlib and compiler and user code all resident as LG with types and proofs attached (the Smalltalk/Lisp-image reality, heavier here for carrying the proofs); seal the toolchain once booted — drop its LG, keep the callables — and the resident set collapses to what is still reflected on; seal everything and the graph is gone, an ordinary native binary at no graph overhead. The expansion factor is thus not a fixed tax but the price of retained reflection, paid only where reflection is kept and reaching zero as regions seal. The seal is a contract, not a free lunch: it keeps what other code has already read out — types, compiled form, a proof's checked certificate — and forfeits the right to re-derive them (recompile, re-prove, structurally edit, or introspect that section), the same shape as stripping symbols from a release build; and only a section's *private* nodes are reclaimed, since interned identities and any subgraph another live reader still points into stay pinned, so the reclaimed fraction is how much of the section was private rather than shared. *(Design direction reached in discussion, July 2026; not yet validated. "Seal" is a placeholder name for dropping a region's reflectability.)*
- **User-replaceable allocators** — `alloc.arena`, `alloc.bump`, `alloc.pool`, `alloc.system`, and custom allocators share one interface. Arenas enable cyclic structures via indices rather than borrows.
- **Two concurrency shapes** — `parallel for` for data-parallel work over disjoint indices (the borrow checker recognizes the pattern); async for I/O-bound concurrency via stackless tasks on user-defined executor pools. A function that can pause is marked `async` and pauses at an explicit `.await`, so suspension is always visible in the source, and `.await` is allowed only inside an `async` function; the `async pool (...)` modifier selects which executor pool runs a region. Tasks are anchored once started (no Pin machinery); borrows cannot cross awaits except within the same task's anchored state record; capabilities flow through the call graph to enforce this statically. What a task may park on is an open set, so the event-listening layer is user-definable the way allocators are: one small interface — register interest, promise a wakeup — with implementations as ordinary replaceable identities, the waker being nothing but "make that task runnable again," and the reactor living with the pool definition it serves (an io_uring pool, an epoll pool, a GUI pool whose reactor is the platform message loop; GPU fences, embedded interrupts, and chain confirmations enter the same way). The stdlib ships the standard pools, so naming one is the baseline and writing one is the escape hatch. *(Ruled in discussion, July 2026.)*
- **Scheduling, preemption, and cancellation.** A task yields cooperatively at each `.await`; beyond that, the runtime can step in at any *boundary* where the task's live state is materialized as graph data — between interpreter steps, or at the edge of a compiled burst. This is what keeps one task from freezing its pool: instead of one opaque compiled function holding state in registers across the whole task, a hot region may compile to short bursts that read their inputs from the task's live state, run at full speed, and write results back at each boundary, so that state is ordinary graph data at every boundary. Preemption and cancellation are then uniform and cheap — a paused or preempted task *is* its materialized state, with no stack maps to emit and nothing to reconstruct from registers; cancelling is dropping that arena-scoped state like any other runtime graph, running the pending `defer`s of its live scopes (teardown is always defer structure — see *Explicit heap, and no implicit destruction*). Only the transient within-a-burst work is ever held in registers, and it is never seen from outside because control is taken only at boundaries. Boundary granularity is a per-region dial: short bursts give responsive preemption and cancellation, at the cost of writing live state out each boundary rather than keeping it in registers and of optimizing only within a burst; one large burst — a whole hot loop — gives top throughput but few stopping points, reserved for compute kernels, the longest burst bounding the worst-case time-to-preempt. It rides on the same interpret/compile boundary the representation section describes (a compiled region falling back to interpretation): where an artifact can deoptimize is where the scheduler regains control. Preempting is invisible and the task resumes seamlessly; cancelling stops it at its last boundary for good — its values are dropped but its remaining steps never run, so keeping state consistent across a possible cancellation is the program's responsibility. Two rulings bound the dial. Splitting a region into bursts is never hidden logic: boundary points are placed by the user or by an ordinary identity — a backend or pool policy — and what gets inserted is reflectable structure, the same law that governs constructor-inserted teardown; the compiler never adds yield points behind the graph's back. And a pool's latency property — no burst here over a millisecond — is not a static WCET proof, which exists only for heavily restricted code: it is empirical, measured history combined with the region's structure, and enforced by deoptimization — a burst that blows its budget is an observable event that demotes its region to finer bursts or to interpretation, so the bound is self-correcting rather than proven. Both belong to the adaptive layer, after v1.0.0. *(Ruled in discussion, July 2026.)* *(Scheduling model reached in design discussion, not yet validated; the bootstrap can ship cooperative `.await` yielding and add boundary preemption as the compiled tier matures.)*
- **Case study: making an RCU library's comment-enforced rules machine-checked.** [TSM](https://github.com/ThobiasKnudsen/LogosMath/blob/gd_to_tsm_and_gtsm/include/tsm.h) is a lock-free, RCU-protected, type-generic hash table in C (userspace-RCU LFHT under a node model where every node's type node carries its `fn_free_callback` and `fn_is_valid` — a C precursor of the dyad), and every safety rule it imposes on callers, it states only in doc comments. Each class of those rules maps onto a Logos mechanism that enforces it. *Conditional ownership transfer* — create/insert/update "take ownership … so you should not free … if successful" — is exactly `own`: the caller's place is emptied at the call and its constructor-inserted `defer free` no-ops on it, and a callee that fails to take the value hands it back inside its error value, which the caller binds to a new name *(the on-failure-ownership-stays reading superseded 3 September 2026, since `own` is static and the name is dead from the call; in v0.1.0 a failed call is a fault, so the case does not arise)*; the leak and the double-free both become unreachable instead of comment-warned. *"Free only via `call_rcu`"* — the node constructor inserts the RCU-deferred free as the only teardown path, RCU-deferred freeing being just another allocator behind the one allocator interface. *Forgotten `rcu_read_unlock`* — the read-guard's constructor inserts `defer unlock`. *Use-after-grace-period* — "a pointer obtained inside the read section must not be used after it" is not a runtime-insertion matter but a lexical lifetime: the reference's lifetime is bounded by the guard's scope, the borrow checker's ordinary static territory — the library's hardest rule happens to be lexically shaped, so the lexical-lifetimes model fits it exactly. *"Never `synchronize_rcu`/`rcu_barrier` inside a read section"* (and defer-free must run outside one) — effect rules, enforced by capability tracking: those operations demand a capability the guard's scope revokes. *A type node must outlive the nodes it types* — an ordinary lifetime relation between identities. The interpreted tier catches the dynamic classes at runtime as checked errors, never UB; the static tiers (borrow checker, capabilities) close aliasing and effect ordering; together, 100% of the header's stated obligations are machine-enforced where the C original enforces none of them.

## Mutability and construction

*(Mechanics settled in design iteration, June 2026; declaration syntax and the `mut` model revised later that month — `mut` recast as a type modifier (mut on the type denotes a mutable value), not a positional slot qualifier — applied recursively up the classifier tower, with value- and type-mutability as independent permissions on the two slots. The phase-bit storage is proposed, not yet validated, and everyday value-mutation writes in place — `=` writes the value slot of the existing dyad, so `&x` stays valid — rebinding to a fresh dyad rejected as breaking identity-is-address *(ruled 30 August 2026)*.)*

**Declarations are immutable by default; the grammar mirrors the dyad's two slots.** A dyad *is* a type slot and a value slot, and two operators write them *(reduced from three, ruled 2 September 2026: `:` as a declaration operator is deleted, see the end of this paragraph)*: `:=` is **declaration** — it introduces a name and binds it to a value, inferring the type from the value (`key := value`); its left operand is **exactly one name or regex and nothing else** *(ruled 5 September 2026)*: a name is a placeholder for an identity, not a thing attributes attach to, so every gate is a prefix constructor on the right — `x := pub 5`, `y := pub mut i32 5`, `math := pub type (…)` — binding just above `:=` so that `x := pub a + b` gates the sum, and a named and an anonymous value (`f(mut i32 5)`) are gated by one mechanism, `:=` keeping one shape (see *`mut` is a gate on the identity's record*); and `=` is **reassignment** — it writes the value slot of an *already-declared* name (`key = value`). A value with its type is written by juxtaposition (`key := i32 32`), and a name declared *without* a value is declared with a **hole**: `?` is a constructor that builds a fresh dyad with both slots `undefined` at every appearance — a literal, never a name, so `x := ?` binds `x` to its own hole rather than aliasing one global unknown — and a type applied to it stamps the type slot and leaves the value `undefined`, so `key := T ?` is the valueless declaration and `key := ?` the bare one, the value taken by later reassignment (`key := T ?`, then `key = value`). Whether a type can be declared without a value is the type's own decision — tolerance for `?` is authored per constructor (*Deferral is authored*), and a type that refuses it simply cannot stand valueless, fail-closed. **`:=` decides nothing about copy versus reference; the type's reading rule does** *(ruled 5 September 2026, and corrected the same day from a first wording that put the decision in `:=` with types as its exception)*. `:=` binds the name to what its right side yields, and what a name yields is defined by its type — *the type defines how the value is read* (*A dyad is a type and a value*). A **data** type reads its value as bytes, and a declaration stores them in a fresh place, so `y := x` is a **copy**: its own address and its own record, `y = 7` leaves x at 5, `&x` and `&y` differ, and y's gates are only what its own right side set (`y := pub x` a public copy, `y := mut x` a mutable one, plain `y := x` closed, per *`mut` is a gate on the identity's record*), never x's. **`type`** reads a type as the identity itself — its constructor, standing with nothing to consume, returns the reference to the type and never a copy — so `x := i32` binds the name to i32 itself, another spelling of it, `x 5` classified by i32 and `x == i32` true; that is no exception in `:=` but `type`'s own rule, exactly as the copy is the data type's. Two names for one place among data exist only where written, `y := &x`, and a value that cannot be copied — an owning `@T`, whose copy would be a second free — is the checked error, moved with `y := own x` or borrowed with `y := &x` (*Memory and concurrency*). Reasons: *identity is address*, so a data name that yielded its dyad rather than its bytes would make `y = 7` write x and `&x == &y` hold with no `&` in sight, reference semantics without a reference, where a copy is the safest default and aliasing already has its explicit spelling; and a decision placed in `:=` would have made one operator carry a rule per kind of value, where the reading rule already lives on the type. The seed has always copied data here. `:=` accepts **any** dyad as the value — a type included, since a type is a value like any other — which is also why the valueless form needs its `?`: `x := i32` names the type, `x := i32 ?` declares. A **function reads as a copy** *(ruled 5 September 2026)*: `fn`'s reading rule is the data rule, so `g := f` is an independent function record sharing f's body graph, `g.compile()` installs bcode on g alone, and `f` is untouched — a fn is a value of type `fn` as an i32 is a value of type i32, and only `type` returns the identity, because a type is what every value's type slot points at, so a copy of it would classify nothing. `language` and `proof` are left to their own constructors, open. An anonymous value with its type is written by juxtaposition — `i32 32`, `f64 2.0`, the type preceding the value — never `T = value`. Recorded as rejected with the ruling: `:` as a type-slot write that bypasses the type's constructor — its old reading, under which `key : T` and the bare `key :` are now superseded by `key := T ?` and `key := ?` — on the ground that the type must be constructed anyway, so a second door into the type slot was a second mechanism. The door left open is `:` returning as pure sugar, `a : T` meaning exactly `a := T ?`, if parameter lists force it back. The seed's `:` stands in until driver convergence. The relation is exact: a name may carry a type and a value but need not, a type may carry a name and a value but need not, and **a value always carries a type** (the type defines how it is read). Names live in the trie; type and value live in the dyad.

`=` is **reassignment, not declaration**: `key = value` overwrites the value of an *already-declared* `key`, keeping its type, and is an error if `key` was never declared — so a mistyped `cont = 6` on an undeclared `cont` is caught rather than silently creating a binding. Declaration is therefore always `:=` (`key := value`, `key := T ?`, `key := ?`) *(amended 2 September 2026)*; `=` only ever rebinds what already exists, and type inference rides `:=` (the type is read from the value). The two operators sit at the very top of the precedence order — the loosest binders — and associate right to left, which is what lets the language define its own operators: `:= := …` is a well-formed declaration whose left operand is the `:=` spelling itself. Parentheses are one identity in that order, and it sits near the top *(rewritten 2 September 2026; the July wording — grouping paren loosest, call paren tightest — described the superseded model)*: `(` is constructed at discovery (*The scope's constructor is the driver*), so a group is a single finished cell before any operator around it runs, and a call `f(a)` is that same cell consumed by the callee's own constructor — the tight juxtaposition just below it, no second bracket. A constructor that takes a *type* as an operand — `array i32 (1, 2, 3)`, `fn () -> i32 ( body )` — authors its own precedence above that juxtaposition level, so `array` takes `i32` before `i32` could take the group as a conversion; the number is written in the identity's own body, as `fn`, `if`, and `for` write theirs, and `type` supplies no default for it *(ruled in discussion, 2 September 2026)*. *(Settled in discussion, July 2026.)*

**`mut` is a gate on the identity's record, not a type** *(ruled 5 September 2026, superseding the type-modifier reading this paragraph first recorded, which stands below as the superseded record)*. Every identity's static record — the id → metadata record of *Metadata has three homes*, where the identity's lifetime lives — holds its **gates, one per slot**, and `mut` is the write gate on the value slot, a prefix constructor on the value like `pub` (`x := mut 5`, `x := pub mut 5`; a name alone stands left of `:=`, *Declarations are immutable by default*), with `x := mut i32 ?`, `&mut` (which is `&`'s own spelling), a field's `x := mut f32 ?`, and the four-state construction spelling below all the same gates. The record is the *identity's*, not the name's *(sharpened 5 September 2026)*: the name entry, the `id_context`, holds what is true of the name — its scope and its liveness range, since `own x` kills the name while the value lives on under another — and points at the identity, whose record holds what is true of the value, its lifetime and its gates; a lookup reads the gate through the pointer, still one lookup, and an anonymous value is gated the same way because it has the record and never needed the name (so `y := pub x` makes y a public *copy* of x's value and leaves x private and untouched — `:=` copies, below). **A type never carries mutability**: `array i32` is one interned type whether or not its elements are written, `+` over a mutable i32 resolves to `add_i32` with nothing to strip, rewrite patterns never see a `mut`, and `y := x` does not copy x's mutability — inference reads the type from the value while the gate defaults to closed, so `y := mut x` says otherwise. An access along a path is permitted only when **every record along the path grants it** — `b.x = 5` needs the write gate on `b` and on the field declaration `x`, so an immutable binding protects its contents and a frozen field stays frozen inside a mutable one — composed under the Kleene rule of *Read and write are one mechanism*; a **dereference starts a new path** — `b.r@ = 5` writes at the address `r` holds, not inside `b`, so it needs only the reference's own through-gate, the `&mut`, and a reference record therefore carries two gates, write to its slot and write through it (the permission *Reference-granular permissions* already puts on the reference identity). A field's gate lives on the field declaration's record, **once per type, never per instance** — a field is bytes at an offset with no record of its own, the same fact that keeps `own` to bare names — so per-instance restriction is done at the binding, `a := p ?` against `a := mut p ?`. The record is consulted at **every elaboration** — parse, graph mutation, reflection — and **never by running code**; it is not erased, the records staying resident for the whole run, compiled code simply never resolving a name. Reasons: a value's permissions are facts about identities, not about machine types, so one record answers reachable, live, and permitted in one lookup, and the seed's liveness range already showed the shape — graph truth on the declaration, the record as the derived fast path; whereas `mut` in the type had made every type carry a second identity and inference copy mutability from value to name. Deleted with the ruling, to stay deleted: **name-mutability**, `mut key` as a renameable trie entry, which nothing used and which had made the commonest declaration mean something exotic. Storage is unchanged: a field whose record grants write is per-instance bytes, one that does not is stored once with the type (*Two muts*). *(Superseded record follows.)* **`mut` is a type modifier — `mut T` is the type of a mutable T**, so mutability is something the *type* states about the value, not a separate value-position qualifier. The type is the sole authority on what the value permits, so the capability lives there: a value whose type is `mut T` is the everyday mutable variable, one whose type is `T` is immutable, and there is no value-position `mut` form — `mut` never sits before the value (`i32 mut 32` is rejected: the value is raw bytes, with nowhere to carry the capability). This is the very same `mut` as in `&mut T` (mutable access to a T), one rule rather than two, which also retires the old inconsistency of writing `mut` on a reference type but forbidding it on a declared type. A record type's per-field mutability rides on each field's type the same way (`f := mut F ?` mutable, `f := F ?` not), so the type alone describes which parts are writable. Changing the type slot itself — reclassifying the dyad rather than writing its value — is not a value-level mutation: it needs the type's *own* classifier to carry `mut` (the identical rule one level up), or a fresh `dyad` built with the new type, which is the immutable-by-default path. This is one recursive rule: **`mut` left-prefixes a type at any level of the classifier tower (`value : i32 : type : …`) and makes the level just below it mutable** — `mut i32` marks the *value* mutable, `mut type` (mut at the ground `type` level) marks the *type slot* mutable. The two are independent permissions on the two slots, so a value-construction expression spells out four states: `i32 32` (frozen type, frozen value — the plain constant, by far the most common), `mut i32 32` (frozen type, mutable value — the ordinary variable), `mut type i32 32` (mutable type, frozen value — *reinterpret-only*: the fixed bytes may be re-read through another type but never overwritten), and `mut type mut i32 32` (both — full structural mutability). Making the type mutable does not imply a mutable value; reinterpret-only is its own quadrant. The tower tops out at the `type : type` self-loop, so `mut` sits at only these two levels in practice — anything higher would mutate the universe. Prefixing the *name* with `mut` (`mut key`) still makes the **name/identification** mutable — the trie entry, not the dyad, since the dyad's content is already reachable through its two slots — and `mut (…code…)` still makes a whole region **structurally** mutable. *(Recorded open 4 September 2026 as a conflict with the gate section's `pub mut x := 5`; resolved 5 September 2026 by the ruling at the head of this paragraph — name-mutability is deleted and `x := mut 5` is the write gate on x's record.)* These stratify by how much structure can change, which is exactly the compile/freeze rule: value-mutation is ordinary data change and stays **compilable**; a type change rewrites how the value is read, so it is **checked and deoptimizes** on write; a structural `mut (…)` region has a live structural writer and therefore **stays interpreted** until it freezes.

**Both slots of a dyad follow one lifecycle: `undefined` → defined → frozen.** `undefined` is the hole — no value yet, writable until defined, and reading it is a checked error, never undefined behavior. The exclusivity rule makes that check local: while a slot is still mutable, only the constructing scope can reach it, so no other scope can ever observe an undefined slot — the flip *is* publication. The two slots obey **one rule at successive levels**: each is written by its definition and then frozen by default, and stays writable past definition only when its classifier carries `mut` — the value while its type is `mut T`, the type slot itself only while the type's *own* classifier is `mut` (the same modifier one level up). The giant common case carries no `mut`: defined once, frozen, the type reading true forever. Reclassifying a live dyad is therefore not an everyday declaration — it needs that one-level-up `mut` or a fresh dyad — and it is not free: a type write must discharge **validity** (the existing bytes are a valid value of the new type) and **layout** (the new type reads the same shape, or storage is reallocated), obligations the refinement/proof layer discharges where it can and that fall to `unsafe` where it cannot, exactly like a checked `transmute`. Because reallocation is itself a value write, a *layout-changing* reclassification additionally requires the value to be mutable; the mutable-type/frozen-value state therefore admits only layout- and validity-preserving reclassifications — the bytes are re-read in place, never moved or rewritten. Structural graph edits that rewrite a dyad's type are the other sanctioned type writes, triggering re-validation as all `graph_mut` writes do.

**The flip is `immut x`, and it is one-way.** Flipping is a write to the dyad's phase, so the ordinary reader–writer rule blocks it while any reference is outstanding — making it owner-only with no live borrows, the same shape as a move — and no separate authority mechanism is needed (a `metamut` grant was considered and rejected; delegating flip authority is just ownership transfer). The reverse flip is rejected outright: facts derived from reading a frozen dyad outlive any reference to it — a checker concludes and drops its reference — so un-freezing is unsound without universal dependency tracking. Frozen is final, which is also why a flip never invalidates anyone: no reader can have assumed less mutability than existed.

**Phase is stored as tag bits, not wrapper nodes** *(proposed)*. A wrapper around the dyad breaks type transparency — reading the dyad's type would yield the wrapper — and a wrapper spliced into the value chain falsifies the prime invariant that the type defines how the value is read. So the construction phase lives in neither: dyads are sixteen-byte aligned, the low bits of the type pointer are therefore free (four of them), and they record each slot's construction state — undefined, defined, or frozen — for both the type and the value slot; name-mutability and structural `mut (…)` are not per-dyad phase, living instead in the trie entry and the region marker respectively. The flip clears a bit in the dyad's own cell — no wrapper ever exists, no address anyone holds ever changes — and the model stays uniform while the storage stays free: every dyad *has* a phase, none *stores* one as structure. Interpretation masks the bits; compiled regions are frozen by construction, so masking is elided exactly where speed matters. Whether the phase should also be *visible* as structure is a presentation question, not a storage one: reflection can synthesize a wrapper view of a dyad whose mut bit is set, so tooling that wants mutability in-your-face gets it without every dyad under construction paying sixteen bytes for the privilege. Per-field mutability of instance fields is carried by neither bits nor wrappers — fields in a value area are raw bytes at offsets, not dyads, under any scheme — but by each field's declared type in the type's scope (`mut F` vs `F`), per the modifier above.

**Two muts, and the storage partition.** The `mut` in a *declaration* is a per-field fact across all instances — the write gate on the field declaration's record *(5 September 2026)*: it is what the derived layout reads, it is fixed when the type is defined, and an instance's later flip never changes a shared layout. A field that is ever mutable — even only during `init` — is per-instance; a binding that is never mutable is identical across every instance and is stored once with the type. A record type is thereby simultaneously C++'s struct (its mut declarations, from which the per-instance layout is *derived* rather than authored) and C++'s namespace (its immutable members, stored once) — and a type whose members are *all* shared is a pure namespace, which is what a language is: the merge of `type` and `struct` into the one identity `type` *(ruled July 2026; respelled, with `language` split back out as the section-opening identity, 4 September 2026 — see* Substrate vocabulary*)* is this partition read to its end. Placement is decidable at the declaration site, writes being the only thing that can differentiate instances. A type's layout-relevant slots must be defined and frozen before its first instantiation; the type locks there.

**Resolution is one rule.** A type keeps the defining scope it was constructed from, and `a.x` asks `a`'s type for `x` — probing the type's `instance (…)` scope, then, if `a` itself has a definition body, `a`'s own bare scope (its namespace members), and climbing no further inside one `.` *(precision ruled 30 August 2026)*; the declaration found decides everything — declared mut: a *place*, the byte offset inside `a`'s value area; immutable: the stored dyad itself. Visibility is one extra test at the same lookup. A call frame is an instance of its function — parameter declarations resolve to a frame exactly as field declarations resolve to an instance — and lookup continues up the type chain, terminating at the `type : type` self-loop.

**Substrate vocabulary.** The cell is the **`dyad`**, its two slots the **`.type`** and the **`.value`** *(ruled August 2026, reverting the July Greek triple — the cell was briefly `synolon`, its slots `logos` and `hyle` — because newcomer-plain words win; *synolon* and *hyle* are retired everywhere)*. The classifier ground is **one identity, `type`**, and **`logos` is a language** *(ruled 4 September 2026, superseding the July merge's naming while keeping its substance)*: every classification chain terminates at the `type : type` self-loop, `type` is the definition keyword (`x := type (…)`), and what it defines is one thing with two defaults — a record type derives its layout where a bare definition leaves parsing and semantics to its author — so `struct` stays merged into `type` (a type with `instance (…)` fields), the alias door of `x := i32` still open for the word. `language` is an identity of type `type`, not a second ground: its constructor opens a body as a **closed section** (*Sections, the arche, and effect identities*), and the Logos language is `logos : language : type` — the identity `logos`, the `logos` binary, and the `.logos` file extension share one spelling because the language is what all three name. Inside Logos code `logos (…)` continues the Logos language's own scope, which makes it the plain group; from inside another language it is the door back, `if := logos (if)` binding Logos's `if`, which stands as its own value under the decline rule (*The constructor is a field*); in a language's definition body the door is one of the five starting names, in its blocks it exists only where the definition admitted it, `logos := logos (logos)` *(ruled 4 September 2026, see *Sections, the arche, and effect identities*)*. Grounds: a type-rooted chain, `3 : i32 : type : type`, is what a newcomer expects, and a language being one identity among the types it defines is what lets a new language be written as one. Superseded in place: the July naming — `logos` as the ground identity's proper name and as the definition keyword, and "`type` and `struct` … never as separate core identities"; the seed spells the root `type` and keeps `logos` as a transitional alias of it until the `language` identity exists to give `logos (…)` its ruled meaning, and the sketches and examples are respelled *(4 September 2026)*. `any` was removed and split: `undefined` is the hole, carrying a definedness obligation; `?` is the **unknown** — a deliberate, classified hole the author writes in place of code not yet designed, inert until filled and rendering any build that reaches it incomplete by construction; it differs from `undefined` (which says *nothing was written here yet* — a checked error to read) by saying *the value is not yet known*, a standing synthesis goal a maturing Logos discharges by the same backward proof search and coherentist plausibility ranking the proof layer already provides, graduating a `?` from left-alone to suggested to filled-and-verified. `@void` is a type-erased address whose interpretation comes from elsewhere — the honest type of the dyad's value field, since interpretation always comes from the type pointer. `native` is a function that is callable-only — a machine-code body (`@exec`) with no Logos source, opaque to reflection (invoked, never read into), and distinct from both `undefined` and `?` because it runs and reaching it is no error; the seed's primitives are all `native`, ported to reflectable Logos source one identity at a time (see *The architecture*). Recorded as rejected, to stay rejected: `metamut`, the reverse flip, `any`, a separate `struct` core identity (merged into `type`, above; `language` is distinct from `type` by the 4 September ruling), the plural "logoi" in any Logos writing (`logos` is invariant; a dyad pluralizes as dyads), a per-record field-name hashtable (field names live in the shared name index, scope-filtered — one resolution mechanism), inheritance, imitating `while` with a stepped `for` (a per-iteration condition deserves its own spelling), the composed declaration `key : T = value`, `:` itself as a declaration operator *(2 September 2026)* — the declaration forms are `key := value`, `key := T ?`, and `key := ?` alone — and, *(5 September 2026)*, `mut T` as a type and name-mutability (`mut key` as a renameable trie entry): `mut` is a gate on the identity's record (*Mutability and construction*).

## Native interop and the Rust bridge

**Logos reaches existing native code as black-box C-ABI calls, not by hosting other languages.** The runtime is an ordinary Rust program built by rustc (LLVM); Cranelift's role is to JIT-compile Logos code at run time. A foreign function is called in-process, by address, across the platform's native calling convention — the same convention `extern "C"` selects, and the one Cranelift-based JITs like wasmtime reach (through trampolines) to call host functions — so even JIT-compiled Logos code calls native code with no linker step, independent of which backend compiled either side. The boundary is the conventional one — `extern "C"` signatures, `#[repr(C)]` data, panics caught before they cross, an `unsafe` contract the borrow checker cannot see past — and richer Rust types (`Vec`, `String`, generics) are reached through a thin per-function shim a binding macro can generate.

**The toolchain is a build dependency, not a runtime one.** Logos ships as a standalone interpreter; that it is written in Rust is how it was built, not what it needs to run. Native code is compiled in as core builtins, loaded at runtime as separate `cdylib` artifacts (interpreter and Rust toolchain ship apart), optionally produced on demand by invoking `rustc` and then loaded, or isolated behind IPC where a crash must not propagate. Hosting a language's full semantics as a Logic Graph dialect remains a separate, heavier option; the bridge is the cheap path to reusing existing ecosystems.

## Error handling

Errors are values: tagged unions `(T | Error)`. Fallible functions declare their error types; callers handle results explicitly via `match`, with `success` / `fails` combinators for boolean outcomes. No exceptions; no implicit propagation in the core — propagation is the explicit `try` *(ruled in discussion, 31 August 2026; Zig's shape)*: `try f()` inside a `!` function hands a callee's error straight to the enclosing function's caller, one visible word per call site, sugar over the `match` that remains the core mechanism. The union is spelled `T!` *(ruled 30 August 2026)*: `fn () -> i32!` hands a recoverable error to its caller. A **checked error** is a different thing *(ruled the same discussion)*: it is never part of a declared type, so it is not a value but a **fault** — the task that hit it is cancelled exactly as *Scheduling, preemption, and cancellation* cancels a task, stopped at its last boundary with the pending `defer`s of its live scopes run and no further steps, the diagnostic being the cancellation's reason; in a single-task program that is abort-with-a-message, teardown done. `T!` is for declared fallibility only; the refinement tier turns faults into compile-time obligations where opted in. Constructor signatures are `-> void!` *(amended in discussion, 31 August 2026, superseding the 30 August "carry no `!`" clause)*: a syntax error a user can cause is a recoverable value — the constructor's `error «…»` builds it — which the driver, the enclosing scope's constructor, handles by recording the diagnostic, marking the cell, and resynchronizing at the next segment boundary or closer, so one parse yields many diagnostics (what tooling needs). A **fault** remains what a constructor hits only on a broken internal invariant — the "cannot happen" class — alongside the checked-error family above. **Staged out of v0.1.0** *(ruled in discussion, 2 September 2026)*: v0.1.0 carries none of the error-value layer — no `T!`, no `try`, no `match` over errors — so the seed knows faults only. `error «…»` is the one primitive, it never returns, and the run aborts with its message, one diagnostic per run; constructor signatures in v0.1.0 are therefore `-> void`, and `T!`, `try`, and the resynchronizing driver land afterwards as library and driver work over tagged unions, converging on the ruled shapes above, which stay the target.

## Meta-reflection and the unified system

This commitment ties everything together.

- **The Logic Graph contains its own parsing rules.** Every token, operator, precedence, and associativity is a queryable node; the parser is non-context-free because it consults the trie, which is itself part of the graph. Tooling becomes language-aware by introspecting the graph rather than reimplementing the syntax.
- **The Logic Graph contains the compiler.** Above the bootstrap seed, the borrow checker, type checker, rewriting engine, optimization passes, and the lowerings (Logic Graph → Logos IR → backend) are all Logos programs and all graph subtrees; the seed itself is the frozen exception — reflectable but not rewritten. Adding an optimization is library work; targeting a platform is implementing the backend interface plus contributing rules.
- **The Logic Graph contains the standard library.** Standard-library code is not special; it is code that ships with the system, readable and (carefully) overridable.
- **The Logic Graph contains documentation, source positions, comments, and metadata.** Docs and comments are the same thing: `#`-built prose nodes interleaved with code, void-valued and invisible to value flow (see *Text literals are plain values*); cross-references are graph edges; positions are node properties (held in the derived source-map).
- **The Logic Graph contains proofs and specifications.** A refinement is a subtree of a signature; a correctness proof is a subtree of a definition. Refactoring code and refactoring its proof use the same tools.
- **The Logic Graph eventually contains the IDE.** Editor behavior, highlighting, refactoring, debugging UI, and configuration are Logos programs over Logic Graphs — hot-reloadable, customizable in Logos, with structural editing as library functions. The Smalltalk vision applied to a modern systems language.
- **The Logic Graph eventually contains the running application, and the browser.** Because the IDE is Logos over the graph, and Logos has I/O and compiles to portable backends, the same reflective structure grows without a rewrite into a shareable, networked, rendering platform: a browser reached from the tooling end rather than built as one. See *The IDE as platform, and the reflective web*.
- **Stratification handles foundational paradoxes invisibly.** When the type strata reason about themselves or proofs quantify over the proof system, a universe hierarchy (following Lean 4) keeps things consistent. Ordinary code never encounters it; only explicit meta-mathematics does. *(Qualified August 2026: with proofs as rewrite rules the hierarchy is not needed for the ruled shape; it re-enters only if rules quantifying over rules are shown to admit a paradox — see* The proof layer*.)*

## Representation, elaboration, and lifetimes

This section records the mechanics of how the Logic Graph is represented, how source becomes runnable, and how runtime-generated structure relates to source.

**A dyad is a type and a value; its definition supplies everything else.** Every dyad is exactly two pointers — a `type` and a `value`, sixteen bytes — and a dyad's *identity is its address*, so dyads are uniformly addressable by handle whatever allocator holds them (no arena is required; the address is the id). The `type` pointer defines how the `value` is read: the type's *definition* — itself a Logic Graph — specifies the dyad's layout, how it consumes surrounding tokens during parsing, the conditions under which it lowers to Logos IR, and the IR it produces for each well-checked case (a `+` over mismatched or sizeless types simply does not lower until that is resolved). Operands are *not* stored inline; they are reached through the `value` pointer, so a binary `+` is a single 16-byte cell referencing its two operands rather than three inline pointers. What `value` points at is an operand *record* whose layout the dyad's definition supplies — the same rule that a type defines how its value is read, applied to operators: a binary operator's value is a two-field record (LHS, RHS) that a third field extends once its operand type resolves — the conserved `[LHS, RHS, type]`, so run, compile, and reflection dispatch on the stored concrete op rather than re-derive it — a function call's is its argument record (one field per argument, a one-field anonymous record for a single argument), and a variadic call's is that record sized per call site. A growable list is never inline either: a sequence's expression array rides behind one indirection, an `array` value the scope dyad's value references. The operator is thus a higher-level identity describing *how to read its operands*; which concrete machine operation runs — which `+` — is resolved from the operator together with the operand type, not from the `+` dyad alone. A dyad is therefore directly addressable once its handle is held, but the graph is *not* addressable by position or name without context: source code is meaningless without its surrounding context, so lookup from text proceeds by trie-directed traversal (the same trie the non-context-free parser consults), with auxiliary indices added where repeated reflection warrants them. Every dyad *is* an identity; most identities carry no string name and are addressed structurally, by pattern-matching over the trie and graph, rather than by name. This is MLIR's idea — a node whose *definition* describes its parsing, operands, and lowering — recast onto a uniform two-pointer cell and fused with the reflective parser. MLIR itself is a candidate *backend* behind the backend interface, never the IR: the Logos IR must be a Logic Graph stratum so the same rewriting engine, type strata, and proofs apply to it, which an opaque external IR could not provide.

**Numeric literals are uncommitted until context classifies them.** A numeric literal lexes as `rational_number` — not a fixed machine type but a comptime-number that can mold into any `int`, `uint`, or `float`. Because the concrete `+` is chosen from the operand types (above), a literal beside a classified value takes that value's type — `a + 1` with `a` an `i32` is i32 addition, `1` molded to i32 — which is what lets one operator and one literal form serve every numeric type without per-literal suffixes (`1i32`, `1.0f`). When *both* operands are still `rational_number`, there is no machine type to mold to, so the operation is carried exactly over the number's reduced fraction (`[num, den]` — a rational is a fraction pair, never text) and the result *stays* `rational_number`, committing to a concrete type only when it finally lands in a classified slot. The resolution rules follow from this: two operands of the same concrete type keep it; a concrete type beside a literal molds the literal to it; two literals stay `rational_number`; two *different* concrete types do **not** silently lower — there is no implicit coercion. Crossing types is therefore explicit, and reuses the token-consumption mechanism above rather than a separate `cast` identity: a numeric type applied to a value (`i32(a)`) *is* the conversion, per-constructor rather than a uniform cast syntax. A comparison resolves its operands the same way but its result is `bool`, one of the primitive types. The logical operators short-circuit; the seed's `not` takes a parenthesized operand (a parsing simplification, not a keep). **`-` before an operand is negation** *(ruled 5 September 2026; the spec was silent and the sketch had said `-` is always the binary operator)*: one identity, whose constructor reads its left context — a constructed operand at `tape[-1]` makes it subtraction, anything else the prefix form — so `a-1` stays subtraction, `-y * 3` negates y first, and `-3` still folds into the literal; the prefix form binds tighter than the binary arithmetic operators, `-y * 3` being `(-y) * 3` (stated as consequence: a user operator that wants to bind tighter than negation sets its precedence above negation's). Reasons: `-y` is what every reader writes and `0 - y` was a workaround; and an operator deciding its arity from the cells beside it is exactly what the eager-segment model gives every constructor, so no second identity is needed. The seed's rejection of `-y * 3` is a bug, folded into the driver convergence (#59). Integer division and remainder are **total, saturating**: `x/0` yields the type's MAX for a non-negative dividend and MIN for a negative one *(sign-aware, ruled 30 August 2026, keeping the float `±inf` analogy honest; `0/0` is MAX, unsigned has only MAX)*, `x%0` yields MAX, and signed `MIN/-1` saturates (`MAX` for `/`, `0` for `%`) — a deliberately loud value, easier to discover than a silent `0`, and the integer analogue of float division's infinity; float `/` is IEEE, and float `%` does not exist (rejected at parse). That is the base tier's defined behavior where nothing proves the divisor nonzero — division by zero cannot be ruled out statically in general — while the refinement tier turns it into a compile-time obligation wherever guarantees are opted into; the two layers compose rather than conflict. The seed folds both-uncommitted arithmetic exactly over `i64` fractions (an out-of-range result is a clean error, not a wrap); true arbitrary precision is deferred, not blocked.

**Text literals are plain values; `#` is the one comment constructor, over the same substance.** A string literal is written `«…»` and is always an ordinary value — never position-dependently a comment, so no value rule ever has to guess what a bare string means (a docstring convention was considered and rejected: at an untyped tail, `x := ( 40 + 2, «a» )` cannot decide between doc and value). Prose is instead always *marked*: `#` is an ordinary identity whose constructor consumes either a following `«…»` string or the raw text to the end of the line (the line form is sugar for the string form), and builds a **comment node** — the same text substance either way, one token, no line/block/doc-comment zoo. A comment node is real, reflectable graph structure interleaved with the code it annotates — documentation is therefore extracted by graph query, not by scraping special syntax — but it is void-valued and invisible to value flow: evaluating one yields nothing, and the value rules (a scope's trailing expression, tail commitment) read through it, so a trailing `# done` never becomes a scope's value and prose never returns anything to the enclosing scope. The seed already builds the reflectable comment node over the `string` substance, in both forms: `# raw text` to end of line, and `# «…»` bounded by the string alone — spanning newlines and ending at its `»`, with anything after it live code; `#` becomes a graph-resident constructor identity at self-hosting. *(Settled in discussion, July 2026.)* Two rules ruled 30 August 2026: the `«` constructor nests by depth — it counts `«`/`»` and `{`/`}` — so a string inside an interpolation inside a string needs no escape; and the only escapes are a backslash before a character the string scope itself lexes and before the backslash — `\{`, `\}`, `\«`, `\»`, `\\` — everything else in text being raw. `«…»` is the one string spelling: no ASCII alternative (`"…"`) anywhere, in files, the REPL, or the command line; typing it is a keyboard and editor matter.

**Pointer types are prefix `@T`; dereference is postfix `x@`; `&x` is address-of.** *(Settled in discussion, July 2026; supersedes the earlier postfix spelling.)* The pointer is the first thing the user interacts with, so it reads first: `@i32` is a pointer to an i32, composing as `@@i32` and applying to any type (`@point`, `@dyad`). Dereference puts the pointer on the left — `p@`, chaining as `p@.x` and `p@@` — reading in evaluation order where a prefix form would need parentheses (`(@p).x`). The split is also what keeps the grammar unambiguous: a dereference can never *start* an expression, so an `@` after a completed value is always a dereference and an `@` opening a type position is always the pointer-type prefix. `&x` takes the address of a storage-backed place (`&p.x`, a field's). The `@`-family is the *raw address* stratum — unchecked, which is all the seed provides at v0.1.0 — and the borrow checker's checked references (`&T`, `&mut T`) later layer on top of it: the same addresses, plus the proof they are used safely.

**The dyad is self-describing down to one fixed point.** The dyad's `type` field is itself declared as a pointer to a *dyad* — not to a classifier primitive: that something functions as a type is a checked invariant, not a substrate field constraint, because the substrate cannot state it. Interpretation is the recursion — to read a dyad, consult its type; to read that, consult *its* type — grounding out at the one dyad whose type is itself, whose layout is the seed's only a-priori knowledge. With the value field a type-erased address (`@void`) and the type field a dyad address (`@dyad`), the substrate is described purely in terms of itself plus raw addresses.

**Source becomes runnable by interpretation; compilation is opt-in.** Source text is converted to Logic Graph nodes one token at a time, and the graph is interpreted directly — there is no separate parse-then-run step once it is in the graph. Scopes marked for a backend (`backend cranelift (...)`) are lowered before they run; everything else is interpreted, and the runtime may promote hot regions to compiled form. Compile-time evaluation is ordinary interpretation performed earlier: a `comptime` marker forces it where the guarantee matters (a result baked into the artifact rather than recomputed each run), but the common case is inferred — the compiler interprets the graph fragments a compiled scope depends on. Because compile-time evaluation runs under a capability set that excludes I/O (effects are capabilities; see *The type strata and verification*), builds are reproducible by construction, while ordinary runtime code retains I/O. Parsing rules are Turing-complete: a type's `constructor` is unrestricted code (surface forms as irregular as natural language are in scope), and a declarative consumption signature, where a type chooses to carry one, is an optional fast path the recognizer can merge and index, never a ceiling. The generic prologue every `constructor` needs (bounds, this-token-is-me) is not written per type: `type`'s own `constructor` installs it, by reference to one shared checker, into every type it constructs, so the contract is visible graph structure; core identities, hand-built by the seed rather than constructed through `type`, are correct by construction. A `constructor` works against two states that stand at every source index: the *parsing tape* and the growing Logic Graph. The tape is the working frontier, holding both the dyads reduced so far but not yet final and the tokens still to consume, the latter lexed lazily on demand (reaching the next position is what pulls the next token from source), so lexing and parsing are one pass the constructors drive rather than two. A constructor reads forward on the tape for the tokens it consumes and back on the tape for its left context, the dyads reduced there so far. When precedence guarantees a cluster will consume no more tokens it is final, so it detaches from the tape and attaches at the current location in the graph, and the next locations are decided by the earlier dyads: an `if` opens a slot for a condition and a body and an optional `else` body, and stays incomplete until those are parsed and placed relative to it. The tape carries `insert`/`remove`, so a constructor may splice tokens in or drop upcoming ones before they lex, and that is the whole macro and custom-syntax mechanism: a syntactic abstraction is a constructor rewriting the token stream over real dyads, not a macro sublanguage. A constructor never hands a result to a scheduling driver: it edits the tape *in place* — replacing its own token with the dyad it built, or with another token, splicing out the neighbours it consumed, inserting tokens elsewhere on the frontier — and the driver decides only *when* constructors run (the precedence decision), never what they leave; what a constructor reports is just applied-or-declined, an explicit signal because a tape left holding a token is a legitimate outcome, not a refusal. The tape is therefore not a private parser structure but **Logic Graph with a string extension**: a constructed cell is a graph dyad already, an unconstructed cell is a pointer to its candidate identity, its span held in the derived source map — a dyad-in-waiting — and the string is the source not yet lexed *(wording amended 2 September 2026)*, so reflecting on the tape needs no second metalanguage, and tape positions, `insert`, and `remove` enter as ordinary identities (the sketch's `parsing_tape` machinery; `token` as a wrapper identity is superseded, 2 September 2026 — an unconstructed cell points at the identity itself) for the constructors self-hosting writes in Logos. *(Ruled in discussion, July 2026.)* The tape is disposable working state, so its splicing corrupts nothing durable; the source text and the graph it builds are what persist, and a re-parse rebuilds the tape from source.

**Elaboration is deferred-reduction operator precedence over the tape.** The driver lexes a segment whole and constructs it highest precedence first *(the eager-segment model, ruled 30 August 2026, superseding the one-token-lookahead shift/reduce this paragraph first described; see* The scope's constructor is the driver*)*. Precedence is an `f64` deliberately: fractional values let a new operator slot between any two existing ones without renumbering — higher binds tighter, associativity breaks ties. A precedence may be spelled *relative* to another identity's — `precedence = mul.precedence - 1` *(the operator is `=`, ruled 4 September 2026: a slot `type` declared is filled, not redeclared, see *The constructor is a field*)* — which is ordinary comptime field arithmetic under *Deferral is authored* (an unresolved operand stays a visible node until forced) and must be resolved by the operator's first use, the ordinary use-before-definition error otherwise *(ruled in discussion, August 2026)*; it is one number on one shared axis, and stays so — the partial order of binding groups is closed as a question *(ruled 30 August 2026)*: declined for the axis, and if unrelated operators are ever to demand parentheses that layers on top as an ordinary check between two operators' groups, changing neither the field nor the driver. Reduction is deferred, so a token's identity is fixed not when it is first scanned but when it is reduced into its dyad, which is what keeps tokens mutable until then and makes a reduced dyad frozen against further token rewriting. That is what lets a higher-precedence operator to the right still rewrite the tokens on its left: it runs while they are still tokens (their reduction has not been forced yet) and they reduce afterward with their new identity, while anything already reduced to a dyad is immune. A constructor may look arbitrarily far forward where its own syntax needs it (lexed lazily) and may rewrite tokens behind it, but that backward reach is bounded to its own scope. Matched brackets are that bound: a bracket pair is a scope boundary that forces its contents to reduce into one dyad, caps a constructor's backward reach at the enclosing bracket, and is the point the token stream re-synchronizes on after a structural edit. Brackets are structural and always nest (`(` `)`, `{` `}`, `[` `]`, and any construct that opens a scope), the same nesting the scope spine records, whereas separators such as `,` are ordinary within-scope tokens, not boundaries. Token rewriting is therefore a within-scope, parse-time power (the Turing-complete parsing above, unchecked in the seed and admitted later only at a level that proves it terminating and deterministic); anything that must reach across scopes operates on the reduced graph through the rewriting engine, not on the token tape.

**Expressions are self-delimiting; `,` is the one explicit separator.** A scope's body is a sequence of expressions with no terminator: the finality rule above — a cluster detaches the moment precedence guarantees it will consume no more tokens — is also what ends each expression, so consecutive expressions simply follow one another, each complete in itself; between *independent* expressions nothing at all stands, while between *dependent* ones — a step that uses a name the previous step declares — the `,` is required under the eager-segment model, which in imperative code is nearly every line *(re-affirmed in discussion, 2 September 2026: newlines stay whitespace; a newline-sensitive rule — Go's continuation rule, or one expression per line — was considered and declined, and paren-less `if c body` with it: conditions and bodies stay scope cells)*. Newlines are ordinary whitespace and `;` does not exist; both are recorded as rejected — `,` is already the one separator, and a second spelling for the same boundary buys nothing *(reason restated 2 September 2026; the earlier ground, that constructors decide every boundary, held for the superseded finality model)*. Separation must be explicit only where adjacency would otherwise read as consumption — where a constructor whose trailing operand is *optional* sits before a value it must not take: `f(i32 3)` is one argument (juxtaposition: `i32` consumes `3` into an anonymous value with its type), while `f(i32, 3)` is two, the type itself and an uncommitted literal. The mechanism is precedence, not a special rule: `,` carries the higher precedence, so it is constructed before `i32` reaches for an operand, and a constructor that accepts not consuming its right-hand side then yields its own dyad as-is — the type as a value. Under the eager-segment model (*The scope's constructor is the driver*) `,` sits above `(` and closes a segment at discovery, which is also what sequences declaration before use within one scope. The same `,` therefore separates fields, arguments, and expressions, one separator everywhere; and like the optional `return` it may also be written where nothing is ambiguous at all, purely for the reader, marking the step boundary other languages spell `;`. *(Settled in discussion, July 2026.)*

**Hosted text does not owe a single reading.** Natural language is in scope as a surface form (the Turing-complete parsing above), and hosting it needs no new substrate: a hosted clause — Latin, English — parses to data, and data is a legitimate resting state. Per *Execution is function application*, a dyad whose type is not a `fn` is never run, so the clause enters the graph as nodes and simply stands, open to the recognizer, reflection, and rewriting but to nothing that requires a single reading. Where recognition is ambiguous the dyad carries every identity that matched; where the *structure* is ambiguous it carries the alternative sub-dyads themselves, a parse forest held as plain value structure; where the system knows nothing at all, the faithful floor is the text literal (*Text literals are plain values*). No obligation attaches at parse time: resolution is lazy, at a use site, where later information either eliminates the alternatives or the demand surfaces `?`, the universal unknown — never `undefined`, which keeps its meaning of nothing-was-written. What hosted language is *for* is truth: a declarative sentence denotes a proposition — an ambiguous one, a set of candidates — and "executing" it is the proof layer applied to that proposition, the checker the `fn` and the proposition its operand, so the evaluation rule stands untouched. The kernel will rarely certify such a claim — proof establishes only what can be specified, never the truth of arbitrary claims (*Received code is checked before it runs*) — so an empirical claim enters as an asserted axiom with provenance, committing to a branch of *the ecumenical proof system*, where contradictory testimony coexists and the coherentist layer grades how sure: proven, refuted, plausible-to-a-degree, unknown, its rankings feeding what to try proving and never counting as proofs. Epistemic status is therefore assigned lazily and revisably by the proof layer, never by the parser: the same untouched sentence climbs from unknown toward plausible or refuted as the web around it grows. Recorded as rejected, to stay rejected: driver-level backtracking (stored branches, rollback of finalized dyads) — finality stays guarantee-based and one-way, exploration lives before commitment (in guards and in-constructor lookahead), and genuine ambiguity is represented, not searched; and `undefined` as the surfacing of ambiguity, which conflates too-many-readings with nothing-written. *(Settled in discussion, July 2026.)*

**Compilation is a reader of frozen structure.** A compiled artifact is a long-lived *reader* of a subgraph's structure; what licenses it is the absence of any structural writer over that region for the artifact's lifetime. So the rule that a `graph_mut` invalidates outstanding readers *is* deoptimization — a structural write to compiled code drops the artifact and falls back to interpretation — while ordinary runtime values flow through unaffected, because what froze is the code's structure, not its data. The interpret-versus-compile choice is then an adaptive matter of profitability, not semantics, and needs no syntax: unannotated code is interpreted while cold or unstable and compiled once it is hot and frozen, with `comptime` the one execution marker that is genuinely semantic (it fixes *when* evaluation happens and what is baked into the artifact). The seed, however, does not promote automatically: it interprets everything and compiles only what is explicitly directed — and v0.1.0's direction is the `fn` type's own shared `compile` member (*Execution is function application*): write the function's body, call `f.compile()` in the pass, and the next call jumps to the installed code instead of walking the body *(settled in discussion, July 2026)*; the scope-granular `backend cranelift (...)` marker and profile-driven automatic promotion are later work riding the same deopt boundary. The same freeze licenses optimization — equality saturation needs a fixed input — so compiling a region, optimizing it, and extracting a cheaper proven-equivalent variant are one operation under one condition: no live structural writer. Editing itself runs only this analysis machinery, which is pure (it holds no I/O capability) over the changing graph; the user's program runs nothing until invoked, and the language's own machinery, being hot and structurally stable, sits permanently compiled and untouched by edits to user code.

**Mutable code is compilable; the reader–writer rule, not mutability, gates compilation.** A region classified `mut` is not barred from compilation — only a region with a *continuously live* structural writer is, and then only because the next write would deoptimize it, so compiling it would not pay. A mutable region that is currently stable compiles and runs at native speed like any other; the "`mut` stays interpreted" rule is this profitability fact, not a prohibition. What governs compilation is the one borrow rule applied to code as data: a compiled artifact is a *read reference* to code structure, so a structural write needs exclusive access and therefore drops every such reader first — that drop *is* the deopt. Two readers of code must not be conflated, because different timings keep them fresh: the **name index** (the resident trie of `id_context`s) never mis-resolves, because resolution filters candidates by open-scope membership: each `id_context` carries the scope it was declared in, and one whose scope is not live is skipped, so a stale entry is inert rather than wrong, and removal is cleanup on explicit source mutation rather than a per-edit correctness step; **`bcode`**, by contrast, `run` trusts and does not re-verify per call, so its freshness is the deopt layer's job (null the stale `bcode`, fall back to the body-walk), not the writer's. Until the borrow checker makes "no structural write while a code reader is live" static, this exclusion is a discipline the program keeps, exactly as with every other mutation.
**The callable ground is `@exec`: a jump capability, minted rather than checked.** *(Settled in discussion, July 2026; supersedes an interim `bcode {entry, arity}` wrapper, rejected as packing the caller's knowledge into the callee's pointer.)* Beneath `fn` there is exactly one executable primitive: `@exec`, an address the program may jump to — `fn`'s `bcode` field carries one inside its `callable` value (the entry paired with its declared convention), and nothing more. Executability is a property of pages, not bytes (the NX bit), and no instruction can ask "may I jump here?" — the only answer is the fault — so Logos never checks it: an `@exec` value can only be *minted* by the machinery that made the memory executable (a backend finalizing compiled code, or an explicit foreign declaration), the same fail-closed shape as every other capability. A jump that lands on non-executable memory is an upstream invariant violation, not a condition to test for per call. The *calling convention* — which registers carry which operands on which platform — is deliberately no part of `@exec`: it lives in the two pieces of code on either side of the jump, both emitted by a backend from the same abstract signature (the `input` record's order and widths), so platform variation is invisible wherever one compiler emits both sides; and the signature survives sealing (a seal keeps what has been read out — types — while dropping the body), so nothing must ride inside the callable. Conventions are declared metadata — ordinary identities a backend renders per target, open-ended rather than an enum — and they carry decisive weight only at the FFI boundary, where the foreign side froze its convention and the declaration is what lines the registers up. Boundary overhead follows: interpretation pays a trampoline per call; a compiler that sees both sides may inline, re-register, or delete the call entirely (co-compilation, including the JIT promoting hot regions); only genuinely foreign code keeps a boundary no optimization removes. The same boundary runs the other way *(ruled 4 September 2026)*: **`compile` never fails on an uncompiled Logos callee** — the call is emitted as a jump into the interpreter, `run`'s body-walk over that callee, so the function being compiled is machine code and what it calls may not be; an error was considered and declined, because an uncompiled callee is not a mistake in the program — interpretation is always a valid way to run it, the interpret-versus-compile choice being profitability and never semantics (*Compilation is a reader of frozen structure*) — and leaving the whole function uninstalled was declined because `f.compile()` must mean f is compiled, silently doing nothing being the one thing a user cannot detect. Compile order therefore decides the call's shape — `pow.compile()` then `f.compile()` gives a direct call that a later co-compilation may inline, `f.compile()` alone gives f with an interpreter boundary at the call — and a boundary left behind is lifted by compiling f again once its callee has code, the ordinary deopt-and-recompile path, with automatic promotion after v0.1.0 as before. The seed's fail-fast on an uncompiled callee, which leaves the caller interpreted, is the divergence to remove. Concrete machine operations are identities — `add_i32`, `fadd_f64` — each immutably carrying its `@exec`; a surface operator like `+` is the parse-time constructor that *resolves* an application to one of them, storing the chosen operation in the dyad, so nothing mutates and nothing is looked up in a side table: to evaluate a dyad, consult its type; if the type carries code, jump. Alternative implementations then live where versions live — versioned scopes — not in per-phase tables. The seed's run tier now lives this paragraph (July 2026): every native is a `callable` value — `[entry: @exec, convention]`, the type of `add_i32` and of a compiled fn's code alike — referenced from the dyad's own op slot, and the interpreter consults no table anywhere; the Cranelift lowering still rides a Rust-side table until lowering re-keys per backend identity.

**Foreign code is a declaration, and the C ABI is the lingua franca.** *(Settled in discussion, July 2026.)* An `extern` declaration names a library, a symbol, a signature, and a convention; the loader resolves it and mints the identity's `@exec` — minting by foreign declaration, the second of the two licensed mints — and an unresolvable symbol fails at load, never as a wild jump. Interpreted callers reach foreign code through a minted *thunk* (the backend compiles one adapter from the interpreter's convention to the foreign one per declaration), so the interpreter stays convention-blind; compiled callers emit against the declared convention directly; and a Logos function crosses the other way by being compiled against the foreign convention and handing over its `@exec` — callbacks are the same mechanism reversed. Data crosses on the platform's terms: struct layout is C-compatible (natural alignment and padding — diverging from the platform ABI buys nothing), and text bridges explicitly (`«…»` is `[len][bytes]`, not a NUL-terminated `char*`). C is the whole interop strategy: Rust exports over the C ABI (it has no stable one of its own) and C++ is taken through `extern "C"` surfaces, so winning C wins both transitively — essential while the library ecosystem is young. Header ingestion is the seamlessness multiplier, and it ends as the parsing doctrine applied to `.h` files: a constructor that consumes C headers and emits declarations, mechanical bindings no human writes.

**Execution is function application, and only functions execute.** Everything runnable is a `fn`; operators (`+`, `=`), field access, and even control flow are functions, so evaluation has one rule: to evaluate a dyad, read its `type` — if the type is a `fn`, invoke it on the dyad's value (its operand record); otherwise the dyad is data, read through its type's layout. A dyad whose type is a function is therefore an application, exactly as the operand-record model already implies. Control flow works as a function precisely because operands arrive *unevaluated* — a function receives its operand record as Logic Graph and decides what to evaluate, so `if` runs its condition and then only the taken branch; laziness is the default the substrate gives, not a special form. The `fn` type carries two shared functions: `compile` (lower the body to machine code, its `bcode`) and `run` (execute the function), plus per-instance `input`, `output`, `body` (the reflectable Logic Graph), `bcode` (the opaque compiled code, null until compiled), and `frame` (the activation-record byte size the function's parameters and locals occupy per call, null when it has none). **A type with something to run carries a function in its `code` slot** *(ruled 4 September 2026)*: a user-defined operator is defined with `type`, not `fn` — `^ := type (…)` fills its precedence, associativity, and constructor by hand, and one more slot, `code`, with an ordinary function written as any function is — so the evaluation rule reads: to evaluate a dyad, read its type; if the type is a `fn`, run it on the operand record; otherwise, if the type carries a `code`, run that function on it; otherwise the dyad is data. A node typed `^` thus runs and compiles exactly as a node typed `f` does, the type's `code` reached the way a call reaches a function, and `f.compile()` on a call site whose type carries a `code` compiles that function. `fn` is thereby the shorthand for what `^` spells out: a function's constructor, precedence, and associativity are the call defaults, and what an operator adds is only its own parse — "fn is just a shorthand for not needing to define constructor, precedence and associativity". `constructor`, `destructor`, and `code` are then three slots of one shape, each holding a function. Recorded as declined with the ruling: folding `fn` into `type` with parameters as instance fields and the body as instance lines; a constructor that emits the operation inline as residual code instead of a node reaching stored code — declined because an operator is one operation with one definition, and inlining its body at every use site would copy it per site and erase the operation from what reflection and `compile` see, where a node typed `^` keeps the call visible; and a separate `code` identity holding signature, body, bcode, and frame for `fn` and the operators to share — considered and dropped the same evening, since what it held is exactly a `fn`, so the slot holds one and no new identity is needed. `run` is one primitive with two paths: if `bcode` is present it jumps to it; if `bcode` is null it walks `body` directly. Interpretation is therefore not a separate function but `run`'s null-`bcode` path, which is why deoptimizing is just nulling the stale `bcode`: the next `run` falls back to walking the body, fail-closed by construction. `run` does not re-verify *whether `bcode` still matches `body`*; that freshness is the checker and deopt layer's job, not paid on every call. One reflection consequence follows: only the body-walk path materializes a reflectable live stack, while a compiled `run` is an opaque leaf (its frames live on the machine stack), so introspecting a running function means deoptimizing it first. The two are simple, predictable primitives; the policy that chooses between them is not theirs.

**A function's surface is `fn (params) -> T (body)`, and its parameter list is a type.** A function literal is `fn ( <params> ) -> <return type> ( <body> )`, an anonymous value that a name binds with `:=`, as in `main := fn () -> i32 ( return 40 + 2 )`. The parameter list *is* a record type, its fields written `name := T ?` *(the colon form superseded 2 September 2026)* or as a bare `name` that accepts any dyad, with an empty `()` the empty record; a function's `input` is therefore literally the type the parentheses define, and building a parameter list is the same work as building a record type. Two consequences *(ruled in discussion, 2 September 2026)*: the caller's positional arguments are the parameter list's **holes, in order** — a member given a value at definition is not an argument, so positional arity is the hole count — and an *expression* line written among the fields, `fn (x := i32 ?, y := i32 ?, assert x > y) -> i32 (…)`, is residual code per *Deferral is authored*: undecidable at definition, where the fields are holes, it runs per call once the frame is filled and before the body — a precondition, a fault in v0.1.0 and a call-site obligation once the refinement tier lands (*Pre- and post-conditions*). Recorded as declined, to stay declined: mandatory named arguments, `f(x=X, y=Y)` as the only call form — the call's `(` constructs its interior before the callee wakes, so `x = X` would be `=` on an undeclared name (the typo protection *`=` is reassignment* keeps), `f(x := X)` would be the no-shadowing error whenever the caller has its own `x`, and a parameter rename would break every caller; optional argument labels may come after v0.1.0 as sugar, with a spelling that is not `=` *(the first of those three grounds is superseded, 3 September 2026: a callable before a bracket reads its own bracket, see* The scope's constructor is the driver*, so the callee is awake; the decline stands on the other two)*. The return type after `->` is mandatory, `-> void` when there is none. The body is a matched-bracket `( )` scope whose value is what it evaluates to, its trailing expression; an explicit `return` is optional and only exits the function early. Brackets divide by role: `( )` delimits scopes, parameter lists, and bodies; `[ ]` is reserved for indexing; `{ }` is text interpolation inside `«…»` and `#` — the string and comment constructors' own spelling — and unassigned elsewhere *(a closed language block reaches out through `logos (…)` instead, see *Sections, the arche, and effect identities*, ruled 4 September 2026)*. A parameter is same-level with the body's top lines *(ruled 3 September 2026)*: the body resolves in the parameter scope, so `own x` on a parameter there makes it dead from that line under the static-`own` rules (*Memory and concurrency*), and a later `x := …` in the body gets a fresh frame slot.

**A scope's value is what it evaluates to, and `return` is an optional early exit from the enclosing function.** Every `( )` is a value-producing scope, and its value is whatever its body evaluates to: its trailing expression. So `a := ( sum := i32 0  ...  sum )` gives `a` the value `sum`, and `fn () -> i32 ( x + 1 )` returns `x + 1`, with no keyword in the common case. `return` is never needed to produce a value; it is written only to leave a function early. `return X` unwinds to the nearest enclosing *function* and makes `X` its result, passing out through any loop, conditional, or block in between, the ordinary early return. A `return` inside a loop inside a function therefore leaves the function, not the loop; a value that is only a block's result is written as that block's trailing expression, not a `return`. A `-> void` function, or a scope whose trailing form yields nothing, has no value to carry. Whether a given `( )`'s value is taken or discarded is still fixed structurally by the construct that introduced it (a bound block's value is used, a loop body's is thrown away): that governs where a value goes, not how it is produced.

**Operands travel on the stack, which is why `run` and `compile` take no arguments.** Each reads its own fields (body, signature, code); the call's operands are placed on the stack by the caller and read by the callee's code — the ordinary calling convention. Under interpretation this copies each operand from its dyad onto the stack per execution (the interpreter's standing cost, as in any bytecode VM); under compilation the dyad is read once at compile time and operand access is baked into the machine code — immediates inlined, locals assigned to registers or stack slots — so compiled code touches no dyad at run time and runs at native speed. Because operands live on the per-thread stack and never in the shared graph, execution is concurrency-safe by construction: the shared Logic Graph is immutable code, the mutable per-call state is each thread's own stack frame. This is also what makes recursion work — each activation gets its own frame — independently of, and prior to, any borrow checker.

**A type's metadata is shared by its values; its per-value data is not.** A type stores its `precedence`, `associativity`, `constructor`, and `destructor` once and shares them across every value of that type (its `shared` members); the bytes that differ per value are the per-instance fields. The record case — a type whose `constructor` derives the layout automatically, reading the field declarations in its scope and filling `fields` and `size_bytes`, so defining ordinary data needs no hand-written layout — and the authored case, where parsing or semantics are written by hand (operators, primitives), are **one identity, not two**: the former `struct`/`type` pair was "nearly identical by design, differing only in that a struct auto-derives what a type leaves to its author," and the merge *(ruled July 2026)* makes the derived layout a default of `type` rather than a second identity. Field *names* are not stored on the record: they enter the shared name index (the trie) like every other declaration and resolve by open-scope filtering (see *Name resolution is scope-filtered*) — a per-record `names` hashtable was considered and rejected, because resolution is one mechanism and a second per-type name store would shadow it. The `shared` keyword itself is a placeholder, not surface syntax to keep: placement is *derived* from mutability (see *Two muts, and the storage partition* — a never-`mut` member is identical across instances and stored once with the type by decision, not annotation), so when `mut` and `pub` land, `shared` disappears and reflection reports a member as shared by reading that it is immutable. *(Settled in discussion, July 2026.)* The seed stores this head in full as each identity's record, and **the constructors drive the tape**: the schedule byte that stood in until they did is retired *(stood down, July 2026 — the seed's driver is the minimal deferred-reduction loop, and each identity's `constructor` does its own consumption)*. The driver classifies a token from the record it already reads — the `precedence` field, combined with constructor presence *(the NaN / finite / +infinity three-way classification the seed used for this is superseded, 30 August 2026: every identity has a precedence, and a precedence at or above `(`'s means construction at discovery; see* The scope's constructor is the driver*)*. A *declarative consumption signature*, where a type chooses to carry one, remains the optional fast path *Source becomes runnable* licenses — never a ceiling, and no longer a stored byte. The `constructor` is a `native` callable leaf (invoked, never read into, per the reflection boundary) under one entry signature that self-hosting replaces with Logos source; and the `destructor` is the undefined null on every core identity except the owning heap pointer, the first the seed fills (July 2026) — `drop x` runs `x`'s destructor, constructor-inserted `defer` teardown, no implicit scope-end destruction (see *Memory and concurrency*).

**Parsing dispatches through the type, and the substrate vocabulary goes plain.** *(Ruled in discussion, August 2026.)* To *parse* an appearance, consult its type — the mirror of "to read a node, consult its type": an identity's `constructor` runs for appearances of its **instances**, building an instance of the appeared identity, so the code that elaborates `array i32 0` lives on array's *type* and constructs the array instance — the C++ intuition restored one honest meta-level up. (The name *poiesis* — bringing-forth from concealment into presence — was considered for this slot and declined: plain words win; `constructor` and `destructor` stay.) There is **no climbing**: a type without a constructor leaves its instances inert on the frontier, data for neighboring constructors to consume — the delimiter behavior generalized, and fail-closed. Shared behavior lives on shared types (operator, keyword, data type — the record's kind byte lifts into real intermediate types); unique syntax (an `import`, a `#`) lives on a **singleton type** of its one identity, the Smalltalk-metaclass shape, never a per-identity override slot. `precedence` and `associativity` remain declarative per-identity record data the type's constructor consults — moving binding order into constructor code alone was considered and declined, since reflection must read parse behavior as data; whether the global number later generalizes to a partial order of binding groups was recorded open and is now closed — one axis, a mixing check layerable on top *(ruled 30 August 2026; see* Elaboration*)*. Realizing the dispatch move is #48's mandate. And the substrate vocabulary goes plain *(ruled the same discussion)*: the cell is the **dyad**, its fields **`.type`** and **`.value`** — the view read is `(dyad a).type` — with *synolon* and *hyle* retired everywhere; **`logos` survived in exactly three places** — the ground identity's proper name, the definition keyword, and the language's own name — *(superseded 4 September 2026: the first two are `type`'s, see* Substrate vocabulary*; `logos` names the language alone)*.

**The constructor is a field, and shared-versus-per-instance is the whole switch.** *(Ruled in discussion, August 2026; supersedes two clauses of the preceding ruling — the dispatch-through-the-type reading and the singleton-type shape — while keeping its ground: fail-closed inertness, no climbing, parse behavior readable as data.)* `constructor` is an ordinary field a type declares for its instances, and where it is declared decides everything. Declared **per-instance**, every instance supplies its own: `type` declares it so, which is what lets each type and keyword define its own parse behavior inside its own definition — `array := type ( constructor = fn (tape) (…), … )`, an `if` or `import` a one-liner — and deletes the metaclass tower entire: no `array_type`, no singleton type per keyword. Declared **shared**, one behavior serves every instance, a data type's values parsing alike. **Absent or empty**, instances are inert on the frontier, exactly the fail-closed inertness above. Dispatch is one lookup with no climbing: an appearance of X runs X's `constructor` field — the field that builds instances of X — and whether the name resolves to X's own slot or to the type's shared one is ordinary field semantics; the dispatcher consults nothing else. Being a type is thereby an *act*, never a property granted in advance: the constructor decides, by stamping the dyad it builds (`tape[0].type = array`) and filling the value behind it. Definition bodies separate the two directions structurally *(ruled the same discussion; placement amended 30 August 2026)*: bare body lines belong to the identity **itself** — they fill its own slots (its constructor, its precedence) and may declare new members that live on it, a namespace's — and everything that lives on its **instances**, per-instance fields (`x := i32 ?`, a place per instance) and members stored once but read on instances (`y := 3` there, read `inst.y`), lives in an **`instance (…)`** scope inside the body; where a declaration is written is where it lives *(the placement rule stands; the word `instance` itself is recorded as disliked and open, 2 September 2026 — `shared` is already retired, so a member of that scope whose value is defined and never `mut` is stored once, and one left `?` at definition or declared `mut` is a place per instance — the Two-muts rule)*. An *expression* line in an `instance (…)` scope is instance-construction code *(ruled 2 September 2026)*: undecidable at definition, where the per-instance places are holes, it runs per instance once the fields are filled — a construction invariant, the frame's precondition of *A function's surface* generalized. **A slot `type` declared is filled with `=`; `:=` declares a member of your own** *(ruled 4 September 2026)*: `precedence`, `associativity`, `constructor`, and `destructor` are places `type` declares for every type it builds, so inside `^ := type (…)` the body writes `precedence = *.precedence + 1`, `associativity = right`, `constructor = fn (tape) -> void (…)` — associativity's values being the two identities `left` and `right` *(ruled the same day; `left_to_right`/`right_to_left` were declined as length paid in every operator definition for a distinction every operator table in the world already makes with one word, and a bool because `right_associative = true` says nothing to a reader of a definition)*, and `type`'s own spec showing both directions in one body, the four slots declared in its `instance (…)` and its own values filled bare — the two operators keep their one meaning each, `=` writing what exists and `:=` introducing what does not — and a `:=` on one of those four names is the ordinary no-shadowing error, which is also what lookup demands, since `^.precedence` probes the instance scope before `^`'s own bare members and a redeclared member would be found second or never. The `:=` spellings of these slots in earlier sketches are respelled. A type body is an ordinary scope for its bare lines: `g := type (y := 3, z := y + 3)` sees `y` in `z`'s line, the declarations obey the no-shadowing rule like any block's (`y := 1, g := type (y := 3)` is the error), and when the body closes they survive as members reached `g.y`. Fields are dot-only outside their scope — never a bare name in surrounding code, so `x := 1, p := type (instance (x := i32 ?))` is legal, and a field's declaration is checked only against its siblings (the seed's check against the outer stack is a bug). `self.` and `child.` prefixes were considered and declined, structure carrying what a mark would have. And since a per-instance constructor is immutable yet differs per instance, shared-versus-per-instance is *authored* structure, no longer derivable from mutability — amending that derivation note in *A type's metadata is shared by its values*. Triggering keeps exactly two discriminators *(ruled the same days)*: **precedence and associativity are the only pattern-matching on whether a constructor runs** — richer multi-node triggers were considered and declined — and a constructor that runs and finds nothing to consume declines, the frontier untouched, while what outranks it has already taken its operands: `f(a)`'s parentheses consume a bare `a` before `a`'s constructor wakes, and before a loose `=` it simply stands aside. The collection surface divides labor the same way *(same discussions)*: `[…]` constructs **itself** — the interior expression parsed once, generically — into a passive node carrying the index, and the collection's instance constructor consumes that constructed node, emitting the bounds check as residual code where index or size are not static (see the deferral ruling below).

**Text is the quote: `lex «…»` hands back the tape, unconstructed.** *(Ruled in discussion, August 2026.)* Obtaining an identity *without* running its constructor — the plain `if`, the plain `:=`, a bare `)` — needs no quoting syntax, because the substrate already has an unconstructed form of anything: text. The one spelling is `lex «…»`: the lexer itself, entered as an ordinary identity, applied to a string. The string's own bounds settle what no quote sign could: `lex «(»` and `lex «(a, b)»` are both well-formed and mean exactly what they say, a lone bracket or a whole group, where a one-token prefix sign is ambiguous between the two (`'(` beside `'(a, b)`) and a bracket-shaped quote can never name a bracket at all (`())` has no reading). Recorded as rejected, to stay rejected: a prefix quote sign (`'`, which is the postfix prime; `\`, which the sketch briefly tried as `\(`, `\)`, `\:`, `\:\=` — those spellings are superseded) and a quote keyword (`bare`, `quote`) — each a second mechanism for what text plus the lexer already provide, and each carrying the arity problem. The sketch's founding pattern is already this ruling: `assign(declare(&mut logos, «:=»), ?, ?)` declares `:=` by its text *(the example respelled 2 September 2026, `:` having left the declaration surface)*. What follows (stated the same session, as consequence rather than ruling): `lex` returns a tape fragment — an `array @dyad` *(ruled 2 September 2026)*: the cells the lexer would have put on the frontier, each a pointer to the identity the trie resolved at the lex site (positions live in the derived source map, not in the cell), unconstructed, no constructor woken — so a single token is a one-element fragment and a group is what a macro splices, `tape.insert(i, lex «(a, b)»)`; text that names nothing lexes to a fresh dyad with both slots `undefined`, its spelling kept tape-side (*The scope's constructor is the driver*, ruled 2 September 2026) — not an error but the way a constructor spells a name that does not exist yet, constructing it later being the ordinary unknown-name error. Two things the ruling leaves untouched, because they never needed a quote: reading an identity's fields (`if.constructor`, `i32.precedence` — the tight `.` runs over the token before its constructor wakes), and passing an operation as a value, which wants the callable identity `add_i32`, not the `+` constructor. `lex` is therefore the macro layer's tool and nothing more. There is no comptime/runtime distinction for `lex` *(ruled 30 August 2026)*: it turns any string into unconstructed identities whenever it runs, and the fragment is graph owned like any other value of the scope that made it. The seed does not yet carry `lex`.

**The scope's constructor is the driver, and the tape only lexes and remembers.** *(Ruled in discussion, August 2026.)* The "driver" the paragraphs above speak of is neither privileged machinery nor the tape: it is the constructor of the enclosing **scope** identity — `(` building its `scope` instance, and its kin — invoked by *its* enclosing scope when its opener appears, recursing by nesting, with the root scope run by `import` over a file and by the command line over its one line. The tape runs nothing. It is a data structure with exactly four affordances — `tape[k]` (a read lexes lazily on demand), `is_constructed` per cell, `insert`, `remove` — *(precision ruled 2 September 2026: a cell is a pointer to the dyad of the identity the trie resolved — `lex «array»` yields an `array @dyad` of one element, the pointer to `array`'s own dyad — never a `token` wrapper; `token` is not an identity, and the sketch's `token` type is superseded. `is_constructed` is the tape's own record, a linked list parallel to the cell list, never a field of the dyad, so the two-field read surface holds. Stated as consequence: because an unconstructed cell points at the identity itself, a constructor never writes through it — `tape[0].type = array` in the sketches reads as replacing the cell's pointer with the dyad the constructor built, the "replacing its own token with the dyad it built" of *Source becomes runnable* — since writing through would reclassify the identity for the whole program, which the construction-phase gate denies later and nothing denies in ungated v0.1.0. A spelling the trie does not know lexes to a **fresh dyad with both slots `undefined`**, its pointer in the cell and the spelling kept tape-side like the flag *(ruled 2 September 2026)*: `:=` fills that dyad and enters the spelling into the trie at declaration — `key := ?` of *Declarations are immutable by default* binds exactly such a dyad — and one nobody declares is the leftover-cell error at the segment boundary. Open until `parsing_tape`'s `[…]` consumption is written: the spelling of the flag read — `tape[0].is_constructed` is a `.` on a dyad with no such field, so `tape.is_constructed[k]` or a tape-defined cell view.)* It is handed to a constructor as a **cheap view with a movable center**: `tape[0]` is the constructor's own cell, negative offsets its left context, positive its right, so passing a tape re-centers a window over the same cells rather than copying them. The tape is a doubly linked list *(direction, stated the same discussion; the sketch's `doublylinkedlist dyad`)*: the center is a node, so re-centering is a pointer move and `insert`/`remove` at the center are constant-time under the many splices constructors make, while `tape[k]` walks k links — an index meant for the small offsets a constructor actually reads. Ordering is therefore *authored per scope kind*: `(` constructs its interior by precedence and associativity; `[` does the same into the passive index node (and may yet converge further on `(`, recorded as direction); `«…»` is the near-degenerate scope that lexes only its own two pairs — `«`/`»` and `{`/`}`, counted by depth so strings nest without escapes, plus the backslash escapes of *Text literals are plain values* — and `#` is that scope to end of line — brackets, strings, and comments one family, differing only in how far they lex and how much they construct — and a hosted clause (*Hosted text does not owe a single reading*) orders its words its own way. **`{ }` is text interpolation** *(ruled the same discussion)*: inside `«…»` or a `#` comment, `{` opens an ordinary full scope whose value is turned into text and spliced where it stood — `«total {n}»` — so a string is a scope that constructs exactly its braces, and `{ }` is unassigned outside text *(its brief extension to closed language blocks on 4 September 2026 was rolled back the same day — a language block's door is `logos (…)`, see *Sections, the arche, and effect identities*)*. Stated the same session as consequence, not ruling: the conversion is the text type applied to the value (`string(n)`, since a type applied to a value *is* the conversion, per *Numeric literals*), and an interpolation inside a `#` comment is not comptime-gated *(ruled 30 August 2026)*: the comment's text is a value that resolves when its inputs exist, and documentation tooling reads what is resolved. **Ordering is the eager-segment model** *(ruled in discussion, 30 August 2026, superseding the incremental shift/reduce-with-holding form first recorded here)*. Every identity nameable in text has a precedence — there is no NaN and no ±infinity class — and `(`'s constructor works in two steps. First it **lexes** its interior one token at a time; a token whose identity's precedence is at or above `(`'s own is **constructed at discovery**, before the next token is lexed — that is where the raw-text consumers live, `#`, `«`, `import`, a hosted-clause opener, and `(` itself, so an inner bracket recurses and lands as one constructed scope cell with its closer consumed by its opener — while every other token is placed on the tape unconstructed; that is what keeps `# a ( in prose` and `import ./path` from being lexed as code, with no raw-consumer marker, only a position on the one axis. Second, at a **segment boundary** — the separator `,`, which sits above `(` and acts at discovery, or the closing bracket — it **constructs** the cells lexed since the previous boundary, highest precedence first, associativity breaking ties, each constructor taking what its syntax needs from the fully lexed segment, left or right, any arity, with no lookahead (a postfix that consumes two cells to its left is as expressible as an infix), and at the top level runs them. Two dependent expressions in one scope therefore need the `,` between them — `x := 5, y := x + 1` — since in one segment `x + 1` would be constructed before `x := 5` and `x` would be an unknown name; the comma is the step boundary *Expressions are self-delimiting* already names. A constructor that takes scope cells as operands (`if`, `fn`, `for`) sits above application on the axis, so `fn () -> i32 ( body )` is taken by `fn` before `i32`'s juxtaposition could read a conversion, and conditions stay scope cells, `if (c) (body)`. That sentence is sharpened *(ruled 3 September 2026)*: an identity whose bracket changes **what names mean inside it, or when its body runs**, sits at or above `(` and **reads its own bracket** — constructed at discovery, before the bracket is lexed, it drives the bracket's parse with its own scope open — because a bracket parsed first would already have resolved its names against the surroundings. `fn` is the forced case: a body resolves in the parameter scope (*A function's surface*), which does not exist until `fn` has run; `for` and `while` likewise, for the loop variable and for the runs-again rule of *Memory and concurrency*; `defer` for the runs-later rule; `type` for its definition body; a language and an instance for the block that continues their scope (below). `if` keeps the plain order, its bodies being inline, once, and naming nothing new. The discovery-time set above (`#`, `«`, `import`, a hosted-clause opener, `(`) therefore gains these, and the seed's shape — `fn`, `for`, `while` parsing their own bodies with the barrier pushed first — is the ruled one. **`X (…)` is one spelling, and X's constructor decides what the bracket is** *(ruled the same day)*: a type's constructor fills its holes from values, positional in order, and takes declaration lines as new shared members (per-instance fields lock at the first instantiation, *Two muts*); a language's constructor **continues its one scope** — every `my_language (…)` block appends to the same body, the REPL's session model, so a name declared in one block is live in every later one until `own` or `drop` ends it, under *Name resolution is scope-filtered* — and an instance's constructor does the same for the instance, `a (x + y)` reading a's fields bare (so the derived record case supplies that constructor to its instances, stated as consequence); `type`'s defines. No rule decides among the three: each identity authors its own, per *The constructor is a field*. A constructor's outcome is read off its cell — constructed, or declined (the frontier untouched, the identity standing as its own value — `i32` before a `,`) — while an error (an operand missing, an unfinished construct) returns as its `!` value for the driver to handle, faults reserved for broken invariants (*Error handling*, amended 31 August 2026) — in v0.1.0 every constructor error is a fault and the `!` return is staged (*Error handling*, 2 September 2026). There is no holding and no re-invocation. When a segment is constructed, a leftover **unconstructed** cell is the checked error, and the constructed cells in order are the scope's expressions, the array the scope dyad's value references. Superseded with this ruling: the one-token lookahead of *Elaboration*, the threefold applied/holding/declined answer, the NaN/finite/+infinity classification of *A type's metadata*, and the zero-or-one-cell wording. The seed's Rust `Parser` stands in today (per-expression tapes, recursive re-entry into `parse_expression`, a `Delimiter` class ending sub-expressions); it makes shift-and-reduce decisions with one token of lookahead, and converging it means moving the loop into `(`'s constructor — constructing at discovery above `(`, by precedence at segment boundaries below it — and delimiters as inert cells the scope reads.

**The dyad's read surface: two fields, and the type answers the rest.** *(Ruled in discussion, August 2026.)* A dyad exposes exactly its two stored fields, `s.type` and `s.value`, and nothing more — the value-decoding reads are not view members at all *(corrected in discussion, August 2026, after the seed briefly put them on the view)*: they are ordinary `.` on the value itself, through its **own** type, because an operator node's slots are the fields *its* type defines — `(x + x).operands[0]` reads the first operand with no view involved, exactly as `p.x` reads a record field, and an array's elements or a string's characters likewise belong to the array and string types' own field surfaces. The view earns its place only for the two reads no value's own type can offer, the cell fields themselves. **Element access is `[…]`; application stays `(…)`.** *(Ruled in discussion, August 2026.)* An object storing multiple elements — whatever its storage and indexing scheme — is a **collection**, and reading a stored element is one surface across all of them, `c[k]`: an array indexes by position, a map by key, a set by membership, each collection kind picking only its index domain. `(…)` remains function application alone — three surfaces, three jobs: `.` fetches a field, `[…]` fetches an element, `(…)` computes. (The model underneath, for the proof layer: a collection is a function from its index domain to its elements — shapes and positions — which is also what makes every strictly positive inductive type one.) So a node's operands are the collection its own type defines, read `(x + x).operands[0]`, and a type's role names are `.roles[i]`. There is no `.kind`: the type *is* the kind, and classification is comparing `s.type` against known identities — a second classification axis was considered and declined as redundant with the cell's self-description. Everything else lives where this section already puts shared metadata, on the type and reached through it: `s.type.arity` and `.roles[i]` (an operator's slot count and slot names), `.precedence`, `.associativity`, `.constructor`, `.destructor`, and the layout reads `.fields`, `.size_bytes`, `.scope`. A read that does not fit the node's type — `.text` of a number, an operand index past the arity — is a checked error; answering `?` instead waits for the `?` identity. The surface is read-only once a cell is constructed — writing goes through constructors and the tape ops, never setters — and writability through the view is a gate on construction phase *(ruled in discussion, 31 August 2026)*: a constructor may write `tape[0].type` and `tape[0].value` while its own cell is unconstructed, and the flip to constructed seals both against the view. In v0.1.0 the view is ungated, every field readable and writable *(staged, 2 September 2026)*, until gates land. How other reads are gated is deferred to the gate section, recorded as deferred. The fields are the dyad's own, not a universal metaproperty *(ruled in discussion, August 2026, resolving the collision with the earlier metaproperty reading)*: `s.type` and `s.value` exist only where `s` *is* a dyad, and reflecting on any other value is the explicit **dyad view** — `(dyad a).type` — so the one spelling always reads the cell's field and no value carries two competing `.type` answers; `(a as dyad)` was considered and declined as the less consistent spelling. Recorded as direction with the ruling: gates over the view — a value a gate makes unviewable as dyad, a `.type` readable but never writable, a `.value` sealed in both directions — are the fine grain over the coarse section default (see *Sections, the arche, and effect identities*). The ruling's ground (stated August 2026): `.` does exactly one job — reading fields the type defines, and every such field is about the *value*; a value's type is never one of its own fields, so the retired universal `.type` metaproperty was `.` doing a second job, and the view repairs it by putting the type *into* a value, where `.type` becomes an ordinary field read. The seed realizes the surface (August 2026, #52 in part): `(dyad a)` builds the view exposing `.type` and `.value` alone; `.operands[i]` is ordinary field access on any operand-kinded value; the type members (`.arity`, `.roles[i]`, `.precedence`, `.associativity`, `.constructor`, `.destructor`, `.fields`, `.size_bytes`, `.scope`) read the shared record as fields of the type value itself; every read folds at parse — comptime reflection, the regime a Logos-written constructor runs in — with a mismatched read the ruled checked error. Still open there: `.items` and `.text` (the array and string types' own field surfaces), runtime-indexed reads, and the runtime-callable method forms.

**Build and run are one self-directing pass.** Lexing, parsing, and execution interleave: a construct can `compile` and then `run` a function during the same pass, immediately, rather than deferring it. There is no separate promotion scheduler in the seed — execution is directed explicitly where it is wanted, and adaptive hot/cold promotion is a later layer over the same boundary. A `run` over a scope that compiles and executes on the spot is therefore comptime metaprogramming in full generality — the whole language available at parse time, operating on real Logic Graph rather than a macro sublanguage — and it stays reproducible because comptime runs without the I/O capability, the same boundary that separates compile-time from run-time effects.

**A type is a comptime value, resolved in the pass.** A function may return `type`; a call to it is evaluated at comptime, during the one pass, and the concrete type it produces substitutes for the call — a dependent declaration `a := metatype(0) ?` is the ordinary declaration mechanism over a computed type (chosen over runtime type-values: types are comptime). A generic *type* is spelled by juxtaposition, the constructor deciding *(ruled 30 August 2026)*: `array i32` is the type "array of i32" — a specialized identity, interned, so `array i32 == array i32` — `array i32 (1, 2, 3)` a value of it, `a := array i32 ?` a declaration; `array(i32)` (collides with conversion) and `array[i32]` (`[]` is element access) are rejected, and a generic type is a chooser like a generic fn (*Deferral is authored*), each parameter yielding its own concrete identity built once. `.type` is the dyad's own field, and reading an arbitrary value's type is the dyad view, `(dyad a).type` (see *The dyad's read surface* — ruled August 2026, superseding the universal-metaproperty reading); `==` and `!=` over type values compare by identity, sound because type identities are interned; and an `if` whose condition is comptime-known folds at parse, its untaken branch dropped unparsed — which is what lets branches for *other* comptime types coexist in one source. *(Settled in discussion, July 2026.)*

**Deferral is authored, and unfinished work is visible.** *(Ruled in discussion, August 2026.)* Progress is data-driven, never scheduled: a node missing an input stays built and advances the moment the input arrives, one rule at three levels — an unconstructed neighbor on the tape (the `is_constructed` flags), an unresolved type (the conserved op slot, which *does not lower until resolved*), an unknown runtime value (control flow arriving). What a constructor cannot decide statically it **returns as residual code** — the collection's bounds check emitted as a scope that runs when index and size exist — so every constructor is a partial evaluator, and "later" is always ordinary reflectable graph: unfinished is a visible `?`, postponed is a visible scope, and there is no hidden thunk, phase, or re-parse — the scope *is* the thunk and forcing it is running it, the laziness *Execution is function application* already makes the substrate default. Tolerance for the unresolved is **authored per constructor, never ambient**: a constructor either accepts a `?` in a slot and holds — which is what a generic function *is*: `fn`'s constructor accepting parameter types not yet known, the body parsed once with unresolved op slots that a call's concrete types fill, walkable meanwhile through `run`'s null-`bcode` path — or refuses it as a checked error, a strict signature; fail-closed wherever nobody opted in. A generic `fn` is a chooser, exactly as `+` is *(ruled 30 August 2026)*: the concrete function for each argument-type combination is a separate identity, built once from the written body with its op slots resolved and reused thereafter, and a call site with known types resolves to that concrete identity and stores it in the dyad as `+` stores `add_i32`; the written generic body is never run itself.

**The command line is Logos source, and the binary stays out of the way.** Everything after `logos` is one line of Logos code, run by the one pass: `logos import ./main.logos, main(«hello»)` imports a file and calls a function it exposes, and the `,` is the ordinary explicit separator keeping `import` from consuming further. There is no file position and no argument position — the earlier spelling `logos file.logos` is superseded, having been ambiguous against the since-retired `.logos` metaproperty (`file.logos` then read as "the logos of `file`") — so running a program is `logos import ./file.logos`, and **`import` is the one identity that loads a file**: its constructor consumes the path token (the same licensed token-consumption as `#` and the planned header reader), the imported file runs top to bottom — there is no `main` entry point: the top level *is* the program, and a trailing value prints (a stand-in until I/O lands) — and an importer, command line or Logos file alike, reaches only the imported file's `pub` names: the ordinary visibility rule, with no import-specific exception *(the target; v0.1.0 has no gates and an importer sees every top-level name, ruled 4 September 2026, see *Feasibility*)*. A program's command-line interface is therefore its `pub` names, arguments are not a separate channel or mini-language, and a run is a pure function of the command-line source plus the files it imports (comptime still runs without I/O). Bare `logos` is the REPL over the same one pass — the command line is a one-shot REPL line — and a failed line rolls its declarations back out of the name index, leaving no trace. The binary has no subcommands and no compile flags, ever: it joins its arguments into source and runs them; what compiles, links, and builds is decided *inside* Logos source (build and run are one pass), never by flags — `--help` is the only flag. *(Settled July 2026; command-line-as-source, `import`, and pub-only exposure ruled in discussion, August 2026, superseding the `logos file.logos` spelling. The seed converged in August 2026 (#58): argv-as-source with the file-path mode removed, `import` with pub-only exposure, once-per-run DAG loading, the fresh-view section boundary — the command line and REPL each running as their own section — and file-relative path resolution.)*

**Importing is dropping the text there, wrapped in its own scope.** *(Ruled in discussion, August 2026.)* The imported file runs where the `import` stands, top to bottom in the same one pass — the textual intuition is the true one — but inside its own scope, and the wrapper is the whole module system. Upward, only `pub` escapes, per the ruling above. Downward, the wrapper is a section boundary (see *Sections, the arche, and effect identities*): the imported scope's trie resolves ambient names and its own imports only, never the import site's surroundings, so a file means the same thing wherever it is imported — which is also what lets the durable store cache it as one artifact — and effect identities reach it only as references handed to its `pub` functions at call time, so an imported top level is pure computation and a dependency can do exactly what its callers pass it the means to do. Recorded as rejected, to stay rejected: bare textual splicing (`#include`), whose leaked private names, double-inclusion collisions, and import-site-dependent meaning are each what the wrapper exists to prevent. The path token ends at whitespace or `,`; a path those cannot spell is written as a quoted `«…»` string; a relative path resolves against the importing file's folder, and against the working directory only when the importer is the command line itself. A file loads **once per run** *(ruled in discussion, August 2026)*: the wrapper severs the import site, so a file's meaning cannot depend on where it is imported, and all importers therefore share the one loaded scope and its identities — two importers of the same file see the same types, never two incompatible copies. Two imports that expose the same `pub` spelling into one scope are the ordinary no-shadowing error at the second import *(ruled 30 August 2026)*; the library idiom is one `pub` namespace identity per file, `math := pub type (…)`, read `math.sin`. The import graph must be a **DAG**: a cycle is a checked error, never a resolution order. And the shape is embraced deliberately, not as a side effect: an effectful program's invocation names its authority — `logos import ./app.logos, main(fs)` — and the command line being the arche, the shell line *is* the grant, visible in history.

**Two graphs, one source of truth.** The *source graph* is file-backed, persistent, and the program's identity; a build is a pure function of it. The *runtime graph* is generated during execution, ephemeral, and owned exactly like other runtime data — arena-allocated (arenas already carry the cyclic structures the graph needs), with the same lifetimes and no garbage collector. Runtime-generated structure is reflected upon the same way source is: by structural traversal, discovered by reachability from the use sites that reference it; there is no value-level or time-travel reflection (a value to inspect is stored in a variable, as in any language; reconstructing past states is the debugger's role over DAP). Reproducibility needs no separate leveling: a build reads only the files, and compile-time evaluation runs without the I/O capability, so the artifact is a pure function of the source. Cleanup needs none either: derived and runtime structure share the lifetimes of the scopes that create them, so when a scope ends its generated graph is freed like any other data — *reclamation*, the effect-free return of memory, which is the one thing that stays implicit precisely because it runs no teardown; anything with real teardown carries constructor-inserted `defer` structure (see *Memory and concurrency*) — and when the program ends everything generated is gone. The runtime may modify the source, but only on explicit command: the change is a *promotion* — its dependencies are closed over, it must be free of runtime-only inputs (or have them reified as constants), and it is copied out of its arena, unparsed to a source diff, re-checked, and committed under gate. Source is never silently rewritten, and converting any subgraph back to source text (unparsing) is a presentation and serialization facility, not the reflection mechanism.

**Versioned scopes.** A scope may have more than one implementation: the canonical one written in the source, plus any number of derived alternatives — an optimized rewrite, a specialization for known arguments, a different backend — that are proven equivalent and chosen by cost. These alternatives are the structural form of the rewriting engine's equality classes: registered at the scope's entry, extracted by a cost function. No global level numbering or edge classification governs them, because none is needed. A running program may attach optimized variants to a function's live representation and discard them when the enclosing scope ends, exactly as it discards any other runtime data; the source file is untouched unless a variant is explicitly promoted. What gets cleaned up is bounded by lifetimes; what is reproducible is bounded by the files being canonical. (This is unrelated to the proof layer's *universe levels* — the Lean-style hierarchy that prevents self-referential paradox when proofs quantify over proofs; the shared word names different mechanisms.)

**Backends are identities, and lowering is keyed by them.** *(Settled in discussion, July 2026.)* A backend is an ordinary identity carrying its own mapping from node kinds to emission code — its rule set lives with it, so adding a backend is adding an identity and its rules, never a core edit — and multiple backends coexist by construction: a scope's compiled forms are versioned-scope alternatives ("a different backend" is already one of the listed kinds above), extracted by cost. Nothing per-identity may hard-code a single backend — one lowering slot per identity would repeat the mistake of one mutable code field on `+` — so the lowering dimension is per backend, per identity. `run` stays backend-neutral because a compiled form is an address plus a declared convention: whoever minted it, the call is the same; code from different backends interoperates through shared conventions exactly as foreign code does, with co-compilation erasure available only within one backend's region. A backend also declares the *gate* predicate over the scopes it accepts — what it rejects simply stays on other versions or stays interpreted, fail-closed. Non-CPU backends (hardware synthesis) fit the same structure with two honest stretches, deferred with it: their artifact is not an `@exec` (the callable is a CPU-side driver stub, the artifact riding the version as data), and their call semantics want asynchrony, which is the effect system's surface, not the ABI's.

**Concurrent access.** Reading shared graph structure across threads uses ordinary shared borrows (`&`): many threads may read the standard library, definitions, and any subgraph at once. Writes are either disjoint — the `parallel for` pattern the borrow checker already recognizes — or exclusive (`&mut`); concurrent mutation of the same dyad is rejected at compile time, as elsewhere. Per-node reference counts are deliberately avoided: they leak on the graph's cycles and track liveness rather than the access exclusion threads need; arena ownership governs lifetime instead. The one genuinely shared, mutable structure is the identity interner — allocating or looking up an identity from multiple threads must be synchronized — together with any equality graph that parallel rewriting builds.

## Identity recognition

How the graph answers "what is this?" — for parsing, for reflection, and for rewrite matching — with a single engine. *(Target architecture; the bootstrap ships the trivial version, detailed at the end of the section.)*

**One engine serves parsing, reflection, and rewriting.** Pointed at a node, the recognizer reads the surrounding structure and returns the identities that match there — the operator a token sequence denotes, the construct a subtree forms, the rule whose left-hand side fits. This is tree/term pattern matching — the structural analogue of regular expressions over text, extended with e-matching where the match is over equality classes rather than syntax — and structural grouping, reflective query, and rewrite-rule matching are clients of the one mechanism. (Recognizing tokens from source *text* is a separate, string-keyed layer — a trie over names — not this system; the two are different ways of reaching the same identity, by name and by structure.) Matching is boolean and exhaustive — a node either has an identity or it does not, and the default query returns *every* identity that matches; there is no fuzzy or probabilistic matching in the core. Where a single answer is required (which parse wins), a *deterministic* precedence/cost order selects it — an order, never a statistic.

**Meta-navigation walks the graph; the scope stack is the graph's own spine.** The structure navigation walks is the one elaboration builds, the Logic Graph itself, and the parse-time *scope stack* is not a separate structure but the chain of enclosing scopes from the current location up to the root, read off the graph: entering a scope is descending into a subtree, leaving it is ascending, and name resolution is the walk up that spine (accelerated by an O(1) open-scope membership set where the batch pass does not already carry the environment). The *parsing tape* is the orthogonal axis, the working frontier of a scope (its not-yet-final dyads and pending tokens), which the constructors consume and turn into graph; a matched bracket is where the two axes meet, since closing a scope reduces its whole tape frontier into one dyad on the spine. So the two axes are distinct, the live per-scope frontier on the tape and settled structure behind it on the graph spine, and the same graph walk a `constructor` uses to place and reach its operands is the walk reflection and rewriting use over built structure. That is the concrete substrate under the one recognizer above. *(Architecture reached in discussion, July 2026; the surface syntax for general meta-access is still open.)*

**Recognizers compile into one shared, stratified structure.** All recognizers merge into one graph; run over a node, it yields the set of every identity that matches there, computing shared sub-tests once rather than re-checking each recognizer separately. The structure is stratified by tractability: a fast *observable skeleton* — navigations and discrete tests on identity, type, arity, and existence — is merged, minimized, and indexed; structural repetition and nesting become cycles and a stack; and arbitrary computation is confined to *guards* at the frontier, run only on the few candidates the skeleton has already narrowed. The skeleton carries the speed, the guards the expressivity. The optimized paths are straight-line — forward dispatch and fail-fast, no backtracking; a condition that compares two nodes is a guard, not a dispatch key, and a relational or negative condition (two operands differ, say) cannot prune the skeleton at all — it rides along as a residual filter or is served by an auxiliary index, exactly as a non-sargable predicate is in a database.

**The structure is itself Logic Graph code — compiled yet extensible without recompilation.** The merged recognizer is not a trie or automaton walked by a special machine; it is ordinary Logic Graph code, run over the start node like anything else, so the same adaptive machinery interprets it cold and compiles it hot. Each identity's recognition code is first minimized and canonicalized — by the ordinary rewriting engine under a compute-cost function, since recognizers are themselves Logic Graph code — so that recognizers branch the same direction wherever they can; equivalent ones then converge onto the same shared paths, and all of them merge into the single graph. Adding an identity is a local merge that reuses those shared paths, hash-consed like any other node, not a global rebuild; the merged graph is allowed to drift from minimal and is re-minimized as a periodic recompaction rather than on every edit. The convergence is guaranteed on the decidable skeleton and best-effort above it, where program equivalence is undecidable and only identical guards merge.

**Admission is a proof obligation, and identification is itself proof.** A candidate recognizer is admitted at a recorded *level* — proven safe (terminating, deterministic, effect-free) or, during bootstrap, not-yet-refuted — and a use-site demands the level it needs, so safety is paid for where required and relaxed where bootstrapping. What is refuted, or resists checking where a use-site demands proof, is rejected; there is no level below not-yet-refuted and no escape past a use-site's demand. This is the proof layer wearing another hat: "X is identity I" is the proposition "X has I's defining properties," so a trivial pattern is a trivial proof and a rich property — totality, type-correctness, a borrow that never conflicts — is a real one; identification, type-checking, borrow-checking, and termination-checking are one activity at different strengths. The system runs that activity on ordinary code, on candidate extensions to itself, and on itself, bottoming out — as everything does — in the small hand-trusted seed it cannot prove.

**Queries specialize the structure.** Beyond the default all-match, a directed query ("is this matrix-addition?") prunes by intersecting the question with the saved recognizers — an automaton product, or in its general form a partial evaluation that bakes in the query's constants — yielding a specialized recognizer that explores only the relevant paths; computing that intersection is itself a job for the identifier. The first pass over freshly tokenized input is discovery (all-match, building structure); directed queries are interrogation over structure that already exists.

**Identification is incremental.** The durable state is the source text, the resident name index (the trie of `id_context`s), and the graph; there is no persistent token array, since the parsing tape is disposable working state rebuilt from source. Re-identification follows the reader–writer rule: each cached identity is a reader of the source span and rules it consulted, and a write invalidates exactly its readers. Most edits are local; the two that are not are handled explicitly. Redefining an *identity* ripples to its uses, found without a full scan through per-subtree *use-sets* (a summary of which identities occur below each node, carried as one more component of the bottom-up state). A structural edit (an unclosed delimiter) is handled by re-lexing forward from the edit to the point where the stream re-synchronizes. The seed and runtime self-modification take the coarse path instead: only the graph is mutated in place, and editing the source *text* simply re-parses it, which is rare because a program rewrites its own *graph* for iterative self-improvement, not its text.

**This is the target architecture, not the seed.** The bootstrap ships the trivial version — recognizers run directly and unmerged, guards interpreted — and grows toward the fully merged, minimized graph, e-matching, and specialization as measurement on real graphs warrants, never before. The shape it grows into recurs throughout the system: a fast, decidable, canonical core; escape-hatch tiers for the general case; deterministic disambiguation; and compilation maintained incrementally with periodic recompaction — the same architecture as the borrow checker, the compiler, and the rewriting engine, which is why one set of mechanisms serves them all.

## Identities, names, and metadata

How identities are stored, named, and annotated: the node store, the optional name index, and how lifetimes and permissions attach without bloating every node. *(These are design decisions not yet validated against a real corpus; the bootstrap can use the trivial version of each and tighten later.)*

**The store is keyed by address.** An identity is an interned handle that lives in some backing store — an array, an arena, or any allocator that hands out stable addresses — in which the identity's *address is its id*. Because every node is a fixed two-pointer (16-byte) cell, that address is literally an index; the store needs no separate key and no hash: the id *is* the address. A content → id hash is a *separate, optional* index, needed only where structural **sharing** is wanted — interned canonical identities (one `i32` referenced everywhere) and the e-graph. Ordinary source nodes are not deduped: each occurrence of `a + a` is its own node with its own address. Identities are *per-run*: addresses, and hence ids, are assigned at runtime and are never persisted. The durable form of any graph is source text — files are canonical, promotion serializes by unparsing — and the graph is rebuilt at load, with disposable content-keyed caches as accelerators where startup cost warrants. Anything that must survive a session (caches, compiled artifacts, certificates) keys by content or structure, never by id.

**Names are an optional index, not the management mechanism.** Every identity — named or not — is reached by its handle and by structural traversal from its uses, so the handle is what you compare, store, and refer to. A name is a second index (string → handle) for the subset that source refers to by word — operators, types, declarations, keywords. Most identities are anonymous subexpressions and carry none; naming them all would mean gensym-ing millions of meaningless names, which is bloat, not management.

**Name resolution is scope-filtered, and shadowing is disallowed.** The name index maps a spelling to a list of `id_context`s, each pairing an identity with the scope it was declared in. A use resolves by keeping the candidates whose scope is currently open (an ancestor on the *scope stack*) and taking the one that remains. Because a name may not be redeclared while another declaration of it is live (no shadowing, enforced by a single check at declaration time), exactly one candidate survives, or none: a genuine out-of-scope use, which still lexes as the name and then fails resolution with a precise error rather than an unknown-token one. Two survivors is impossible under that rule, so it doubles as a cheap internal invariant: if resolution ever finds two in the same scope stack, the index is corrupt. The ancestor walk runs over the graph's own scope spine, accelerated by an O(1) open-scope membership set during elaboration; the `id_context` list is resident for the whole run, so a spelling can be resolved later from any context by the same membership test, and entries are removed only when their declaration is deleted from the source. Two precisions *(ruled 30 August 2026)*: members of a type are dot-only outside the scope that declares them — reached by `.` probing exactly that scope, never a bare name in surrounding code, so the no-shadowing check for a field runs only against its siblings — while a type body's bare lines are live within the body and obey the rule like any block's (see *The constructor is a field*); and strictness has no exceptions — parameters, locals, loop variables, and members alike — with mitigation library-side: keep the ambient set to primordial names, ship the standard library behind namespaces. *Live* is refined *(ruled 3 September 2026)*: a declaration is live while its scope is open **and** the name has not been made dead by `own` or `drop`, so an `id_context` carries, beside its scope, a **range** in that scope's body order, from the declaring node to the **item of that body** holding the `own` or `drop` that makes it dead (the line itself for a same-level end, the whole `if` for one inside its body; while that item is still being parsed the slot holds the `own` or `drop` node itself, so a later read in the same line already fails), or to the scope's end where nothing does *(the containing-item choice ruled the same day)*. Reflection reads the graph, not the index: the declare node and the emptying node are ordinary items of the scope body, and a teardown node stores the place it empties, so where a name is declared and where it dies is a walk over the body; the index's two pointers are the derived fast path over the same facts, and an edit that deletes an emptying node resets the end to null, as deleting a declaration removes the entry. A use resolves at a point by keeping the candidates whose scope is open *and* whose range covers the point. The entry points at the identity, whose own record carries its **gates** *(ruled 5 September 2026; the range is the name's fact, the gate the identity's)*, so the one lookup answers open, live, and permitted together, reading the gate through the pointer; a partial move adds a **sub-range** under the entry — `own p.f` ends the path `p.f` at that line, created only then, and marks p dead as a whole with its sibling paths live *(5 September 2026, *Memory and concurrency*)*; both records are consulted at every elaboration — parse, graph mutation, reflection — and never by running code. The invariant becomes: two entries for one spelling never overlap on one scope stack, so two survivors still means a corrupt index; and resolving a spelling later from any context stays exact, the point deciding rather than the scope alone (a use written before its declaration falls outside every range). The dead mark is static, set by the parser as it sees the `own` or `drop` under the three rules of *Memory and concurrency*, and a dead name takes nothing: a read, a write, or a pass after it is a parse-time error, and only `:=` may follow, redeclaring the spelling into a **fresh** place (the old place's inserted teardown still runs at scope exit and finds the null it expects). This is the whole relaxation, name recycling after an explicit end: a redeclaration while the earlier one is live stays the error, the two-line shape `y := own x` then `x := …` is the legal one, and it is what gives the REPL its name reuse, `drop x` then `x := …` on later lines, the session scope's body being ordered like any other. Recorded as declined, to stay declined: the one-line rebinding `x := f(own x)`, because `:=` declares its name before it parses its value (self-reference needs it), so the right-hand `x` would be the new placeholder and the check would already have fired; and a last-use notion of dead (dead once nothing later reads the name), which needs the rest of the scope in view, which the eager one-pass parse forbids.

**Metadata has three homes, chosen by frequency and origin; the model is uniform, the storage is not.** *(Revised June 2026; supersedes the earlier wrapping design.)* A wrapper around a node would make every read of its type yield the wrapper, and a wrapper spliced into the value chain would falsify the prime invariant that the type defines how the value is read — so no facet wraps. Instead a facet lives where it is naturally read: **(1) universal and tiny** — the construction phase, the four bits every node passes through — rides in the node's own tag bits (see *Mutability and construction*), read on every access because the node is already in hand. **(2) Syntactic deviations** — what the user writes on a declaration: `pub`, per-field `mut`, capability and backend modifiers — are read off the declaration's structure at resolution time, the same lookup `.` already performs, so they are not side-data at all; and the gates among them are cached on the identity's record — this id → metadata record, beside the identity's lifetime — *(ruled 5 September 2026)*, the gate node on the declaration staying the truth and the record the derived fast path exactly as the name entry's range is to the emptying node, so lifetime and gate are read by one lookup through the name entry's pointer (*`mut` is a gate on the identity's record*). **(3) Inferred deviations** — facts analysis derives that are *not* in the source: a lifetime extended past its scope by escape, a borrow state — are reflectable nodes reached through the derived id → metadata index below. Intrinsic inferred facts (a non-default lifetime) share one per-node metadata record found by that index; relational and event facts are independently-reachable nodes by nature — a borrow references its target, a move relocates a scope-level drop node — so they need no index entry on the target. The giant common case deviates in none of the three: scope-tree defaults supply lifetime (the enclosing scope) and visibility (own scope and descendants) with nothing stored, the phase bits clear at freeze, and the node stays sixteen bytes. The asymmetry is the rule — *a deviation the user writes lives in the declaration; a deviation analysis infers lives in a fact-node* — and a facet that can be either, such as an annotated versus an inferred lifetime, enters by whichever door it came from. (Source positions are not a node facet at all: a node's position is the source span it was parsed from, held in a derived source-map that is one-to-one with source, rebuilt from source, and absent for runtime-generated nodes; fine-grained permissions are carried by the reference, per *Reference-granular permissions*.)

**Lookup rides the scoped walk; the index is only an accelerator.** During checking, lexical scoping guarantees a binding's declaration is an *ancestor* of every use, so a top-down walk carrying its environment (push bindings on scope entry, pop on exit — standard scoped-checker behavior) always has the binding's metadata in hand at a use; no index is needed for the batch pass. Cross-references that skip ancestors — to types, functions, definitions elsewhere — are exactly the `'static` / default cases with no non-trivial lifetime to look up. A derived index (id → metadata node) earns its keep only for out-of-walk access: re-checking a single node after an edit, or a tooling hover, where there is no environment built up.

**A uniform model is not uniform storage.** Every identity *has* a permission and a lifetime in the model, but almost none *store* one. The node stays lean — just its type and value (16 bytes), the handle being its address rather than a stored field; metadata hangs off only on deviation; defaults are inherited from the scope tree (permissions on scopes, lifetime from the enclosing scope, dropped at its end); and the giant common case — immutable `'static` definitions: operators, types, the standard library — shares one default of readable-by-all, with no lifetime tracking, no drop node, no borrow state. Storage is proportional to *deviations*, not to identity count, which is what makes a uniform model affordable.

**A declaration has a stable identity across edits, distinct from its content hash.** The per-run address (*The store is keyed by address*) is ephemeral, and the optional content hash changes on every edit, so neither is a stable handle on *the same declaration* as its value changes under an editor. That handle is nominal: the pair of the spelling it was declared under (optionally a regex, for pattern-recognized identities such as numeric literals) and the declaration context that distinguishes same-spelled identities. It is stable under edits to the value and changes only under rename, the opposite stability from the content hash and complementary to it: a cache keys by content and should miss when content changes, whereas a proof in progress, a cache of derived facts, or a collaborator's cursor must follow the same declaration across content changes and therefore keys by the nominal identity. It is device-agnostic, since two systems sharing a root context resolve it identically, which is what lets a cross-device reference and a re-parse both re-associate persistent metadata against the right node. Like the name index and the id → metadata index, it is a *derived accelerator*, not a field on the node, so it stays off the hot path: interpretation dereferences the address directly, and the nominal identity is consulted only for serialization, cross-device exchange, and re-parse correspondence. It covers only *named* declarations; anonymous subexpressions (*Names are an optional index*) are re-associated structurally or by content. For a CRDT over the graph itself (*The IDE as platform, and the reflective web*), the nominal pair is only the human-stable half of a node id: a globally unique, origin-attributed component (a replica id and a logical counter) is added to it, to distinguish independently-created same-spelled declarations and to give anonymous nodes an id at all. *(Design direction reached in discussion, July 2026.)*

## Standard library and ecosystem strategy

The standard library is built **before** release, avoiding the fragmentation that plagues languages shipping thin stdlibs. By the time Logos is available, the standard ways to do common things are decided, documented, idiomatic, and tested by real programs.

*Release* here means v1.0.0, the stability promise. Preview milestones (v0.x, v0.1.0 first) ship with almost no standard library, explicitly labeled not-to-build-on; the completeness commitment gates v1.0.0, where fragmentation risk actually begins. *(Ruled in discussion, 31 August 2026.)*

It includes: collections and the iterator protocol `for` desugars onto; Unicode-aware strings and parsing; numerics including arbitrary precision and the cost functions for stability-aware rewriting; symbolic math (expressions, algebraic rule sets, differentiation, integration, polynomial and linear algebra, domain support, verified rules where possible); allocators and smart pointers; concurrency and async primitives; I/O, networking, and filesystem (files and folders as Logic Graph values); verification utilities (SMT integration, refinement predicates, inductive types, common tactics); the compiler-extension framework; and the documentation generator.

The cultural commitment matches the technical one: **single canonical solutions, opinions formed, batteries included, idioms documented.** Competing libraries exist, but the standard library defines what idiomatic Logos looks like, and the language's design is opinionated enough to back it.

**Completeness, not cleanliness, is the anti-fragmentation mechanism.** *(Recorded in discussion, 31 August 2026.)* A minimal core does not protect a surface from dialect sprawl — it causes it: every gap a clean core leaves is filled downstream, and filled differently (Scheme, the cleanest core ever shipped, fragmented worst; Common Lisp and Python, complete and canonical, held together). Cleanliness buys something narrower and real — a coherent base generates no wart-patching extensions — but the load-bearing protection is the batteries-included commitment above: a base so complete there is nothing missing to fill. The trap to keep in view is the beautiful minimal core whose gaps invite a thousand well-intentioned fillings.

## Tooling philosophy

- **LSP-first.** A Logos-written LSP server delivers highlighting, errors, autocomplete, go-to-definition, hover, and refactoring to any LSP editor, so users keep the editors they already have. Because so much information is already in the Logic Graph, the server is richer than equivalents in other languages.
- **Standard-protocol debugging and profiling.** DAP, standard samplers, flamegraphs — users keep the tools they know.
- **A Logos-native structural editor and IDE as long-term work.** Operating directly on Logic Graphs: semantic rather than textual editing, principled rather than heuristic refactoring, the editor itself customizable in Logos and able to ask "update all related occurrences?" with confidence. The effort is real but far smaller than equivalent IDEs elsewhere, because the meta-reflection does the heavy lifting that would otherwise require separate AST, analyzer, refactoring, and language-server stacks. Not on the critical path — LSP covers the immediate need.
- **Documentation generation as a flagship feature.** With types, signatures, doc comments, examples, capability declarations, and proofs all in the graph, generated docs are richer than conventional tools — verified examples, proof obligations, capability summaries — and the generator is customizable Logos.

## The IDE as platform, and the reflective web

*(Design direction reached in discussion, July 2026; far-horizon, dependent on the base language, the compiler, and the structural editor landing first, and not on the critical path.)*

The IDE is Logos programs over the Logic Graph (*Meta-reflection and the unified system*). Because it is, and because Logos has I/O and compiles to portable backends, the same reflective structure that is the editor can grow, without a rewrite, into a shareable, networked, rendering platform: a browser reached from the tooling end rather than built as one. This section records that direction and the properties the substrate already provides for it.

**The graph is edited as text or as graph, because the graph is primary.** A use is a reference to the identity it uses, an edge in the graph, not a spelling to be re-resolved on the fly (*Representation, elaboration, and lifetimes*). So text and graph are two renderings of one structure rather than two artifacts kept in sync, and the editor projects any region either way, as glyphs or as nodes and edges, toggling per region. Per-region is what keeps the graph view legible: a whole-program node-link view is an unreadable hairball, a focused region is not, and the arrows are the identity references already in the graph rather than a dependency view recomputed and re-synchronized on every edit. This is why the projection is cheap here and would be a synchronization problem in a text language, where the edges must first be recovered by parsing and analysis.

**Received code is checked before it runs, because the substrate carries its own proofs and capabilities.** A shared unit of Logos (code, data, or interface) can carry checkable proofs of its own behavior, in the manner of proof-carrying code: that it does not touch the network, that it reads only what it is handed, that it terminates. The receiver's kernel checks the proof cheaply before running anything, and the unit runs under the capability model with no ambient authority (*Memory and concurrency*), so it can touch only what it is explicitly granted. This is the design answer to the web's structural gap, that received code is trusted by default and inspectable never. Its reach is exact: it provides verifiable code *behavior* and verifiable *provenance* (which axioms or sources a result rests on, carried as the proof's branch, *The ecumenical proof system*), not the truth of arbitrary claims, since a proof establishes only what can be specified; and it applies to content built in the system, since legacy content carries no proofs to check.

**Reaching the web is compilation to WASM, not interpretation inside it.** The backend interface already lists WASM (*The architecture*). The platform compiles Logos to it and adopts the language-neutral substrate primitives: the WebAssembly component model and WASI for module interop, WebGPU for compute and for rendering the interface directly, QUIC with HTTP/3 and WebTransport for transport, and OPFS for local persistence, while rendering its own interface rather than reimplementing the DOM and the accreted web-API surface. Shipping the *interpreter* into WASM would stack the graph-walker's cost on WASM's own, and the interpreter's hot operations (pointer-chasing the graph) are what WASM handles least well; compiling sidesteps both. The interpreter's absolute speed is not on this path in any case: it runs cold and structurally-mutable code, and hot regions compile (*Source becomes runnable by interpretation*).

**Collaboration is real-time because source is the truth and identities are stable.** Source text is canonical and the graph is rebuilt per device with its own per-run addresses (*Two graphs, one source of truth*), so two systems collaborate by exchanging *source*, not addresses, and each resolves it locally. Real-time collaboration is then a conflict-free replicated document, persisted locally in OPFS and synced over WebTransport, at either of two levels. The near-term level is a sequence CRDT over the source text with each device re-parsing, which needs no graph-level identity and reuses established libraries; the nominal identity (*A declaration has a stable identity across edits*) and incremental re-identification (*Identification is incremental*) then preserve per-node metadata across each re-parse. The harder, later level is a CRDT over the graph structure itself, for collaborative structural self-modification, which needs every node to carry the origin-attributed identity described in that same paragraph and is complicated by the graph's cycles. Promotion (*Two graphs, one source of truth*: unparse a graph edit to a source diff, re-check, commit under gate) is the bridge that keeps even graph-level edits anchored to canonical source.

**The image's failure mode is designed out.** Smalltalk proved a live, reflective system can be productive and still lose on the practical properties a team needs: diffable, mergeable, collaboratable, deployable, interoperable. The cause was the image, a live mutable binary object graph held as the source of truth, which has no stable, comparable, portable form. Logos avoids each failure at its root. Source text is canonical, so diff, merge, and collaboration ride on text and on CRDTs keyed to stable identity, rather than on comparing heaps. Sealing (*Reflectability is a droppable capability*) collapses a region to a bare native artifact, the small deployable Smalltalk could not produce. Foreign code as a declaration and compilation to standard backends (*Native interop and the Rust bridge*) keep the system from becoming an island. The one residual risk is cultural rather than architectural: an everything-in-the-graph design must not harden into an everything-must-enter-Logos ethos, which is how the ancestor became a walled garden.

## Englogos: a Logos-native human language

*(Design direction reached in discussion, July 2026; far-horizon, dependent on the proof layer and the ecumenical system, and not on the critical path. Recorded as a direction with a first surface sketch — August 2026, language_sketch.logos and *A first surface sketch exists* below; learnability, speakability, and the broader lexicon remain undesigned.)*

**Englogos is the inverse of hosting: a human language built on Logos rather than an existing one taken in.** *Hosted text does not owe a single reading* accepts natural language as it stands — irregular, ambiguous — and represents what cannot be resolved. Englogos runs the other direction: a constructed, human-usable surface whose grammar is authored as Logic Graph constructors from the start, regular by construction, its complete rule set queryable at any moment. It needs no new substrate — it is the parsing doctrine ("surface forms as irregular as natural language are in scope") applied to a surface designed to be regular.

**The design target is Humboldt's property, engineered: finite means, exception-free, dense.** Human languages already make infinite use of finite means, but their rules are implicit, unenumerable, and shot through with exceptions that persist because enforcement is only social. The substrate's discipline is the opposite — the refrain across this document is one rule, no exceptions (one evaluation rule, one reader–writer rule, one resolution rule, one dyad) — and Englogos extends that discipline to a human surface. Its information density comes from the generality of each rule, never from irregularity: one maximally general rule doing the work natural languages spread across special cases and their exceptions.

**Exceptions dissolve because the grammar is data and irregularity pays admission.** The grammar is enumerable — every token, construction, and precedence a queryable node (*Meta-reflection and the unified system*) — so there is no place for an implicit rule to hide. A form as irregular as any natural-language idiom is admissible, but only as an explicit constructor, admitted under the recognizer's proof obligations (terminating, deterministic, effect-free) and disambiguated by a deterministic order, never a statistic (*Identity recognition*). An exception is therefore not a violation of a rule; it is another first-class rule, visible to every speaker and every tool. The exception category does not exist.

**Generativity is two-level.** A natural language's finite grammar generates infinite sentences; Englogos's finite kernel additionally generates grammars. Constructors are Turing-complete, so the surface can grow — new constructions, new vocabulary as new identities — while every extension remains expressed in, and checked by, the same fixed core. Lexicon and grammar are both open the way a natural language's lexicon alone is; the kernel underneath never moves.

**Meaning is the proof layer's, exactly as for hosted text.** A declarative Englogos sentence denotes a proposition; "executing" it is the checker applied to that proposition; empirical claims enter as asserted axioms with provenance, committing to branches of the ecumenical proof system, and epistemic status — proven, refuted, plausible-to-a-degree, unknown — is assigned lazily and revisably by the coherentist layer, never by the parser. What Englogos adds over hosting is only that the sentence-to-proposition mapping is authored and regular, so a sentence's candidate set is small or singular by construction rather than recovered from irregular text.

**Density through underspecification stays legitimate.** Part of natural language's compression comes from ambiguity resolved by context. Englogos keeps the trick without the guessing: an underspecified form parses to the candidate structure it denotes — alternatives held as plain value structure, per the hosting ruling — and resolution stays lazy, at a use site, surfacing `?` where demand outruns knowledge. The recorded rejections stand unchanged here: no driver-level backtracking, and underspecification is represented as data, never searched for a winner the source does not determine.

**A first surface sketch exists: a split copula, and tense as a stack of reference points.** *(Sketched in discussion, August 2026; recorded because this section's "no vocabulary exists yet" no longer held. A sketch, not a stable design — the examples live in language_sketch.logos.)* Two decisions are fixed. The copula splits: `be` assigns or creates — directional, a stipulation or a coming-into-being — while `is` affirms or checks, and identity affirmed with `is` is symmetric where `be` never is, so the checker can tell an axiom being installed from a proposition to prove (*Meaning is the proof layer's*). Tense is navigation over a stack of reference points whose root is speech time: `la` and `il` push a point past-of or future-of the current one; `o` resets to the root permanently, `so` resets for one word; `sa` pops one point for the rest of the sentence, `se` for one word (a push-simultaneous `o` was deleted as redundant — it moved depth, never time). The permanent reset makes `o` a keyframe: a reader joining mid-stream resynchronizes at the next `o`, a corrupted marker damages at most the span up to it, and «he olaeat and she olasang» leaves the two pasts deliberately unordered, each `o` re-anchoring before its own `la` — the differential encoding's known fragilities bought back at one letter, at the writer's discretion. Markers compound sequentially, read left to right — `illa` is a past of a future, an ordered chain and never a set — and the encoding is differential: each verb marks only its offset from the previous verb's point, so "he said she had told him they would finish" is one marker per verb, `lasay latold ilfinish`, where English re-derives every clause from speech time and piles up auxiliaries. A bare verb sits at the current stack top; a quantifier over times still binds the verb under it, so bare `is` under «in all time» is bound, not deictic. The unknown time is `?`, spoken «que», and composes with the markers («the time lailis que» asks a future-of-a-past). `often` is a frequency quantifier centered on the current stack point, so the habitual needs no aspect axis. `when P` commits that P will hold at an unknown time; `if P` accepts that P may never hold; neither moves the stack. Negation scopes over everything after it and focuses the word right after it: with individual arguments position moves only the evoked alternative and never the truth matrix, with quantifier words position is scope and does change it («not often eat» is rarely, «often not eat» is frequent skipping). The unknown `?`/«que» generalizes past time: it asks whatever slot it fills — a thing, a person, a time («when que»), or, as the argument of `is`, the truth of a clause, so «she laleave ois que» is the polar question — *Density through underspecification*'s `?` put in the speaker's mouth, surfacing exactly where demand outruns knowledge. Sentence boundary is inert: «.» resets nothing, the stack persists across sentences, and the keyframe is the only resynchronization, so a document is a delta stream with explicit keyframes; `o` is accordingly a one-way door, written once the points below it are finished with, while mid-sentence the temporary ops (`so`, compounded `se`) reach now or an outer point without burning the chain. Roots never inflect — the marker carries all tense, `laleave` and never `laleft`, and a host-language irregular form is an error, not a variant. Modality splits with the same discipline as the copula: `must` is necessity and `should` expectation, distinguished by strength as «always» is to «often» — obligation always met against obligation often unmet — and a modal carries its own time apart from its event's («he must lais lying»: necessity now about lying then). The progressive is `is` over the `-ing` state — «lais crossing» affirms an in-progress state holding at a past point, and a state never entails completion, so «was crossing, never crossed» is consistent and the imperfective paradox dissolves lexically, the `die`/`dead` split made productive; recorded open with it: `-ing` is the language's first suffix and the participle's composition is undesigned. Possession is location — «ears at him» — `at`'s single contextual-restriction reading doing the deleted `hav`'s work. `almost` is the proximative: underway or imminent, and did not happen. Recorded open besides the participle: `when` as used generically («ears at him turn red when he lie») against its episodic ruling; quantifiers over times («never», «ever») have no words; and trailing `not` in live examples stands unreconciled with the rightward-scope rule. The stack is the index half of the names-versus-indices duality: named anchors over `before`/`after` remain the general mechanism for deep or long-range reference, the short forms are surface sugar over them, and the stack is a pure function of the words to the left, so parsing stays the one tape pass with no new parser state (*Source becomes runnable*: a constructor reads back on the tape for its left context). Recorded as superseded: the interim `paoil`-as-eternal portmanteau, whose set reading cannot survive sequence semantics — eternity is quantification over times, never a marker. Recorded as rejected, to stay rejected: tense morphemes carrying counterfactuality (English's fake past) — a counterfactual marks a branch of the ecumenical system, and an antecedent's falsity is cancellable implicature, epistemic status assigned by the proof layer, never the parser (*Hosted text does not owe a single reading*).

**The surface converges on English, and speakability gates admission.** *(Ruled in discussion, August 2026.)* The convergence target is maximal: Englogos reads as close to English as regularity allows, because adoption depends on familiarity. New machinery appears only where English has no exception-free device doing the work — the tense stack, the copula split, `que` — and deliberate foreignness as signage (making the surface visibly alien wherever English is irregular, so that readers distrust their imported intuitions) was considered and declined: uninflected roots stay because they are the regular device, not as a warning label. The false-friend risk an English-maximal surface invites — a form that parses, but to a reading the writer's English intuition did not intend — is accepted on the stated ground that the surface is machine-checked: the parse is data, the reading echoes back at write time, and a wrong guess surfaces immediately instead of lingering. Recorded open with the ruling: that ground covers tool-mediated writing, and speech between people carries no checker — what disciplines the spoken case is undesigned. And speakability now gates every identity at admission rather than being retrofitted: a candidate word is said aloud before it is ruled, meanings that must not be confused take phonetically distant forms, and a marker inventory is judged as a sound system, not letter by letter. The gate's first standing case is the temporary-ops trio `so`/`sa`/`se` — one vowel apart in a differential encoding where a misheard marker corrupts to the next keyframe — whose respelling stands open.

**A surface option, not an ethos.** Per the walled-garden warning (*The image's failure mode is designed out*), Englogos is one surface over the graph among several — hosted natural languages and ordinary Logos stand beside it — never a requirement for entry. And the substrate's guarantees end where human-language design begins: learnability, speakability, morphology, and vocabulary design are disciplines of their own that the graph does not answer, which is much of why this section records a direction and not a design.

## Chain programmability: constrained targets as backends

*(Design direction reached in discussion, July 2026; far-horizon, dependent on the backend interface beyond Cranelift, the rewriting engine, and the verification strata, and not on the critical path. Prompted by covenant-style programmability arriving on UTXO chains — Kaspa's Toccata upgrade and its SilverScript language — but recorded chain-neutrally.)*

**A chain VM is a gate-constrained backend, not a new subsystem.** Per *Backends are identities*, a backend carries its own lowering rules and declares the fail-closed gate predicate over the scopes it accepts. A chain's script or covenant VM is exactly such a target: tiny, deterministic, fee-priced, rejecting most of the language. What the gate demands is what the chain demands — determinism, termination, no I/O — and that is already native vocabulary: capability tracking and totality obligations (*The type strata and verification*), stated and checked rather than left as compiler discipline. Hosting an existing chain language's full semantics as a Logic Graph dialect stays what *Native interop and the Rust bridge* already calls it, a separate and heavier option; the in-grain path is a Logos surface lowered through a chain backend.

**Fee schedules are cost functions.** On-chain execution is priced per operation — gas, script pricing — and the rewriting engine already extracts the cheapest proven-equivalent form under a user-supplied cost function (*The rewriting engine*). A chain backend therefore ships its fee schedule as a cost function and gets fee minimization as the ordinary extraction step, safely aggressive because every rewrite carries its equivalence proof, in a domain where a miscompile loses funds.

**The domain's economics reward the verification strata.** Deployed contract code is immutable, adversarially attacked, and its failure is unbounded financial loss — the inversion of the usual cost-benefit that makes proofs a luxury elsewhere. The historical exploit classes — reentrancy, overflow, access control, accounting errors — are mostly statable invariants, refinement- and proof-layer territory, and the pay-as-you-go strata are the difference from today's bolted-on specialist verifiers: verification in the same language, over the same graph, from a refinement up to a dependent proof. Comptime metaprogramming supplies the flexibility the constrained target cannot: full Logos runs at build time to generate the small artifact the gate admits (*Build and run are one self-directing pass*), so expressiveness lives in authorship rather than being asked of the chain.

**The reach is exact.** The chain VM is a hard ceiling on what deployed code can do; the improvement is in authorship — correctness and cost — never in on-chain expressiveness. Proofs establish only what is specified: wrong specifications, oracle and economic attacks, and key theft stay untouched. And a ZK execution proof is a different artifact from a compile-time proof about the program, though a zkVM fits the backend interface like any other target.

## Durable state: checkpoints, caches, and the store

*(Design direction reached in discussion, August 2026; nearer-term than the surrounding direction sections but not on the v1.0.0 critical path. The store's file format and the resource re-acquisition protocol are not yet designed.)*

**A durable store, in files, managed by Logos code alone.** Things that outlive a process live in a file-backed store keyed by content, structure, or nominal identity — never by per-run address, per the standing ruling that "anything that must survive a session (caches, compiled artifacts, certificates) keys by content or structure, never by id" (*The store is keyed by address*). The cross-process identity it needs is the one already specified for the graph CRDT (*A declaration has a stable identity across edits*): the nominal pair plus an origin-attributed component, covering anonymous nodes. How a durable reference is spelled follows the one rule that the type defines how a value is read: a durable pointer type resolves a stable id where `@T` dereferences a per-run address, so which store a reference reaches into is stated by its type rather than by tag bits — direction, like the rest of this section, with the format undesigned. The seed owes this store nothing but file syscalls, which are already in the `native` floor; formats, manifests, compaction, and policy are stdlib or third-party Logos, and the manifest itself is Logic Graph values ("filesystem (files and folders as Logic Graph values)"). The store has two tenant classes with different guarantees: **re-derivable** entries (cached compilations, proof certificates, derived facts), whose deletion loses only time, and **authoritative** entries (checkpoints, later database data), which are the only record of what the outside world told the program. The database direction — hosted query surfaces as ordinary constructors, storage engines behind one interface the way allocators are, planners as the rewriting engine under I/O cost functions — is a later tenant of the same store, not a separate subsystem.

**A checkpoint is materialized task state, saved.** The scheduling model already holds that a paused task *is* its state as graph data at burst boundaries (*Scheduling, preemption, and cancellation*); a checkpoint serializes exactly that state, with every `bcode` nulled — so resume reconstructs a fresh graph (identities stay per-run: addresses translate to file offsets on the way out and are rebuilt on the way in), starts interpreted, and re-compilation is a cache lookup. Saves happen only where code says so: a library may wrap the save in a timer, but the runtime never checkpoints behind the program's back — the same law as constructor-inserted teardown and boundary placement. Plain memory serializes transitively (what a saved value points at is saved with it); a value backed by the outside world — an open file, a connection — refuses to serialize, a checked error at the save site, discoverable because such values are built by constructors that declare what they are. A task waiting on the outside world is saved *as waiting*: on resume it re-asks — re-request, re-arm, re-register with its reactor, the user-definable layer already ruled — and writing waits to tolerate re-asking is the program's responsibility, the same shape as the cancellation ruling.

**Cached machine code re-enters as foreign code.** `@exec` has exactly two licensed mints, and the cache adds no third: a cached compilation is written out as an ordinary dynamic library and loaded back through the foreign-declaration door, so the platform loader — and its code signing, where the OS enforces it — does the trust work the substrate would otherwise have to duplicate. Content keys and fingerprints guard against corruption and staleness, never against an attacker: whoever can write the cache can write the source, so file permissions are the security for both alike. Cache keys derive from the per-subtree use-sets incremental identification already carries, a node's content plus what it resolves to, so an edit that changes no dependency — a comment — invalidates nothing. What the cache persists is what *Versioned scopes* already models — a scope's proven-equivalent compiled alternatives, today discarded with their scope — so persistence gives the alternatives a durable home rather than adding a new kind of thing.

Recorded as rejected, to stay rejected: a third `@exec` mint for cache loads; runtime-automatic checkpointing in any form (timers are libraries over the explicit save); implicit persistence of I/O-backed values; and a separate argument channel or argument mini-language (the command line is Logos source — *The command line is Logos source*).

## Feasibility and effort

The accounting of relative effort and risk:

- **Bootstrap seed (Rust)** — bounded; the hard part is restraint, keeping it small enough to audit.
- **Base language (self-hosted)** — the bulk of the language work, but well-understood territory (borrow checking, inference, data structures) and strongly accelerated by LLM-assisted implementation.
- **Rewriting engine** — bounded; the algorithm is established (egg-style equality saturation) and adaptable to the Logic Graph. Cost-function infrastructure and rule authoring take longer to get right.
- **Symbolic math stdlib** — the most uncertain. Differentiation, basic integration, polynomial arithmetic, and simplification are achievable early; Mathematica-level coverage is a long mathematical-engineering effort. Logos need not reach that bar to be valuable — an 80%-case library with compile-time symbolic evaluation is more useful than another runtime CAS clone.
- **Refinement types + SMT** — established design space (Liquid Haskell, F\*, Dafny); integrating SMT discharge with the base type stratum and building tooling is real but bounded.
- **Full dependent types + proof terms** — the deepest, longest piece, building on the same foundations Lean matured over years. In v1.0.0 *(ruled 5 September 2026, superseding the earlier 'not needed for an initial release': the release is the completeness promise, and verification left out is a gap downstream fills)*; the foundation is architecturally present from the start while the implementation accretes toward it.
- **Backends** — Cranelift and LLVM are well-documented with many existing integrations to learn from; custom backends (embedded, WASM, GPU) are smaller projects given a good interface.
- **Standard library** — ongoing for the language's lifetime; the v1.0.0 subset must cover collections, numerics, I/O, concurrency, basic symbolic math, and verification utilities.
- **LSP server** — less than building from scratch elsewhere because the information is already in the graph.
- **Documentation generator** — modest; the graph carries everything, the work is rendering and cross-references.
- **Structural editor / IDE** — large, but far smaller than equivalent IDEs elsewhere; not on the critical path.
- **Debugger/profiler integration** — standard-protocol integration first; Logos-native versions later.
- **Compiler-extension framework** — partly free from meta-reflection; conventions and tooling mature alongside the standard library, which demonstrates the patterns.
- **Verified demonstration projects** — a verified kernel module, crypto library, or compiler pass; research-grade, and what establishes credibility in the verification niche.

**The preview milestone, v0.1.0** — the first public invitation leads with "the language defines itself": a new operator or keyword defined in ordinary Logos source, used in the same file, compiled with `f.compile()`. Critical path, in dependency order: eager-segment driver convergence; the tape's four affordances as Logos-reachable identities; Logos-written constructors invoked during the parse; `lex «…»`; the demo file. `lex` stays on the path although the reshaped demo never quotes text *(re-affirmed 5 September 2026)*: the first public build must already be able to splice text-built fragments, since that is the macro layer's only tool and a v0.1.0 without it would show constructors that can only shuffle cells already on the tape. Recorded open with the reshaping: the spelling by which a Logos-written constructor builds the node's operand record — the value that points at `tape[-1]` and `tape[1]` for a node typed `^` — is not yet written, and is the first thing step 3's design must settle. A thin LSP server gates v0.1.0's public release, not the demo. Verification (proofs, refinements), the borrow checker, and the rewriting engine are explicitly not v0.1.0 work. *(Ruled in discussion, 31 August 2026.)* Also staged out *(2 September 2026)*: the error-value layer (v0.1.0 has faults only and `-> void` constructors, see *Error handling*) and gates over the dyad view (fully readable and writable in v0.1.0, see *The dyad's read surface*). And **every gate** *(ruled 4 September 2026)*: v0.1.0 has no `pub` and no `mut` — everything is readable and writable, `=` writes any declared name, and an importer sees every top-level name of the file it imports — because a seed with no gates is a smaller seed, and the gate rulings (`pub`-only exposure, `mut` as type modifier, the fail-closed default) stay the target they were, landing together after v0.1.0. The seed diverges today in carrying the `pub` gate slot and its pub-only import tests; removing them is pending v0.1.0 work. The demo is pinned *(ruled 2 September 2026; reshaped 4 September 2026)*: a user-defined power operator `^`, **defined with `type`** — right-associative, its precedence spelled relative (`*.precedence + 1`), its **constructor written in Logos**, building one node typed `^` that holds its two operands read from `tape[-1]` and `tape[1]` and removing the two cells, and its **`code` slot** holding the power computation as an ordinary function (*Execution is function application*) — then `f := fn (x := i32 ?) -> i32 ( x ^ 3 + 1 )`, `f.compile()`, `f(2)`. The separate Logos-written `pow` the 2 September form called through `^` is deleted as old thinking: the operator is the operation, and `fn` would have been only the shorthand that fills the parse slots `^` fills by hand. *(The parameter was respelled the same day — the `x : i32` first written here was the superseded colon form; the demo carries the one declaration form, and the `:`-as-sugar door of *Declarations are immutable by default* stays open but unused.)* The constraint that pins it: a v0.1.0 constructor must build **existing node kinds**, since a new node kind needs a lowering rule per backend and that is post-v0.1.0 work — a node whose type carries a `code` is the existing call kind, which is what `f.compile()` lowering `x ^ 3` as an ordinary call to `^`'s code demonstrates. What step 3 must therefore expose from the seed is exactly `tape[k]` read and write, `remove`, `dyad (type, value)` construction from Logos, `fn`-typed parameters carrying a tape, `.precedence` as a comptime field read, and a type's `code` slot consulted by `run` and `compile`.

**Accelerants Logos has that earlier language projects lacked:** LLM-assisted implementation, mature compiler infrastructure (Cranelift, LLVM, egg), well-understood foundations (dependent type theory, SMT, borrow checking), and a decade of accumulated PL research. None make the project trivial; each meaningfully reduces effort versus inventing each piece.

**Decelerants:** the unification ambition is genuinely novel in the systems-language space, so some design problems surface through implementation rather than prediction. The Logic-Graph-contains-everything commitment is tested by every feature, and keeping it coherent demands sustained architectural discipline. The verification stratum is where unexpected issues are most likely.

## Closing

The vision is large, and honest about being large. Each piece has working precedents elsewhere — Lean 4's self-hosting, MLIR's layered IR, egg's equality saturation, Rust's borrow checking, Smalltalk's malleable system — and the contribution is unifying them rather than inventing from scratch. The risks are real but the architecture is sound and coherent.
